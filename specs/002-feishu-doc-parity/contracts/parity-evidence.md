# Parity evidence contract

Every completed parity row must record:

- `surface`: shell, mode, authoring, block, collaboration, lifecycle or integration.
- `behavior`: concise user-visible claim.
- `officialSource`: official Feishu URL or `out-of-scope`.
- `liveObservation`: test-document observation URL/notes when applicable.
- `implementation`: repository file(s) and provider/host boundary.
- `verification`: focused test command or browser journey.
- `status`: `verified`, `partial`, `blocked` or `out-of-scope`.
- `limitations`: account, browser, region or provider limitations.

A row is `verified` only when the official/live claim, implementation and verification agree. A row cannot be marked verified from source inspection alone.

Evidence levels are distinct: `contract` (core/provider tests), `local-browser` (the shipped UI in Chromium/Safari), and `live-parity` (the corresponding observed Feishu journey). A lower-level pass never closes a higher-level requirement. Skipped actions remain `unverified`, even if an old runner printed PASS. Missing native document behavior remains a gap; contract-only closure is limited to the FR-025 exclusions.
