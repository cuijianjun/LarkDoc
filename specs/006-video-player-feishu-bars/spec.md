## 2. 飞书视觉契约（以用户截图为准，本地源码佐证）

### 2.1 源码研究（rea + 本地飞书源码）
- 本地无播放器核心 chunk `doc_common_videojs`（webpack id 49256）源文件，无法逐像素还原控件内部 CSS。
- 已确证：飞书播放器基于 video.js；在线播放支持 5 档倍速 / 4 档清晰度；画中画网页版支持。
- 上传卡源码（298-web-upload-progress-viewer）为任务列表弹窗，与图2 的「大卡单任务进度」不同形态；图2 以用户截图直接为准。
- 因此本轮**以用户两张截图为 1:1 视觉契约**，不自造不存在的细节。

### 2.2 顶部功能栏（图1 红框，从左到右）
白色胶囊工具条，浮于画面上方，圆角、浅描边、阴影。分组：

1. `问问豆包` AI 按钮：左侧一个小图标 + 数字角标「66」+ 文字「问问豆包」（有中文名，按规则不出 tips）。
2. 分隔线。
3. 纯图标组（无文字，按规则需 tips）：
   - ↗ 展开/弹出（对角箭头）
   - ↓ 下载
   - — 减号/收起
   - 字幕（CC/文本框图标）
   - 布局/画屏（蓝色高亮=当前激活态）
4. 分隔线。
5. 纯图标组：
   - 链接/分享（带链条图标）
   - 列表/播放列表（带横线箭头图标）
   - 评论气泡

交互：悬浮出现；纯图标给中文 tips；「问问豆包」沿用统一 AI 弹窗；下载/链接/评论沿用既有能力，未接入的保持隐藏或占位不误点。

### 2.3 底部控制栏（图1 红框，从左到右）
深灰半透明渐变条，贴画面底部，白色文字/图标。

- 播放/暂停（图中为暂停 ‖）
- 时间 `00:06/01:56`（当前/总时长，`mm:ss/mm:ss`，无空格）
- 弹性留白
- `1x` 倍速（浅描边小按钮）
- `480p` 清晰度（浅描边小按钮）
- 画中画（小窗图标）
- 音量（喇叭图标）
- 全屏（四角箭头图标）

进度条：位于控制栏**顶部上沿**，一条通栏细线（浅底 + 蓝色已播），非控制条内嵌方块。

### 2.4 上传中态（图2）与「高度不够」
- 浅灰圆角大卡，高度与完成态视频块对齐、内容垂直居中；图2 中进度条与「上传中 X%」居中成组。
- 进度条状态变化：0% 灰底 / 进行中蓝 / 100% 绿（沿用既有三段配色闸门）。
- **本轮重点**：上传卡与完成态播放器**等高对齐**（高度 1:1，不再出现「高度不够」），完成前后不跳版。
- 进度条与百分比文字严格同帧（保留既有「无 width transition」闸门）。

## 3. 方案

1. **顶部功能栏**（T21）：在 `buildVideo()` 的播放器壳内新增 `.lark-doc-video-topbar`，按 2.2 顺序与分组构建；复用 `VIDEO_ICON`/`iconNode` 与统一 AI 弹窗入口；纯图标按钮挂中文 `aria-label` + tips，有中文名的「问问豆包」不出 tips。
2. **底部控制栏**（T22）：按 2.3 重排 `buildVideo()` 的 controls：进度条提到控制栏顶部上沿（`.lark-doc-video-seek` 改绝对定位通栏），时间改 `mm:ss/mm:ss`，右侧只留 1x/480p/画中画/音量/全屏；下载移到顶部功能栏（底部不再重复）。
3. **上传卡高度对齐**（T23）：核对 `is-uploading[data-upload-kind=video]` 与 `is-video-ready` 两种态的块高，令上传卡与完成态播放器等高、内容居中；不动非视频上传卡、不动 453 PDF/卡片契约。
4. **闸门**：新增/更新 DOM 契约单测（顶部功能栏按钮序列、底部控制栏顺序、进度条定位、时间格式、上传卡等高），增量测试后打包给预览链接。

## 4. 明确不做
- 不改选中文字/➕/命令菜单/六点句柄/顶部插入弹窗的既有 tips 规则（已验收）。
- 不改 AI 弹窗统一逻辑、分享可配置、评论隐藏、图片功能栏 tips（已验收）。
- 不改真实进度模型（blob URL + ArrayBuffer 字节进度，已验收 MISMATCH=0）。
- 不启用分片网络上传（无后端）。
