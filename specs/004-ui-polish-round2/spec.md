## 1. 目标与边界

## 3. 需求与验收标准

### US1 / P1：功能栏图标 tips 全覆盖

现状根因：
- `src/ui/bubbleBar.js` 的行内格式（加粗/斜体/删除线/下划线/行内代码）、高亮、复制、评论都是**纯图标按钮**，只写了 `aria-label`，**从未绑定任何提示层**。
- `src/ui/commandMenu.js` 在 `kind === 'plus'` 的「基础」分类里把 `.lark-doc-command-label` 用 `clip-path` 视觉隐藏（只留图标），但同样没有提示层；其余项有中文名称。
- `src/ui/tableTools.js`、`src/ui/blockHandle.js`、`src/ui/cellPlusTools.js` 的功能条里同样有一批纯图标按钮无提示。
- 唯一样式正确的实现是 `src/ui/toolbar.js` 里的委托式判定（`tooltipTarget`），但它把逻辑写死在工具栏内部，无法复用。

- **FR-101**：抽出一层共用绑定器，供所有「功能栏」容器复用同一套判定与同一种 tips 视觉（复用 `.lark-doc-tooltip`，不新造样式）。
- **FR-102**：加提示的判据 = **纯图标可点控件**（`button` / `[role=button]`）。
- **FR-103**：三类**不加**：① 带**可见**中文名称（`textContent` 非空且**未被视觉隐藏**）；② 有**下一级弹窗**（含 `[class*=caret]`、`aria-haspopup="menu"`、`[role=combobox]`）；③ 分隔符 / 纯装饰节点。
- **FR-104**：文案优先级 `data-tooltip-title` → `title`（摘掉后转存）→ `aria-label`；不得留空白 tips。
- **FR-105**：覆盖范围 —— 划词气泡条、➕/斜杠命令菜单、表格功能条、块手柄、单元格➕、表格边缘浮层。
- **AC-101**：悬停气泡条的加粗/斜体/删除线/下划线/行内代码/高亮/复制，均出 tips 且文案与 `aria-label` 一致。
- **AC-102**：悬停气泡条的「问问AI」「正文▾」「对齐▾」「取色▾」**不出** tips（有中文名或带 caret）。
- **AC-103**：➕ 菜单「基础」分类的图标格出 tips（文案为对应命令名）；同一菜单内带中文名称的行不出 tips。
- **AC-104**：表格功能条 / 块手柄的纯图标按钮出 tips；带中文文字或带下拉的不出。
- **AC-105**：提示只能有一个（不出现自绘 tips + 原生 tooltip 双份）。

### US2 / P1：AI 弹窗统一成「表单式」

现状根因：
- `src/ui/workspacePanels.js` 里有两套 AI UI：`aiPanel`（表单式：上下文范围 / 操作 / 要求 / 生成预览 / 结果 / 六个结果按钮）与 `imageAiChat`（对话式：hero + 消息流 + composer）。
- 003 把**表单控件 `aiActionBar` 塞进了对话式面板的 composer**（`imageAi.setActionBar`），显隐又把 `aiPanel` 写成 `on: false`，于是：对话式外壳 + 表单控件混在一张卡里，样式必然错位 —— 这就是「原来的弹窗样式全乱了」。
- `src/mount/domRenderer.js` 里 `action === 'chat'`（块菜单「问问AI」、表格「问问AI」）走 `openSelectionAI()`，落到对话式面板；工具栏/气泡/命令菜单走一次性生成，也落到同一张对话式壳。**没有任何入口展示表单式面板**。

- **FR-201**：表单式面板（标题「AI 助手」+ 状态徽标 + 说明 + 上下文范围 + 操作 +（翻译时的）目标语言 + 给 AI 的要求 + 生成预览/发送对话 + 状态 + 结果卡 + 复制/插入到光标/替换范围/重新生成/接受结果/拒绝）成为**唯一形态**，所有入口共用。
- **FR-202**：表单控件必须**直接**长在该面板里，不再注入对话式外壳。
- **FR-203**：对话式面板（`imageAiChat`）退出显隐；其独有能力（图片/选区**引用条** + 移除、`Esc` 关闭）迁到表单式面板，不得丢失。
- **FR-204**：入口一致性 —— 工具栏「AI」、气泡「问问AI」、块菜单「问问AI」、表格功能条「问问AI」、图片「问问AI」都打开同一张面板；图片入口带引用条。
- **FR-205**：面板样式对齐参考图：卡片圆角、标题行 + 右侧圆形关闭、说明文字、控件分组、结果区灰底圆角卡、底部按钮成行且**不换行错位**。
- **AC-201**：四个入口（工具栏/气泡/块菜单/表格）打开的面板，`aria-label` 与结构一致，均为同一实现。
- **AC-202**：图片「问问AI」打开同一面板且带 `[图片] ×` 引用条；移除引用不改正文；未配置 AI 时不发请求。
- **AC-203**：面板内不再出现对话式 hero（「今天有什么工作要处理？」）。
- **AC-204**：视觉对照参考图：结果卡为浅灰底圆角、按钮不出现半截被裁切、不与 toast 重叠错层。

### US3 / P1：视频上传占位按飞书形态

现状根因：`src/core/media/file-upload-tasks.js` 的覆盖层是 `inset: 0` 铺满 `figure.lark-doc-file`，而文件壳高度**写死 453px**（preview 409 + footer 42 + 2）。视频上传时，`文件名 / 进度条 / 百分比` 挤在顶部约 60px 内，下面空着约 350px 白色区域 —— 也就是「多余的地方放进度条」。

- **FR-301**：视频上传中不再铺满 453px 空壳，改为**紧凑媒体卡**：16:9、圆角、深色底，内容（文件名 / 细进度条 / 百分比）垂直居中，无大块留白。
- **FR-302**：卡片尺寸与真实播放器同宽（534px→300px 高），完成后**恢复**为完整播放器壳，不横向跳动。
- **FR-303**：进度更新路径不变 —— 只改两个属性 + 一次样式重算，**不进事务、不重建 NodeView**（沿用 003 的结论）。
- **FR-304**：文件 / PDF 上传占位维持 003 已验收的形态，**不动**。
- **AC-301**：上传中视频块高度 ≤ 320px（16:9），覆盖层内容垂直居中，块内空白高度 < 60px。
- **AC-302**：进度 0→100 期间可见地推进；完成后覆盖层消失、落成 `video` 播放器（`data-src` 存在）。
- **AC-303**：撤销一次即整批移除（沿用 003）。
