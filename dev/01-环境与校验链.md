# 1. 环境与校验链

> 所属：lark-doc 开发备忘分册　|　返回导航：[`dev/00-INDEX.md`](./00-INDEX.md)

## 1. 环境与校验链

```bash
cd apps/lark-doc
env -u NODE_OPTIONS npm run check              # 全量 = check:gate + check:artifacts
env -u NODE_OPTIONS npm run check:gate         # 门禁段（约 30s，现代 Node）
env -u NODE_OPTIONS npm run check:artifacts    # 产物段（5 份产物 + vditor + size，Node 14）
env -u NODE_OPTIONS npm run check:quick        # 秒级：architecture + contract:check + lint
```

`check:gate` 由四个**可单独调用**的小段拼成（2026-10-27 起，就是原来的 8 个门禁，只是拆开了）：

| 段 | 内容 | 真正的失效条件 |
| --- | --- | --- |
| `check:deploy` | node14 + offline + ecs-images + session-providers | 改 `scripts/`、依赖、部署/会话配置 |
| `check:code` | lark-doc-core + lark-doc-workspace + architecture + unit（全量） | 改任何 `src/` |
| `check:ui` | theme-tokens + theme-contrast | 改 CSS 变量 / 主题 / 颜色字面量 |
| `lint` | `eslint --ext .js,.vue src scripts` | 改任何 `.js` / `.vue` |

**按改动域选门禁**（日常别全跑，只跑命中那一行）：

| 你改了什么 | 跑这些 | 可跳过 |
| --- | --- | --- |
| `src/core/blocks/*.js` 等块逻辑 | `npx vitest run test/unit/<对应文件>` + `check:quick` | 构建 5 项、theme、deploy |
| CSS / 主题变量 / 颜色 | `check:ui` + `check:quick` | 构建 5 项 |
| `scripts/`、`package.json` 依赖 | `check:deploy` + `lint` | 构建 5 项、单测 |
| 导出面 / 子入口 / `web-component` | `check:code` | — |
| 发布前 | 全量 `npm run check` | — |

- `check:unit` 是**全量** `vitest run`；只改一两个块时用 `npm run test:unit -- <文件名片段>` 或 `npx vitest run test/unit/xxx.test.js`，别为了一个块烧 60 多个文件的机时。
- **改完块代码必须 `npm run contract`**（否则 `check:quick` 里的 `contract:check` 会红）—— 契约是从代码生成的，见 [`08`](./08-工具与生成物.md)。

- **`check` 拆两段，各用各的 Node**：门禁段必须现代 Node —— `vitest@5` 的 `engines.node` 是 `^22.12||^24||>=26`，Node 14 起不来；`yjs → lib0/webcrypto` 在 Node 14 下取 `crypto.webcrypto` 为 `undefined` 直接崩（`TypeError: Cannot read property 'subtle' of undefined`）。产物段（四个 `build*` + 体积门禁）仍按 `engines` 卡 Node 14。`scripts/release.sh` 第 4 步据此用 `NODE24_DIR` 跑门禁、 `NODE14_DIR` 跑产物。
- **`check:artifacts` 有产物指纹闸门**：5 份产物的构建输入（`src/**` 的路径+大小+mtime、构建配置、`dependencies`/`peerDependencies`/`engines`/`browserslist`）没变就直接复用，跳过 5 次构建（约 3 分钟）；变了才重建。只改文档、改 `scripts` 不会触发重建。详情 [`08`](./08-工具与生成物.md)。
- **开发/构建环境只需 Node `>= 14.21.3` + npm `>= 8.19.4`**（`check-node14.js` 只做最低版本门禁，Node 20 等更高版本同样合法）；接入方运行时同样 `>=14.21.3`（`engines` 已放宽，ES2022+ API 由入口 core-js polyfill 补齐）。`env -u NODE_OPTIONS` 不能省（WorkBuddy 的 NODE_OPTIONS shim 会让 webpack 报错）。
- `npm run check` 必须 **EXIT=0 且 0 error**（warning 也要清掉）。
- demo 在 `apps/vue2-webpack-node14`（Node14 `npm run dev`，端口 8080，路由 `/lark-doc` 走源码 alias、`/lark-doc-wc` 走预构建 element 产物），**通过软链加载 dist**，改源码后必须 `npm run build` 才能看到效果；只改 element 产物相关（WC 路径）还要 `npm run build:element`。
- 起 dev server 必须带 Node 14 前缀（`PATH=$HOME/.nvm/versions/node/v14.21.3/bin:$PATH`），默认 `node` 版本过高会让版本门禁直接退出；`curl` 探活要加 `--noproxy '*'`（系统代理会返回 502，误判成服务没起来）。
- 浏览器验证统一走 `npm run verify -- <目标>`，不要再手工逐个 `node scripts/verify-browser-xxx.js`（用法见 [`05`](./05-验证资产.md)）。它用 **Node22** + `playwright-core`（`NODE_PATH` 由脚本自动补），dev server 必须用后台方式启动。
- 本环境里 bash `grep` 偶发空结果，重要判断用 Read / Grep 工具交叉确认。
