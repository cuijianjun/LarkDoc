# 8. 工具与生成物（`_codex/`）

> `_codex/` 整个目录被 `.gitignore` 覆盖 —— **所有产物都不入库**，所以 `release.sh` 的 `git add -u` 不会误提交，也不会误删源文件。
> 代价：全新 clone 里没有这些产物，第一次要用得先生成。三个生成器都是「原文件唯一真源，只读不写源文件」。

## 8.1 块契约（`_codex/contract/`）

从 `src/core/blocks/*.js` 生成，**代码是真源**，所以不会和实现漂移。

```
npm run contract          # node _codex/gen-contract.mjs       重生成
npm run contract:check    # node _codex/gen-contract.mjs --check  判过期，EXIT=1
```

产物：`INDEX.md`（2.8 KB ≈ 951 token，一屏列完 42 个文件）+ 每个块一份 JSON（最大 2.7 KB）。

JSON 字段：

| 字段 | 内容 |
| --- | --- |
| `node` | ProseMirror 节点名（`Heading.extend` 这种没写 `name:` 的，从基类名推） |
| `attrs` | 属性名 + 是否有 `default` + 默认值字面量 |
| `tags` | `parseHTML` / `renderHTML` 认的 `data-*` / 属性 |
| `constants` | `LIMITS` 之类大写常量（≤220 字符的内联字面量才收） |
| `exports` | 导出符号 |
| `summary` | 源码顶部注释摘要 |
| `evidence` | 源码里的 `02 §N` 锚点 → `requirements/02#§N`（N ≤ 30 记为章节）或 `#LN`（行号） |
| `file` | 源文件名 |

**为什么要生成而不是手抄 `02`**：手抄必漂移。契约里每个字段都能在源码里指到行；`attrs` 漏了就说明块定义本身有问题。`02` 降级为「为什么这么设计」的证据库，靠 `evidence` 锚点按需回查。

**局限**：词法级扫描不是 AST。`...base` 这类动态对象展开、跨文件常量会漏。`attrs` 解析为空时先确认是不是拆到了同目录的 `<block>-attrs.js`（生成器已认这种拆法，`calendar_event` 就是这样）。

**报错信息怎么写**：生成器只输出 `✓/✗` + 前 10 个过期文件 + 修复命令，不打 diff —— 打 diff 就是往上下文倒几百行。

## 8.2 需求切片（`_codex/req/`）

`node _codex/split-req.mjs` 把 6 篇超大需求切成 148 片，源文件一字未改。

| 编号 | 源文档 | 体量 | 片数 | 最大单片 |
| --- | --- | --- | --- | --- |
| 02 | 块类型规格总表 | 468 KB | 42 | 31.8 KB |
| 03 | 工具栏与菜单 | 153 KB | 20 | 23.1 KB |
| 04 | 浮层与弹窗 | 290 KB | 19 | 32.5 KB |
| 05 | 接口文档 | 207 KB | 26 | 33.4 KB |
| 10 | 缺口与待补清单 | 169 KB | 16 | 33.3 KB |
| 17 | 全量功能模块契约 | 159 KB | 25 | 33.5 KB |

用法：`_codex/req/README.md` → `_codex/req/<编号>/INDEX.md` → `Read` 命中的那一片。每片头两行标了来源文件与源行号区间。

## 8.3 行号索引（`_codex/requirements-index.md`）

`node _codex/gen-req-index.mjs` 生成 `requirements/*.md` 的标题行号表。查「某句话在哪一篇第几行」用它，再 `Read(offset, limit)` 精确取 —— 比读整篇省 146 倍。

## 8.4 开发备忘拆册（`dev/`）

`DEVELOPMENT.md` 原来是 41 KB（≈13.8k token）的「改代码前必读」，等于每开一个会话先交一笔固定税。现在：

- `DEVELOPMENT.md`（1.7 KB）只剩入口 + 三条铁律；
- `dev/00-INDEX.md` 是「我要做什么 → 读哪一册」的对照表；
- 每册 0.25–3.4k token，**改哪个域只读那一册**。

注意：`dev/` 是被 git 跟踪的新目录，`git add -u` 不会自动收录，第一次要 `git add dev/`。

## 8.5 产物指纹闸门（`_codex/artifacts-stamp.json`）

`scripts/ensure-artifacts.mjs` 是 check:artifacts 和 prepack 共用的完整发布目录闸门。当前有 **25 个必须存在的代表产物**，覆盖默认/full/CJS/ESM、lite、Element、五项特性、适配器、collab、plugin、PM、共享 Mermaid、graph 与 manifest；发布目录实际文件远多于 25 个。

当前这些代表产物都对应 `build:all`。闸门按脚本去重，需要重建时只调用一次完整构建；输入与全部输出一致时直接复用，不靠固定耗时判断。

```bash
npm run artifacts:check                    # 只检查，不构建；需重建时 EXIT=1
npm run check:artifacts                    # 自动准备并验证产物
npm run prepack                           # 完整目录复用闸门 + 产物/体积校验
# 明确需要强制重建时：在项目 npm 环境调用 ensure-artifacts.mjs --force
```

判定条件同时满足才跳过：

| 条件 | 说明 |
| --- | --- |
| 25 个代表产物存在 | 只是齐备性入口，完整范围见脚本 ARTIFACTS |
| 整个 dist 的输出 SHA256 一致 | 按排序遍历每个文件，以相对路径和实际字节计算；同大小改写、缺文件或多文件也会失效 |
| 构建输入 SHA256 与 stamp 一致 | 包含下面这些内容，不依赖源码 mtime |

构建输入包括：

| 输入 | 判定口径 |
| --- | --- |
| src/** | 排序后的相对路径与文件内容 |
| Rollup 配置、package-lock.json、style.css、构建器、资源/图校验辅助脚本 | 文件路径与内容；确切清单见 CONFIG_FILES |
| scripts 下 build*.js / build*.mjs 以及 ensure-artifacts.mjs | 构建器与闸门自身变化也失效 |
| package.json 的 version、依赖、peer、engines、browserslist、sideEffects、exports、browser、collabDependencies | 只读取影响产物的字段；**只改版本也必须更新 manifest 等产物** |
| 所有 build / build:* npm 脚本 | 改构建命令必须重建，无关脚本或 README 不触发 |
| Node 主版本与 npm_config_user_agent | 保留固定 Node/npm 入口；裸 node 与 npm run 的用户代理口径不同 |

不要退回裸 mtime、文件大小或只检查入口文件的判定。`artifacts-stamp.json` 虽然保留代表产物 size 供记录，但复用依靠输入指纹与**完整 dist 内容 hash**。

stamp 在 `_codex/artifacts-stamp.json`，被 gitignore。全新 clone 没有记录，因此首次构建；测试可用 LARK_DOC_ARTIFACTS_STAMP 指向其它位置。重建必须保留项目 npm_execpath，脚本用当前 process.execPath 调用同一个 npm，不从不确定 PATH 另找版本。

输入变化、输出漂移、代表产物缺失或无 stamp 都会解释重建原因。构建过程中若输入再次变化，闸门拒绝写成功记录；停止修改后再运行。`--force` 还会清除目标级输入缓存，不能把它作为每次校验的默认动作。
