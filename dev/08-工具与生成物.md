# 8. 工具与生成物（`_codex/`）

> `_codex/` 整个目录被 `.gitignore` 覆盖 —— **所有产物都不入库**，所以 `release.sh` 的 `git add -u` 不会误提交，也不会误删源文件。
> 代价：全新 clone 里没有这些产物，第一次要用得先生成。三个生成器都是「原文件唯一真源，只读不写源文件」。
>
> **生成器脚本本身不在 `_codex/` 里。** 块契约生成器已经迁入 `scripts/gen-contract.mjs`
> 并入库 —— 它曾是 `_codex/` 里唯一被 npm scripts 依赖的文件，跟着目录一起被忽略后，
> 任何新 worktree / 新 clone 的 `npm run contract:check` 都会报 `Cannot find module`。
> 原则：**被 npm scripts 依赖的 = 进 `scripts/` 入库；纯产物 = 留在 `_codex/` 被忽略。**

## 8.1 块契约（`_codex/contract/`）

从 `src/core/blocks/*.js` 生成，**代码是真源**，所以不会和实现漂移。

```
npm run contract          # node scripts/gen-contract.mjs       重生成
npm run contract:check    # node scripts/gen-contract.mjs --check  判过期，EXIT=1
```

产物：`INDEX.md`（2.8 KB ≈ 951 token，一屏列完 42 个文件）+ 每个块一份 JSON（最大 2.7 KB）。

JSON 字段：

| 字段 | 内容 |
| --- | --- |
| `node` | ProseMirror 节点名（`Heading.extend` 这种没写 `name:` 的，从基类名推） |
| `attrs` | 属性名 + 是否有 `default` + 默认值字面量 |
| `tags` | `parseHTML` / `renderHTML` 认的 `data-*` / 属性 |
| `constants` | `LIMITS` 之类大写常量（≤220 字符的内联字面量才收） |
| `exports` | 导出符号 |
| `summary` | 源码顶部注释摘要 |
| `evidence` | 源码里的 `02 §N` 锚点 → `requirements/02#§N`（N ≤ 30 记为章节）或 `#LN`（行号） |
| `file` | 源文件名 |

**为什么要生成而不是手抄 `02`**：手抄必漂移。契约里每个字段都能在源码里指到行；`attrs` 漏了就说明块定义本身有问题。`02` 降级为「为什么这么设计」的证据库，靠 `evidence` 锚点按需回查。

**局限**：词法级扫描不是 AST。`...base` 这类动态对象展开、跨文件常量会漏。`attrs` 解析为空时先确认是不是拆到了同目录的 `<block>-attrs.js`（生成器已认这种拆法，`calendar_event` 就是这样）。

**报错信息怎么写**：生成器只输出 `✓/✗` + 前 10 个过期文件 + 修复命令，不打 diff —— 打 diff 就是往上下文倒几百行。

## 8.2 需求切片（`_codex/req/`）

`node _codex/split-req.mjs` 把 6 篇超大需求切成 148 片，源文件一字未改。

| 编号 | 源文档 | 体量 | 片数 | 最大单片 |
| --- | --- | --- | --- | --- |
| 02 | 块类型规格总表 | 468 KB | 42 | 31.8 KB |
| 03 | 工具栏与菜单 | 153 KB | 20 | 23.1 KB |
| 04 | 浮层与弹窗 | 290 KB | 19 | 32.5 KB |
| 05 | 接口文档 | 207 KB | 26 | 33.4 KB |
| 10 | 缺口与待补清单 | 169 KB | 16 | 33.3 KB |
| 17 | 全量功能模块契约 | 159 KB | 25 | 33.5 KB |

用法：`_codex/req/README.md` → `_codex/req/<编号>/INDEX.md` → `Read` 命中的那一片。每片头两行标了来源文件与源行号区间。

## 8.3 行号索引（`_codex/requirements-index.md`）

`node _codex/gen-req-index.mjs` 生成 `requirements/*.md` 的标题行号表。查「某句话在哪一篇第几行」用它，再 `Read(offset, limit)` 精确取 —— 比读整篇省 146 倍。

## 8.4 开发备忘拆册（`dev/`）

`DEVELOPMENT.md` 原来是 41 KB（≈13.8k token）的「改代码前必读」，等于每开一个会话先交一笔固定税。现在：

- `DEVELOPMENT.md`（1.7 KB）只剩入口 + 三条铁律；
- `dev/00-INDEX.md` 是「我要做什么 → 读哪一册」的对照表；
- 每册 0.25–3.4k token，**改哪个域只读那一册**。

注意：`dev/` 是被 git 跟踪的新目录，`git add -u` 不会自动收录，第一次要 `git add dev/`。

## 8.5 产物指纹闸门（`_codex/artifacts-stamp.json`）

`dist/` 有 5 份产物，全建一遍约 3 分钟。`check:artifacts` 和 `prepack` 都要产物，以前是「谁要谁重建」。

现在统一走 `scripts/ensure-artifacts.mjs`：**构建输入没变 + 产物齐备 → 直接跳过**。

```
node scripts/ensure-artifacts.mjs            # 智能判断（prepack / check:artifacts 用的就是这个）
node scripts/ensure-artifacts.mjs --check    # 只判定不构建，该重建则 EXIT=1
node scripts/ensure-artifacts.mjs --force    # 无条件重建
npm run artifacts:check                      # = --check
```

判定条件三个都要满足才跳过：

| 条件 | 说明 |
| --- | --- |
| 5 份产物都存在 | `common` / `umd.min` / `esm` / `collab.esm` / `element.umd.min` |
| 产物 size 与 stamp 记录一致 | 防止被人手改过或被截断 |
| 指纹与 stamp 一致 | 见下表 |

指纹吃什么（`sha1` 聚合）：

| 输入 | 为什么 |
| --- | --- |
| `src/**` 每个文件的 `相对路径 + size + mtime` | 源码改动 |
| `vue.config.js` / `babel.config.js` / `postcss.config.js` / `jsconfig.json` | 构建配置改动 |
| `package.json` 里只取 `dependencies` / `devDependencies` / `peerDependencies` / `engines` / `browserslist` / `sideEffects` | 依赖与目标环境改动 |
| `npm_config_user_agent` | 换 Node / npm 版本后产物可能不同 |

**不要改成裸 mtime 判定**：`package.json` 里改一行 `scripts` 或改文档 mtime 都会误判全部过期，闸门就白做了。当前实现改 `scripts` 仍跳过、改 `devDependencies` 才判过期，是刻意区分的。

stamp 落在 `_codex/artifacts-stamp.json`，**已被 gitignore**（`_codex/` 整目录），所以全新 clone 里没有 → 第一次必然判「无构建记录」并构建，符合预期。要换 stamp 路径用 `LARK_DOC_ARTIFACTS_STAMP` 环境变量（测试用）。

失败时只输出一行原因（`无构建记录` / `源码/依赖/构建配置有变动` / `产物缺失` / `产物 size 与记录不符`），不打印 diff。
