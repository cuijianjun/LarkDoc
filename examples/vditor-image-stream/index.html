Vditor 支持「图片接口渲染」吗？—— 两种应用层写法

后端上传只返回 attchId，取图必须请求 /api/file/:id/stream 且带 Authorization。Vditor 没有开箱即用的渲染期拉流，下面两栏分别演示「上传期换票」与「渲染期 hook」。

方案 A · 官方写法（推荐）

上传期换票：upload.format

把 attchId 换成浏览器能直接加载的代理直链，再交给 Vditor 写进 ![](url)。文档、导出、协同全是普通 URL，零 hack。工具栏的上传按钮也走这条链路，可自己选图验证。

方案 B · 应用层 hook（有边界）

渲染期拉流：preview.parse

文档里存流接口地址。<img> 裸 GET 会 401，preview.parse() 里带鉴权 fetch 拿二进制 → blob: 回填。只对预览区生效；wysiwyg / ir 编辑区不覆盖，blob URL 也不能持久化。

请求日志

    关键代码（应用层只需要这两段） 
    // A：upload.format —— 后端只给 attchId，应用层拼成可加载的直链
upload: {
  url: '/api/upload',
  headers: { Authorization: 'Bearer demo-token' },
  format(files, responseText) {
    const { data } = JSON.parse(responseText)        // { code:0, data:{ attchId } }
    const url = `${location.origin}/api/file/${data.attchId}/raw`
    // Vditor 的 genUploadedLabel 只认这套结构，返回值必须是 JSON 字符串
    return JSON.stringify({
      code: 0, msg: '',
      data: { errFiles: [], succMap: { [files[0].name]: url } }
    })
  }
}

// B：preview.parse —— 渲染后拿到 DOM，异步拉流再回填
const cache = new Map()   // src → Promise<blobUrl>，去重 + 避免重复请求
preview: {
  parse(element) {
    element.querySelectorAll('img[src$="/stream"]').forEach(async (img) => {
      const src = img.getAttribute('src')
      if (!cache.has(src)) {
        cache.set(src, fetch(src, { headers: { Authorization: 'Bearer demo-token' } })
          .then(r => r.blob())
          .then(blob => URL.createObjectURL(blob)))
      }
      img.src = await cache.get(src)   // 只改 DOM，不写回 Markdown
    })
  }
}
// 生产还要补：token 过期重试、destroy 时 URL.revokeObjectURL、懒加载并发上限
