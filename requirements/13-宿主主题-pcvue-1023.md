## 1. 宿主主题机制（源码实测）

### 1.1 三处源码

| 文件 | 行 | 内容 |
| --- | --- | --- |
| `src/assets/styles/theme.scss` | 24-219 | `$themes` map：`default` / `dark`（`newYear` 已注释） |
| `src/assets/styles/theme.scss` | 223-238 | `@mixin useTheme()` 生成 `html[data-skin="#{$key}"] & { @content }`；`@function getVar($key)` |
| `src/store/modules/themes.js` | 1-31 | `changeTheme` → `localStorage.currentTheme` + `documentElement.setAttribute('data-skin', theme)` |
| `src/layout/components/Navbar.vue` | 93-110 | 主题下拉（`default` / `newYear` / `dark`）——**整段被注释** |

### 1.2 切换链路

```
用户点下拉 → Navbar.changeTheme(value)
           → $store.dispatch('themes/changeTheme', value)
           → localStorage.setItem('currentTheme', theme)
           → document.documentElement.setAttribute('data-skin', theme)
           → CSS 里 html[data-skin="dark"] .xxx { … } 生效
```

> 初始值：`localStorage.getItem("currentTheme") || "default"`（`themes.js:1`）。

### 1.3 关键约束：编译期展开，无运行时变量

宿主**没有一个 CSS 自定义属性**（全库 `*.scss` 中 `--xxx:` 零命中）。所有主题色在构建时就被展开成 `html[data-skin="dark"] .foo { color: #fff }` 这样的具体规则。

**推论（直接决定集成方案）**：

1. lark-doc **无法**通过 `var(--宿主变量)` 继承宿主配色 —— 宿主根本没有变量。
2. 要跟随宿主，只能**读属性**（`data-skin`）或**读计算样式**（`getComputedStyle`）。
3. 宿主想微调 lark-doc 的颜色，只能写 `html[data-skin="dark"] .lark-doc { ... }` 覆盖，或走 lark-doc 的 JS API。

## 3. 三方主色冲突（必须解决）

| 来源 | 主色 | 场景 |
| --- | --- | --- |
| 飞书实测（[06 §1.2](./06-视觉规格Token.md)） | **`#1456F0`** 蓝 | 1:1 复刻目标 |
| lark-doc 现代码（`--lark-doc-green`） | **`#00b887`** 绿 | 现有实现 |
| pcvue 宿主（`$--color-primary`） | **`#06A17D`** 绿 | 嵌入环境 |

- `#00b887` 与 `#06A17D` 是两个不同的绿，**并排时能看出色差**。
- 宿主深色底是 `#1d3d39`（**墨绿系**），而 [11 §4.1](./11-主题切换.md) 推导的是 `#17181A`（**中性灰系**）。两者在宿主内并排会明显割裂。
- **结论**：lark-doc 深色值不能只按飞书/中性灰定，**在 pcvue 内嵌场景下必须提供"墨绿系"一组**。见 §4.3。

## 4. 集成契约设计

### 4.1 新增 `theme: 'host'` 模式（推荐）

lark-doc 三态之外，加第四种取值：

| 取值 | 语义 |
| --- | --- |
| `light` / `dark` / `system` | 见 [11 §3.1](./11-主题切换.md) |
| **`host`** | **跟随宿主**：MutationObserver 监听 `document.documentElement` 的 `data-skin`，按映射表取值 |

```js
new LarkDoc({
  theme: 'host',
  hostSkin: {              // 宿主皮肤名 → lark-doc 主题
    attr: 'data-skin',     // 默认 'data-skin'
    map: { default: 'light', dark: 'dark', newYear: 'light' },
    fallback: 'light',     // 未命中的皮肤名
  },
})
```

**要点**：
- 只在 `theme: 'host'` 时挂 MutationObserver，避免无谓开销。
- `data-theme-source` 相应写 `host`。
- 宿主无 `data-skin` 属性时用 `fallback`。

### 4.2 备选 / 不推荐

| 方案 | 评价 |
| --- | --- |
| 宿主在 `changeTheme` 里显式调 `larkDoc.setTheme(...)` | ✅ 可控性最好，**作为兜底推荐同时提供** |
| lark-doc CSS 里直接写 `html[data-skin="dark"] .lark-doc` | ❌ 耦合宿主私有属性名，换宿主即失效 |
| 读 `getComputedStyle` 反推主题 | ❌ 脆弱，且宿主是编译期规则，取不到"主题名" |

### 4.3 深色色板需增补「宿主对齐档」

[11 §4](./11-主题切换.md) 给的是中性灰推导档。针对 pcvue 内嵌，**追加一组（无需推翻原档，作为可选 preset）**：

| Token | 通用档（11 §4） | **宿主对齐档（pcvue dark）** |
| --- | --- | --- |
| `--ld-bg-page` | `#17181A` | **`#1d3d39`** |
| `--ld-bg-content` | `#1D1F21` | **`#1d3d39`** |
| `--ld-bg-surface` | `#26282B` | **`#425756`** |
| `--ld-bg-surface-raised` | `#2E3033` | `#4b5b5c` |
| `--ld-bg-hover-chrome` | `rgba(255,255,255,.06)` | **`#425756`** |
| `--ld-border-chrome` | `rgba(255,255,255,.12)` | **`#425756`** |
| `--ld-border-content` | 同上 | **`#4b5b5c`** |
| `--ld-text` | `#E3E5E8` | **`#ffffff`** |
| `--ld-text-secondary` | `#A6ACB3` | `#999999`（对齐 `bread-posi-font-color`） |
| `--ld-brand` | `#4C88FF` | **`#06A17D`**（宿主主色在深底上本就够亮，不提亮） |
| `--ld-shadow-chrome` | 减弱 40% | **`none`**（宿主 `header-bottom-box-shadow: none`） |

> 交付形态：一个 `theme-preset-pcvue.css`（或 JS 常量），宿主引入即可，不改 lark-doc 默认档。
