## 1. 判定标准：什么叫「闭环」

### 1.1 六段式 2.0（原 6 段不够，补 3 个横切维度）

`00-README` 定义的 6 段式覆盖的是**单功能内部**的完整性。这次审计发现它**系统性漏掉了三样东西** —— 它们不属于任何一个块，但每个块都要用：

| 维度 | 原六段式里有吗 | 为什么必须有 |
| --- | --- | --- |
| **① 空间轴**：增 / 删 / 改 / 查 | ✅ | 已有 |
| **② 可见性轴**：显示 / 隐藏 / 禁用 | ✅ | 已有 |
| **③ 视觉轴**：像素 / 颜色 / 状态视觉 | ✅ | 已有 |
| **④ 数据轴**：字段 / 接口 | ◐ 只有字段，无 API | 见 §3.3 |
| **⑤ 时间轴**：撤销 / 重做 / 历史 | ❌ **全库缺失** | 见 §3.1 |
| **⑥ 搬运轴**：复制 / 剪切 / 粘贴 / 拖拽 | ◐ 只有拖拽 | 见 §3.2 |
| **⑦ 异常轴**：空 / 加载 / 失败 / 无权限 / 超限 | ❌ **分散且不成体系** | 见 §3.4 / §5 |

> **判定口径**：一个功能算「闭环」，必须同时回答「怎么产生」「怎么消失」「怎么改」「怎么找回来」「出错怎么办」「没权限怎么办」「能不能撤销」「能不能搬走」。

### 1.2 本次审计的三条硬线

1. **有没有值**：凡写进表格的尺寸/色值，必须能追溯到一次实机采集（batchNNN），否则标【待补】。
2. **有没有唯一入口**：同一能力若有两个入口（如插链接：`Cmd+K` vs 气泡条），必须写明**哪个是可靠入口**，否则实现时会各挑一个。
3. **有没有反向路径**：每个「增」都要能对上「删」，每个「显示」都要能对上「隐藏」，每个异步请求都要能对上「失败态」。

## 3. 真正的逻辑断链（按严重度）

> 这些**不是「少采了几个像素」**，而是「规格里根本没有这条路径」。按「会不会让 P1 翻工」排序。

### 3.1 【S1】时间轴缺失：撤销 / 重做 / 历史栈

**现状**：全库只有两行

```
| 撤销 | ⌘ + Z |
| 重做 | ⌘ + Shift + Z |
```

以及三处零散提及（`addToHistory: false` 用于缩进归一化、协同模式换 `Y.UndoManager`、C3 用例「撤销只撤自己的」）。

**缺的是整个行为契约**：

| 待定项 | 为什么必须有 |
| --- | --- |
| **合并粒度** | 连续输入是否合并成一步？飞书是「按输入停顿或语义边界合并」，不是按键合并。不定 → 用户按一次 `Cmd+Z` 只回退一个字符，体验崩 |
| **不进栈的操作清单** | 已知：缩进归一化（`addToHistory:false`）。未知：折叠展开？选区变化？滚动？只读态切换？主题切换？ |
| **blockId 复原** | 撤销「删除块」后，块是拿回原 `blockId` 还是新生成？**这决定评论锚点会不会丢**（评论锚 `blockId`，见 05 §5.5） |
| **与持久化的关系** | 撤销后是否立即触发 `save`？是否写快照？飞书口径是「撤销=一次正常编辑」 |
| **协作下的 origin 隔离** | `Y.UndoManager({ trackedOrigins: [本地 origin] })` 已在 09 定了方向，但**没定义本地 origin 常量**，也没说「远端更新到达时本地栈要不要清空」 |
| **栈深度上限** | 未定。Tiptap 默认 100，飞书未测 |
| **撤销与修订模式** | 修订模式下 `accept/reject` 不可撤销（07 §12 已定），但**修订标记本身**能否被 undo？未定 |
| **UI 入口** | 只有快捷键，没有按钮。飞书顶栏有无撤销按钮？未采（受 A13 阻塞） |

#### 3.1.1 撤销契约实测（batch185 · 已闭环 4 条）

> 上表 8 个待定项里，**4 项已用 Playwright 实测收口**，剩下 4 项仍挂缺口。

| # | 待定项 | 实测结论 | 判读 |
| --- | --- | --- | --- |
| 1 | **UI 入口** | 顶栏 `.toolbar` / `.lark-doc-topbar` 里**枚举不到任何撤销/重做按钮**（`U5 → []`） | ✅ **飞书顶栏没有撤销按钮**，只有快捷键。V1 也**不做按钮**（省一块 UI） |
| 2 | **合并粒度（连续打字）** | 输入 `"ABCDEFGHIJ"` → 一次 `Cmd+Z` → 剩 **`"ABCDEF"`** | ⚠️ **与 batch167 的结论不一致**（batch167：10 字符零延迟连打 → 整行消失 = 合并成 1 步；本次：只撤末尾 4 字符 = 被切成 2 组）。**说明分组边界不稳定**，取决于输入过程的事件节奏。V1 取 `newGroupDelay: 500`（ProseMirror 默认），**不追求与飞书逐字符一致** |
| 3 | **合并粒度（有停顿）** | 输 `"K1"` → 停 1.5s → 输 `"K2"` → 一次 `Cmd+Z` → 剩 **`"K1"`** | ✅ **按停顿分步**，与主流编辑器一致。V1 用 `prosemirror-history` 默认 `newGroupDelay: 500ms` 即可（飞书阈值未精测，取 500~1500 之间） |
| 4 | **blockId 复原** | 新建块 `bid=207` → `Backspace` 与上一块合并 → `Cmd+Z` → **`bid=208`**（不是 207） | 🔴 **撤销后 blockId 重新生成**，原 id 不回来 → **评论锚点、折叠状态、收藏锚点全会断**。**V1 必须修**：撤销应恢复 `blockId`（`prosemirror-history` 本身会恢复 node attrs，只要 `blockId` 存在 attr 里就不会变；飞书是在 `transform` 后重新分配 id 导致的） |
| 4b | **重做链** | `Cmd+Shift+Z` → `bid=159` / 内容 `"/ZX9"`（回到合并前）；再撤销 → `bid=209` | 🔴 **每次重做/撤销都生成新 id**，同一条链上 id 一直在变（207→208→209） |

> 🔴 **V1 决断（三条硬要求）**：
> 1. `blockId` **必须存在 `node.attrs` 里**，撤销/重做时由 `prosemirror-history` 自动还原，**绝不在 `dispatch` 后重新分配**
> 2. 合并粒度取 **停顿分步**（`newGroupDelay ≈ 800ms`），**不照抄飞书的「4 字符一步」**
> 3. 顶栏**不做**撤销/重做按钮，只留 `Cmd+Z` / `Cmd+Shift+Z`（与飞书一致）

#### 3.1.2 剩余 5 项 · V1 契约（飞书不可测，直接拍板）

> 这 5 项**在飞书里没有可观测入口**（无撤销栈 UI、无历史面板、无只读态开关），继续实测是浪费时间。**改为 V1 自己定契约**，写死在这里，实现时照抄。

| # | 待定项 | V1 契约 | 理由 |
| --- | --- | --- | --- |
| 5 | **不进栈的操作清单** | **不进栈**：选区变化 / 光标移动 / 滚动 / 折叠展开 / 悬停高亮 / 主题切换 / 只读态切换 / 缩进归一化（`addToHistory:false` 保留）<br>**进栈**：一切 `doc` 内容变更（含表格合并、列宽、底色）、块属性变更（`indent` / `isHeader`）、块增删移<br>**特例**：列宽拖拽（`<col width>`）**合并成 1 步**（拖拽期间 `addToHistory:false`，`mouseup` 时一次性提交） | 折叠/滚动不是内容，进栈会让 `Cmd+Z` 变得「按了没反应」；列宽拖拽若每帧进栈，一次拖拽会塞几十步 |
| 6 | **与持久化的关系** | 撤销 = **一次正常编辑** → 走同一条 `on('change')` 管线 → 触发 `save`（含 `json` 落库）→ **不写额外快照**、**不特殊标记** | 与飞书「撤销=正常编辑」口径一致；若撤销跳过 save，会出现「撤销后刷新回滚」 |
| 7 | **协作 `origin` 隔离** | 本地 origin 常量：**`'local'`**（`Y.UndoManager({ trackedOrigins: ['local'], captureTimeout: 800 })`）<br>**远端更新到达时不清空本地栈**（`Y.UndoManager` 天然只追踪 `trackedOrigins`，无需清）<br>本地 `Cmd+Z` **绝不能**撤掉别人刚打的字 | `trackedOrigins` 是 Yjs 官方解法，清栈会导致「别人一动我就不能撤销」 |
| 8 | **栈深度上限** | **100**（ProseMirror / Yjs 默认值），**不做配置项** | 飞书未暴露；100 步足够覆盖真实编辑回退需求 |
| 9 | **修订模式下的撤销** | 修订标记（`insertion` / `deletion`）**本身可被 undo**（它也是 doc 变更）；但 `accept` / `reject` **不进栈**（07 §12 已定：不可撤销）<br>→ 实现：`accept/reject` 的 `dispatch` 加 `addToHistory: false` | 「改错了能退回来，但『已接受』是个不可回头的确认动作」 |

> ✅ **至此撤销轴 9 项全闭环**：4 项实测（3.1.1）+ 5 项契约（本节）。**无遗留缺口。**

> 📌 **建议落点**：`07` 新增一整节「撤销 / 重做与历史栈」，按 6 段式写。这是 S1，P1 之前必须定。

### 3.2 【S1】搬运轴缺失：复制 / 剪切 / 粘贴 / 多块多选

| 多块复制 | 无 | 跨块选区的判定边界（部分选中的块算不算整块） |
| 剪切块 | 无 | 剪切后空块是否保留 |
| 粘贴为副本 | 无 | **`blockId` 必须重新生成**（否则评论锚点、折叠状态串台）；已知 07 §10 有一条「重复 blockId 以 mapping 邻近者保留原 id」——那是**拖拽复制**的口径，与「剪贴板粘贴」是否同一套？未定 |
| 粘贴到容器内 | 无 | 复制一个分栏列，粘到高亮块里合法吗 |
| 外部 HTML 粘贴 | 无 | 从 Word/网页复制进来的富文本**清洗规则**（保留哪些 mark、哪些变成纯文本） |
| 外部 Markdown 粘贴 | ◐ | `07 §8` 有 Markdown **输入规则**表，但那是一行一行打字的规则，**不是粘贴整段 MD 的解析规则** |
| 粘贴图片 | ◐ | `02 §11` 增里列了「粘贴剪贴板图片」，但**粘贴的是 URL 还是二进制**、失败怎么办未定 |
| 剪贴板内部格式 | 无 | 是否写 `text/html` + 私有 `application/x-lark-doc`？不写私有格式就无法「从别的 tab 粘回本 tab 保真」 |

> 📌 **建议落点**：`07` 新增「块级剪贴板与多块多选」；`05` 补 `clipboard.serialize/deserialize` 契约。

### 3.3 【S1】数据轴缺一层：块操作 API

**现状**：`05` 的 API 全部是**文档级**（`DocumentSession`：load/save/connect/createVersion…）+ **Provider 级**（persistence/comments/…）。**没有任何一个「块操作」方法**。

18 个块的「增删改查」都写在 `02` 的 ② 段里，但那是**用户操作路径**（按什么键、点什么菜单），不是**程序契约**。

**后果**（这才是要命的地方）：

- P1 要把「叶子节点」改成「容器节点」（A14/A15），届时要改每一个块的插入/删除/移动逻辑
- 现在没有共享 API → 每个块各写一遍 → **P1 改 18 次**
- 也无法写统一测试（「所有块都必须能 move/duplicate」这类断言无从下手）

**建议定义的契约**（一步到位，P1 直接用）：

```ts
interface BlockAPI {
  insert(payload: BlockPayload, at: { afterBlockId?: string; parentId?: string; index?: number }): string; // → newBlockId
  update(blockId: string, patch: { attrs?: object; content?: PMNode[] }): void;
  remove(blockId: string, opts?: { keepChildren?: boolean }): void;   // keepChildren 决定子块上提还是同删
  move(blockId: string, to: { afterBlockId?: string; parentId?: string }): void;
  duplicate(blockId: string, opts?: { newBlockIds?: boolean }): string;
  transform(blockId: string, toType: string, attrs?: object): void;   // = turninto
  get(blockId: string): BlockSnapshot | null;
  children(blockId: string): string[];                                 // 容器块用，P1 必需
}
```

> 📌 **建议落点**：`05` 新增 §5.12「块操作 API」。**这是本审计里投入产出比最高的一项**：写 1 页，省 P1 的 18 次返工。

### 3.4 【S2】异常轴不成体系：空 / 加载 / 失败 / 无权限 / 超限

**现状**：`07 §10` 有 10 行「边界与错误态」，`05 §5.3.1` 有 capability 映射，`04 §3.4.1` 有「降级卡」三个字。**但没有一张「哪类块 × 哪一态 = 什么 UI」的表。**

具体缺：

| 缺什么 | 影响 |

| 异步块的**加载骨架**尺寸 | 图片/文件/电子表格/网页卡片/嵌入/白板六类，插入后到资源返回之间的占位长什么样、多高。不定 → 加载完成时页面跳动 |

| **降级卡统一 chrome** | A17 已列为缺口：三处（skip 档置灰 / 桥超时 / 未知 providerId）共用一套，但没有任何一处给出规格 |

### 3.5 【S2】白板全屏编辑器完全无规格

`04 §5.2` 只有一行【待补】。白板是独立全屏编辑器（画布 + 侧边图形库 + 顶部工具条），**不是文档内浮层**。它至少需要：入口（slash「画板」）、画布尺寸与缩放、图形库分类、导出为图片、只读态。

> 如果不是 V1 必做，应在 `09` 的档位表里显式标 `skip`，而不是留成「待补」——**待补会让人以为要做**。

### 3.6 【S2】引用是「容器」还是「叶子」，两处口径不一致

- `02 §8` 按**叶子** `blockquote` 写（规格完整）
- `10 A14` 指出飞书是 **`quote_container` 容器**，可包裹任意块
- `02 §17` 的容器对照表里**没有 `quote_container` 这一行**

同一件事在两篇里是两个结论。P1-01 的任务单写着要做 `quote_container`，但规格篇还是叶子的写法。

> 📌 需要一次决断：V1 做叶子（`blockquote` 仅含段落）还是做容器？建议 **V1 做叶子 + 读取时兼容容器**，把容器化推到 P1 之后，并在 `02 §8` 顶部显式写明这个边界。**不能两篇各说一套。**

> ✅ **2026-10-25 已决断（与上面这条建议相反，按实测走）**：**V1 直接做容器**，schema 为 `blockquote: { content: 'block+' }`。
> 落点：[`02 §8 ①`](./02-块类型规格总表.md) 顶部已加「容器 / 叶子口径声明」6 行表 + 硬约束。
> 依据三条实测：① 类名本身就是 `.docx-quote_**container**-block`；② `data-block-type` 值是 `blockquote`（`quote_container` 是 lark-doc 历史命名，**同指一物，不是两个块**）；③ 内部确实可放标题/列表/代码块/表格/图片（飞书不做类型限制）。
> 🔴 **为什么推翻「先做叶子」**：`02 §8 ④` 那个 `822 × 26` 看着像叶子，但它只是**单行引用时的容器外框高度**（= 一行正文 26px），多行时容器随内容增高、宽度恒 822。把「高度恰好等于一行」误读成「结构上是叶子」，是做错这一块的唯一原因。
> ⚠️ 代价必须认：写成叶子会让「粘贴多块进引用」「引用内插表格」两条路径**全部失效**，而这两条恰恰是用户高频操作，补回来的成本远高于一开始就写容器。
> 📌 `10 A14` 那行「飞书是 `quote_container` 容器」**保留不改**——它描述的是同一个东西的另一个名字，改掉反而丢掉线索；两处已互相引用。

### 3.7 【S2】「任务列表」与「任务清单」是两个东西，但没有一处并列说清

- `02 §5` `taskList` / `taskItem`：**无负责人**的勾选列表（Markdown `- [ ]`），已有完整规格
- `09` 的「团队协作 5 项」里的**任务清单**：带**负责人 / 截止日期 / 状态**的团队协作块（slash `task list`，落入 `inline-trigger` 体系）

`02 §19.3` 已实测出后者是**行内 atom**（与人员/群名片/云文档共用 `mention` node，`attrs.kind='task'`），但 §5 的 `taskList` 那里没有任何交叉引用。实现者按名字找，极可能把两者做成一件事。

> 📌 落点：`02 §5` 开头加一句「本节 = 无负责人的勾选列表；带负责人的团队任务清单见 §19.3，二者不同 node」。

> ✅ **2026-10-25 已落**：[`02 §5 ①`](./02-块类型规格总表.md) 顶部已加 4 行对照表（本质 / 有没有负责人 / 落什么 schema / 在哪一节）+ **判定口径** + **最容易做错的地方**。
> 关键三条（实现时按这个记）：
> 1. 任务列表 = **块**，`data-block-type="todo"`，`{type:'taskItem', attrs:{checked}}`，**无负责人**；
> 2. 任务清单 = **行内 atom**，`span.inline-trigger`，`{type:'mention', attrs:{type:'task', id}}`，**有** `assignee`/`dueDate`；与 @人 / 群名片 / 云文档**共用同一个 node**（[§19.3](#193-提及--mention实测)）；
> 3. **斜杠菜单里的「任务」落的是任务列表（`slash todo`）；任务清单只在提及面板 `@` 里出现** —— 这是最容易做错的一点，两者**不要塞进同一个 schema 分支**。

### 3.8 【S2】表格进阶 5 项的细则缺失

`02 §10` 六段式完整，但五个进阶能力只有名字：

| 能力 | 缺什么 |
| --- | --- |
| 合并单元格 | 选区合法性规则（跨行跨列/含表头行能否合并/合并后内容怎么拼） |
| 列宽持久化 | 存储格式与单位（px？比例？`colwidth[]`？）、schema 字段名 |
| 表头行列开关 | 开关后视觉差异（底/字重/边框）是否与普通单元格不同 |
| 整表选区 | 判定条件（点左上角？`Cmd+A` 两次？）、选中后能做什么 |
| 横向滚动 | 触发宽度、滚动条样式、滚动时首列是否冻结 |

#### ✅ 2026-10-25 结案（batch186–190 实测，5 项已全部有答案）

| 能力 | 实测结论 | 状态 |
| --- | --- | --- |
| **合并单元格** | `MergeCell` → `colspan=2 rowspan=2`、节点仍是 `TD`、**内容按行优先以单个空格拼接**（`"A B C D"`，不是 `\n`）、可 `Cmd+Z` 撤销。建选区**两种手势都行**：`click(A) → Shift+click(D)`，或 `mouse.down/move/up` 拖选（batch208 复核，旧记「拖选无效」已更正）。🔴 **按钮是 toggle**：已合并态再点 = **拆分**，拆后 `colspan` 回 1、**内容整体留在左上格不回填**（有损）。🔴 被吞格**留在 DOM 且 `display:none`**（每行 `td` 数恒 = 列数，`colspan` 之和会 > 列数） | ✅ 闭环（batch208/209） |
| **列宽持久化** | 落在 `<col width="280">`（**整数 px 字符串**），表宽 = 各列之和（840）；均分列宽后**总宽守恒**（`200,100,540 → 280,280,280`） | ✅ 闭环（schema 字段名待定） |
| **表头行列开关** | 🔴 **不只是加底色**：`标题行` 会把首行整行搬进独立的 `sticky-row-wrapper` 克隆表（`position: sticky; top: 26px; z-index: 1`、无 `colgroup`、`table-layout: auto`），块内 `table` 数 1→2；`标题列` 只加底色 + `header-column` class，不克隆。底色 `#F2F3F5`，**字重 400 不加粗**，`tag` 仍是 `TD`，**不生成 `thead`/`th`**。两个开关都是 **toggle**，菜单文案恒为「标题行/标题列」不变成「取消 X」 | ✅ 闭环（batch205，详见 02 §10 ⑦-7） |
| **整表选区** | `Cmd+A` 一次选不中（`selCells 0`），两次反而**插了 6 行**（12→18）。**飞书没有「`Cmd+A` 选整表」**；选整表只能鼠标框选 | ✅ 闭环（= 明确不做） |
| **横向滚动** | 🔴 **飞书根本不给横向滚动**：全链**无一个** `overflow-x: auto/scroll`，`.content-scroller` 是 **`hidden`**（`cw 769 / sw 844`），超宽部分**直接被裁掉**（右侧 71px 看不见），**无可见滚动条** | ✅ 闭环（V1 改判为 `auto`，见 §3.9） |

> ✅ **2026-10-24 batch203 补结**：**均分列宽除不尽** = 每列 `Math.ceil(表宽/列数)`，`437 → 146/146/146 = 438`，**总宽不守恒**（`总宽' = 列数 × ceil(总宽/列数)`）。不是「最后一列吃余数」。
> ⚠️ 仍缺：合并的**反合并（拆分）**规则（batch206 正在测）、长表（> 视口高）首行**是否真的吸顶**。

## 4. 端到端主流程（6 条链路）

> 单功能闭环 ≠ 流程闭环。以下 6 条是用户真正会走的路径，逐条看断在哪。

### L1 冷启动：打开文档 → 看到正文

```
URL → 鉴权 → 取 doc → 解析 JSON → 构建 schema → 首屏渲染 → 挂载交互 → 可编辑
```

| 环节 | 规格 | 缺口 |
| --- | --- | --- |
| 鉴权 / 无权限 | `05 §5.3.1` `canView:false` → 整页替换（图标 + 文案 + 申请按钮） | 遮罩的像素规格（图标尺寸/文案字号/按钮尺寸）**未采** |
| 取 doc | `05 §5.2` `load()` 契约完整 | — |
| 解析失败 | `05` 有 4 条错误文案 | 展示形态（toast？整页？可否重试）未定 |
| 首屏渲染 | `02 §0` 通用能力 | **加载骨架**未定（见 §3.4） |
| 空文档 | — | 空文档的初始块（1 个空段落？）+ 占位文案。✅ **矛盾已消解**（2026-10-25）：以「**不显示占位文案**」为准，见下 |

> ✅ **L1 那处硬矛盾已收口（不再是缺口）**：`02 §1` ③ 的「末尾空块显示『输入正文内容，或按 / 键选择』」已在 `02` 第 110~111 行**显式作废**，并注明「旧记是推导值，与 `00` 冲突，以实测为准」。现行唯一口径：
> - **飞书空块不显示任何占位提示** —— 伪元素 `content` 为空串、无 `data-placeholder` 属性，视觉上就是**完全空白 + 26px 行高**；
> - `#BBBFC4` 只是**占位色 Token**（供宿主自定义时用），不代表飞书自己会画占位；
> - 若产品仍要提示，属 **lark-doc 自有扩展**，文案与样式自定，**不得记作飞书规格**。
>
> 剩余真缺口只有「**空文档的初始块结构**」一项（1 个空段落 vs 0 块），归 `05 DocumentAPI.create` 的契约问题，不影响视觉。

### L2 编辑主环：输入 → 格式化 → 块操作 → 撤销 → 保存

```
键入 → 输入规则(Markdown) → 选区 → 格式化 → 块转换 → 缩进 → 撤销 → 自动保存 → 快照
```

| 环节 | 规格 | 缺口 |
| --- | --- | --- |
| 键入 / 输入规则 | `07 §8` 全表 | ✅ |
| 格式化 | `02 §15` 10 种 mark | ✅ 加粗已闭环：`style="font-weight:bold"` = **计算值 700（不是 600）**，且**不生成 `<strong>`/`<b>`**，全靠行内 style + `data-string="true"`（batch166 + 02 §15 ④-1） |
| 块转换 | `03 §3.2` 转换菜单 10 项 | ✅ |
| 缩进 | `02 §0` | ✅ |
| **撤销** | 只有快捷键 | ❌ **见 §3.1** |
| 自动保存 | `05 §5.2` + 三闸门 | ✅ 但**防抖时长**未定 |
| 快照 | `05 §5.4` 上限 20 | ✅ |

- 🔴 **六条反直觉结论**
  1. **正文同步走 HTTP POST 逐块提交，不走 WebSocket。** 别再按 Yjs + awareness 建模；WS 只承载 IM/CCM 与 AI。
  2. **并发模型是「单块 cs3 变更集 OT」，不是整块覆盖、也不是 CAS。** 版本号只是 OT 的基准 rev：落后可 rebase，超前直接 `4000028`。别实现成「版本不等就整块覆盖」。
  3. **客户端永不自己升版本。** 被拒就原样重试（指数退避 4 次），版本号只认服务端下发的 `N+1`。

### 9.14 D8 续：虚拟化**证实**（推翻 §9.8「不做虚拟化」）【batch456 + batch457】

**方法**：366 块真实文档，容器 `.bear-web-x-container` 步进滚动，每步 dump DOM 里真实存在的 `[data-block-id]` 集合 → 排序算 gap。

| **文档总块数** | **366**（`data-block-id` = 连续 `1…366`） |
| 任一时刻挂载数 | **7 ~ 59**（总量 **2% ~ 16%**） |
| 卸载方式 | **真卸载**：早期块 id 从 DOM 消失形成 gap（非 `display:none`） |
| 常驻不卸载块 | **7 个**：`1 / 38 / 40 / 147 / 158 / 163 / 366` |

| `loading="lazy"` | `img` 0/4、`iframe` 0/5 ⇒ **不用原生 lazy**（与 §9.8 一致） |

**逐点快照**：`st=0` → `1–23`+`251–256`（29 个）；`st=5000` → `1,38,40` + `68–118`（54 个）；`st=6472` → `1,38,40` + `108–147` + `158,163,366`（46 个）；`st=12144` → `163–208` + `228–270`（50 个）；**`st=16000`（底部）→ 只剩 7 个常驻块**；回顶 → 35 个。
