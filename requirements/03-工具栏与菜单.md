# 03 · 工具栏与菜单（命令条 / 气泡条 / 斜杠菜单 / 块菜单）

> 本文件覆盖飞书文档**所有命令入口**的像素级规格与 CRUD 闭环。
> 数值标注：【实测】= Playwright 实机 `getComputedStyle` + `getBoundingClientRect` 读取；【推导】= 由实测值算得；【待补】= 未拿到。
>
> **核心架构结论（复刻必读）**：飞书所有命令条**共用一套组件**（`.panel-menu-item` / `.panel-submenu-item` / `.menu-divider-item`），差异只在 `data-name` 与容器尺寸。工程上应实现**一个 `LarkMenu` 组件 + 一份命令注册表**，而不是每种菜单各写一份。

> 🔴 **hover 底色有两档，按类区分（batch256 B2–B6 四次采样，最长 2.2s）**
>
> | 项类型 | hover 稳定态背景 |
> | --- | --- |
> | 普通 `.panel-menu-item` | **`rgba(31,35,41,0.1)`** |
> | `.panel-submenu-item.hot-area-unique` | **`rgba(31,35,41,0.05)`** |
>
> 采样序列（`highlight submenu`）：静置 `rgba(0,0,0,0)` → t=300ms `0.05` → t=700ms `0.05` → t=1300ms `0.05` → **t=2200ms `0.05`（不变）**。
> → **`0.05` 不是过渡中间帧**（旧版这么写是错的），它就是这个类的稳定值。`hot-area-unique` 的大热区视觉更轻，避免 44×24 的热区比 24×24 的图标项看起来更重。

### 子菜单行为差异【实测】

| 项 | 类名附加 | 展开方式 |

### 图标色 Token【实测】

类名规律 `color-{b,g,i,o,t,y,w}-500` + 少量特例。复刻应直接把这一串做成图标色板：

`color-b-500`（蓝）/ `color-g-500`（绿）/ `color-i-500`（靛）/ `color-o-500`（橙）/ `color-t-500`（青）/ `color-y-500`（黄）/ `color-w-500`（紫）；特例：`color-b-600`、`colorful-indigo`、`color-bitable-brand`、`meego-sub-item-icon`、`diagram-url`。

## 3.1 文本浮动工具栏（选区气泡条）

### ① 功能定义
选中**非空文本**时在选区上方浮出的横向命令条，执行行内格式（加粗/斜体/…）与文本级块转换。

### ② CRUD 闭环
| 操作 | 触发 | 结果 |
| --- | --- | --- |
| **创建（显示）** | 鼠标拖选 / `Shift+方向键` 选中 ≥1 字符 | 气泡条出现在选区上方 |
| **读取** | 每个按钮按下沉态反映当前选区格式（加粗已生效则高亮） | 见下方「active 选中态」实测 |
| **更新** | 点按钮 → 命令立即作用于选区，气泡条**保持不关闭**（可连续操作） | — |
| **删除（隐藏）** | `Escape` / 点击别处 / 选区清空 / 滚动使选区离屏 | 卸载 |

### ②-1 按钮「格式已生效」active 态【batch255 A1–A4 实测】

选中 `Z55` → 点 `Bold` 前后三次采样：

| 时点 | `className` | `background-color` | `path` computed `fill` | 图标 `color` |
| --- | --- | --- | --- | --- |
| **A1 加粗前**（静置） | `panel-menu-item` | `rgba(0,0,0,0)` | `rgb(43,47,54)` | `rgb(43,47,54)` |
| **A2 点加粗后** | `panel-menu-item menu-item-hovered menu-item-actived` | **`rgb(224,233,255)`** | **`rgb(51,109,244)`** | `rgb(43,47,54)` |
| **A4 `Cmd+Z` 撤销后** | `panel-menu-item menu-item-hovered` | `rgba(31,35,41,0.1)` | `rgb(43,47,54)` | `rgb(43,47,54)` |

**三个必须照抄的细节：**

1. **底色 `#E0E9FF`**（`rgb(224,233,255)`）。这是浅蓝，不是 `0.1` 灰。
2. **蓝色只加在 `path` 上，不加在容器上**。A2 里 `icon` 的 computed `color` 仍是 `rgb(43,47,54)`，但 `path` 的 computed `fill` 变成 `rgb(51,109,244)` —— 而 `path` 的属性仍是 `fill="currentColor"`。
   → **说明飞书用 CSS 直接覆盖了 `svg path` 的 `fill`**，绕开了 `currentColor` 继承。
   → 复刻时**不能**只写 `color: #336DF4`，必须写 `path { fill: #336DF4 }`，否则 `currentColor` 会把它拉回 `#2B2F36`。
3. **`#336DF4` 就是「选中蓝」**，与色板选中环（§3.2.4 ④-7）完全同色；**不是**品牌蓝 `#1456F0`。全站「选中」语义统一用 `#336DF4`。

复刻 CSS：

```css
.lark-bubble-item { background: transparent; border-radius: 4px; }
.lark-bubble-item:hover { background: rgba(31, 35, 41, 0.1); }
.lark-bubble-item.menu-item-actived { background: rgb(224, 233, 255); }  /* 必须排在 :hover 之后 */
.lark-bubble-item.menu-item-actived svg path { fill: rgb(51, 109, 244); }
```

**判定逻辑（读选区格式）**：`menu-item-actived` 的有无 = 该格式在当前选区是否已生效，与 `isActive('bold')` 一一对应。这个类**不是静态类** —— 撤销后立即消失（A4）。

> ⚠️ 反向印证：`highlight submenu` 在 batch253 静置时就带 `menu-item-actived`，原因是当时选中的 `Z55` **本身已有黄色高亮**（`text-highlight-background-yellow-light-bg`）。所以它不是「静态脏类」，而是「选区已有高亮」的正确反映。

### ③ 显示 / 隐藏规则
- **显示条件**：选区非空 且 编辑器 focused。
- 🔴 **关键约束【batch169 N1 实测】**：**选区必须由指针（点击 / 双击 / 拖拽）产生**。用键盘打出来的选区（`Shift+方向键`、`Cmd+A`、`Shift+Cmd+→`）**不会弹出气泡条** —— batch167 K1 与 batch168 K1 两轮键盘选区测试，`[data-name]` 命中数均为 **0**；batch169 改用鼠标拖选后立刻出现完整 13 项。
  - **复刻含义**：显示条件要写成「`selection 非空` **且** `lastSelectionSource === 'pointer'`」，**不能只判断 `!selection.empty`**。否则键盘选区会多冒出一个浮层。
  - 反例参考：**斜杠菜单**是纯键盘触发（`/` 后继续打字），气泡条是纯指针触发 —— 两者触发源互斥，别共用一个显示判定。
- **隐藏条件**：选区为空 → 不显示；选区跨块时**仍显示**（飞书允许跨块选区）。
- **避让**：气泡条默认在选区**上方**；上方空间不足（被吸顶栏遮挡）时**翻到选区下方**。
  - 吸顶偏移量算法：`bubbleSafeTop()` = `.lark-doc-topbar` / `.lark-doc-toolbar` 中 `position: sticky|fixed` 且 `top ≤ 1` 的元素底边 + 6px。菜单 `top` 的 clamp 下界用它。

> ⚠️ **顺序陷阱**：飞书是 **加粗 → 删除线 → 斜体 → 下划线**（`Bold / Strikethrough / Italic / Underline`），**删除线在斜体之前**。常见的 `B I U S` 直觉顺序是错的，照抄会错位。
> **间隙规律**：同组内图标项步进 **32**（24 + 8）；跨越分隔线时变成 **17**（8 + 1 分隔线 + 8）；`more` 前是 **25**（分组级大间隙）。
> **采集方法备忘**：必须**双击选词**产生真实选区才会渲染完整 13 项。用 `mouse.down/move/up` 模拟拖拽在本页面经常落空（只渲染出 `more / shareTextLink / comment` 3 项块级气泡条）。
>
> ✅ **2026-10-25 方法更正【batch169 N1 复现成功】**：拖拽**不是不能用，而是要分步**。可行写法：
> ```js
> await page.mouse.move(x + 4, y);
> await page.mouse.down();                 await sleep(120);
> await page.mouse.move(x + 124, y, { steps: 8 });   // ← 必须 steps>1，一次跳到位会被判定为 click
> await sleep(120);
> await page.mouse.up();                   await sleep(900);

#### ④-5 应用后的 mark 结构【实测 · batch135 · 普通正文段落】

> ⚠️ 采集必须在**普通正文段落**做。代码块内 `code-hljs-*` 语法高亮**优先级更高**，字体色会被覆盖（batch134 踩坑）。

**仅字体色（选第 3 个 = 红 #D83931）**

```html
<span class="textHighlight textHighlight-pink-text textHighlight-ccmtoken"
      data-string="true" data-leaf="true">选中文字</span>
```

```css
color: rgb(216, 57, 49);          /* = 色板色值 */
background-color: rgba(0, 0, 0, 0); /* 未设背景 */
```

**再叠加背景色（第 1 行第 5 个 = 黄 rgba(255,246,122,.8)）** → 同一个 span 追加：

```css
color: rgb(216, 57, 49);                 /* 保持不变 */
background-color: rgba(255, 246, 122, 0.8); /* 新增 */
```

**点「恢复默认」** → span 降级为普通文本 span：

```html
<span class=" author-7018536132879155201">选中文字</span>
```

```css
color: rgb(31, 35, 41);
background-color: rgba(0, 0, 0, 0);
```

**关键结论**

| 点 | 结论 |
| --- | --- |
| 载体 | 单个 `<span>`，**字体色与背景色共用一个 span**，不是嵌套两层 |
| 类名三段 | `textHighlight` + `textHighlight-{name}-text` + `textHighlight-ccmtoken` |
| 数据属性 | `data-string="true" data-leaf="true"` |
| 字体色 | 走 **`color`** |

## 3.3 块手柄菜单（六点 drag-handle）

### ① 功能定义
hover 任意块 → 块左侧浮出「类型图标 + 六点拖拽手柄」→ 点图标展开块级命令菜单。

### ② CRUD 闭环

#### ④-3 可靠打开方式【★ batch228 定判 · 复刻与自动化都照这个来】

**先说结论**：用 `document.activeElement` 判定「光标在哪个块」在飞书里**永远失败** —— 飞书把 DOM focus 委托到根 `page-block`（`data-block-id="1"`），所以你会误以为焦点没落上，从而跳过 `/` 输入，菜单永远弹不出来。这是历史上「`/` 菜单时好时坏」「` ``` ` 建不出代码块」的共同根因。

**正确判定 = 读 `window.getSelection()`**：

```js
/* 光标实际所在的块 */
const caret = () => page.evaluate(() => {
  const s = window.getSelection();
  if (!s || !s.anchorNode) return null;
  const el = s.anchorNode.nodeType === 1 ? s.anchorNode : s.anchorNode.parentElement;
  const b = el && el.closest ? el.closest('[data-block-id]') : null;
  return { bid: b && b.getAttribute('data-block-id'),
           bt:  b && b.getAttribute('data-block-type') };
});

/* 用 Range 把光标塞进目标块末尾（别用 click —— 空 text 块会点到 page 块上） */
async function focusBid(bid) {
  await page.evaluate((bid) => {
    const blk = document.querySelector('[data-block-id="' + bid + '"]');
    blk.scrollIntoView({ block: 'center' });
    const ce = blk.querySelector('[contenteditable="true"]');
    ce.focus();
    const r = document.createRange();
    r.selectNodeContents(ce);
    r.collapse(false);                 // 折叠到末尾
    const s = window.getSelection();
    s.removeAllRanges();
    s.addRange(r);
  }, bid);
  await sleep(400);
  return caret();                      // ← 必须是 caret()，不是 activeElement
}
```

**标准打开序列**（batch228 实测 100% 命中，`n: 90`）：

```js
const c = await focusBid(bid);
if (c && c.bid === bid) {        // ← 校验用 caret.bid
  await page.keyboard.type('/');
  await sleep(3400);             // ← 面板动画 + 84 项挂载，给足 3.4s（<3000ms 必拿空数组）
}

   **V1 建议**：不必复刻排序算法，按**原始分组顺序**输出、只保留命中项即可，视觉差异极小（用户的真实动作是「打两个字直接回车」，不会去比对顺序）。

   → **复刻口径**：关键词无命中时 **`v-if` 卸载整个浮层**，**不要**渲染一个空白面板，也**不要**加「没有找到」提示。同时 `/` 文本本身留在正文里（菜单关掉但斜杠没被删）。

## 3.7 复刻落地建议（工程）

1. **一个 `LarkMenu` 组件**承载全部菜单；`data-name` 作为唯一命令 id，与快捷键、右键、气泡条**共用同一份命令注册表**。
2. 命令条**两变体**：`selection`（气泡条，横向）/ `block`（块手柄，纵向 214×32）。**没有 `contextmenu` 变体** —— 飞书不接管 `contextmenu`，右键走浏览器原生（batch287 定判，见 §3.1 ⑥）。
3. hover 底色统一 `rgba(31,35,41,0.1)`；圆角 4（项）/ 6（容器）；阴影 `rgba(31,35,41,0.1) 0 4px 8px 0`。
4. 所有浮层**无滚动条**（外层容器不出现 scrollbar），超长项内部滚动。
5. 吸顶避让：`bubbleSafeTop()` = sticky/fixed 且 `top ≤ 1` 的栏底边 + 6px。
