## 1. 文档模式状态机（三态，不是二态）【实测】

飞书文档是**三种交互模式**，不是「只读/可编辑」二态。入口：顶部「编辑」按钮（`docs_mode_switch_dropdown_btn`，x=1130, y=32），**下拉式**而非普通 toggle。

```
        ┌──────────┐
        │   编辑   │  ← 默认；完整编辑权限
        └────┬─────┘
   ┌─────────┼─────────┐
   ▼                   ▼
┌────────┐        ┌────────┐
│  修订   │        │  阅读   │
└────────┘        └────────┘
提出修改建议        仅查看或评论
需他人接受/拒绝     只读，仅可评论
```

| 模式 | 快捷键 | 可编辑正文 | 可插入块 | 可评论 | 气泡条 | 块手柄 | 拖拽 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| **编辑** | `E` / `Ctrl+⌥+E` | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| **修订** | `⌘+⌥+X` | ⚠️ 变修订建议 | ⚠️ | ✅ | ✅ | ✅ | ⚠️ |
| **阅读** | `Ctrl+⌥+V` | ❌ | ❌ | ✅ | ❌ | ❌ | ❌ |

> 复刻要点：「修订」是**独立的第三态**（改动以「修订建议」形式落地，需他人接受/拒绝），不能简化成编辑态的一个开关。
> **修订态的完整规格（标记 DOM / 建议面板 270 宽 / 6 个头部按钮 / 接受·拒绝行为）见 [§12](#12-修订模式suggest-mode完整规格实测-batch157158159160)。**

### 1.1 修订模式官方交叉核对（O1 + 真飞书 E2 · 2026-10-25）

真飞书测试页真实切换结果：

- 下拉入口文案：`编辑 / 可编辑文档`、`修订 / 提出修改建议`、`阅读 / 仅查看或评论文档`。
- 选择「修订」后顶栏按钮变为「修订」，页面出现「已切换为修订模式」提示；选择「阅读」后顶栏变为「阅读」，正文编辑控件/块手柄卸载，并出现「已切换为阅读模式」提示；再次选择「编辑」后恢复编辑态并出现「已切换为编辑模式」。
- 模式是当前用户维度的状态；不会把其他协作者切换成修订态。

官方帮助中心补充的状态约束：

- 有编辑权限的用户可进入修订模式；有阅读权限的用户可看到修订建议；有编辑权限的用户可接受/拒绝建议。
- 不支持批量接受/拒绝全部建议；接受/拒绝可用 `Cmd/Ctrl+Z` 撤回。
- 刷新或重新打开后仍保持修订模式。
- 高亮块边框/背景、内容缩进、有序列表序号、代码块语言、画板内编辑等不生成修订卡片，直接产生内容变更。

官方旁证：[使用文档的修订模式](https://www.feishu.cn/hc/zh-CN/articles/364198000460-%E4%BD%BF%E7%94%A8%E6%96%87%E6%A1%A3%E7%9A%84%E4%BF%AE%E8%AE%A2%E6%A8%A1%E5%BC%8F)。

## 2. 权限状态机（能力位驱动 UI）

| 能力位 | 缺失时的 UI 表现【实测】 |
| --- | --- |
| 复制权限 | 目录项加 `contextmenu-without-copyperm` → **右键菜单静默禁用**（不弹空菜单）；查找替换面板加 `without-copyperm-dom` → 隐藏部分能力 |
| 评论权限 | 气泡条 `comment` 项隐藏 |
| 版本权限 | 历史记录「还原此历史记录」按钮禁用（见 [05](./05-接口文档.md) `can()` 闸门） |
| 分享/管理权限 | `canManagePermission` 默认 **false** |

> **判定规则**【源码】：`can(key)` = `capabilities[key] !== false`（即**只有显式 `false` 才算禁用**），且异步取能力失败时**不炸**，回落默认。见 [05](./05-接口文档.md) §authorization。

## 3. 块状态机

### 3.1 块的四个互斥视觉态

| 态 | 类名 | 触发 | 清除 |
| --- | --- | --- | --- |
| 常态 | — | — | — |
| hover | 无独立类名（CSS `:hover` 或 JS 加类） | 鼠标在块区域 | 鼠标离开 |
| **focused** | `.focused` | 光标在块内 | 光标离开 |
| **isEmpty** | `.isEmpty` | 块内容为空 | 输入任意字符 |
| 选中（多块） | 拖选跨块 | 拖选 / `Cmd+A` | 点击别处 / `Esc` |

**叠加规则【实测】**
- `focused` 时**不叠加** hover 底（避免光标块看起来一直 hover）
- `isEmpty` 与 `focused` 可共存 → 显示占位文案
- 容器块（高亮/引用/表格）内部子块也可各自 `focused`

### 3.2 gutter 槽位（块左侧控件）【实测】

**顺序从左到右固定**：类型图标 → 拖拽手柄 → 折叠三角

| x（相对 heading 左边距 604） | 元素 | 尺寸 | 适用范围 |
| --- | --- | --- | --- |
| 545 | `.overlay-container.overlay-transition` > `.menu-trigger.{type}-menu-trigger.has-drag-icon` > `.hover-drag-icon-wrapper` | **42 × 26**，bg `#FFFFFF`，radius 6 | 全部块（层级 **79**） |
| 547 | `.hover-block-type-icon-container` > `span.universe-icon` | 24×24（图标 22×22） | 全部块 |
| 571 | `span.universe-icon.drag-handle` | **14 × 14** | 全部块 |
| **587** | **`.fold-handler` > `.svg-wrapper` > svg** | **16 × 16** | **仅可折叠块**（标题 / 列表 / 引用） |

- 三角右边缘距块左边 **1.75px**
- `menu-trigger` 变体类跟随块类型：`heading1-menu-trigger` / `ordered-menu-trigger` / `image-menu-trigger` / `file-menu-trigger` / `text-menu-trigger`
- 折叠三角是**标题块独有**的第三个 gutter 控件（普通文本块只有前两个）

### 3.3 折叠状态机

```
展开 ──点击三角──► 折叠 ──再点──► 展开
  │                  │
  │                  └─► 子块追加 .block-hidden（display: none），标题自身保留
  │                  └─► .fold-wrapper 追加 fold-folded，svg 旋转 -90°
  │                  └─► 目录对应项加 catalogue__item-collapse.collapsed
  │
  └─► 折叠状态按 blockId 持久化
```

| 规则 | 说明 |
| --- | --- |
| 折叠单位 | **标题块**（含其 `heading-children` 子树）；列表项；引用 |
| 状态存放 | **挂在 `blockId` 上**，不是位置索引（增删块后仍对得上） |
| 与目录的关系 | **两套独立状态**，可分别折叠（飞书实测） |
| 持久化 | 三闸门（见 [05](./05-接口文档.md)） |
| **折叠隐藏机制** | 子块追加 **`block-hidden`** 类，`getComputedStyle` → **`display: none`**（`visibility: visible` / `opacity: 1` / `height: auto` / `overflow: visible` / `position: relative` / `marginTop: 16px`，rect 全 0）【✅ batch261 A5 实测 bid=71 `.block docx-task_list-block block-hidden`】。**DOM 未卸载**（仍可 `querySelectorAll` 到），**也不是** `height:0 + overflow:hidden` |
| 隐藏块计数 | 折叠 bid=53（H7，域内 1 个 text 块）后 `.block-hidden` 数 = **1**；复原后回 **0**【batch261 A4/A9】 |
| **折叠态类名** | `.fold-wrapper` → `fold-wrapper **fold-folded** fold-show can-fold fold-block-id-53`；`svg` transform = `matrix(0,-1,1,0,0,0)` = `rotate(-90deg)`，`path.d` 不变 |
| **折叠三角 tooltip** | **展开态 hover = 「收起」** / **折叠态 hover = 「展开」**（文案 = 点击后的动作，非当前状态）【batch262 A2 + batch261 A6】。容器 `.ud__tooltip.ud__tooltip-placement-t` 48×36，内容 `.ud__tooltip-content` bg **`rgb(31,35,41)` #1F2329** / color `rgb(255,255,255)` / fs **12px** / radius **8px** / padding **8px 12px**。触发靠 `svg-wrapper` 追加 **`ud__tooltip-open`** 类，**不是** `title`/`aria-label`/`data-tooltip` 属性（三者均 null） |
| **「N 个项目已折叠」文案** | **飞书 web 端不存在**。两次折叠（batch259 C4、batch261 A8）在标题块内扫全部子节点，只有文字 `span` + `.fold-handler`，**无任何行尾计数文案** → 复刻不要做这个元素 |

> ⚠️ 复刻踩坑：折叠范围 = **缩进子树**（非标题专属）；文本块后的**未缩进列表是隐式子块**，但 `previousIndent` 要用**原 indent**。
>
> ⚠️ `can-fold` **不是**「有子块」的标志，而是**块类型可折叠**的标志：bid=52 是 H7、下一兄弟也是 H7（域内 0 个子块），照样带 `can-fold`，照样能折叠（**空折叠**，无块被隐藏，只有三角旋转）。


### 3.4 拖拽块（drag & drop）状态机与落点指示【实测 · batch137/139/142/145】

#### 3.4.1 三态流转

```
idle ──鼠标进入块左缘 gutter（x ≈ 块左 − 60 ~ 块左）──► handle-visible
handle-visible ──mousedown 于 .drag-handle──► dragging（位移 > 5px 才真正启动）
dragging ──mouseup──► 落点提交 ──► idle
dragging ──Esc──► 取消（源块恢复，DOM 无残留）
```

| 态 | DOM 证据 | 视觉 |
| --- | --- | --- |
| `handle-visible` | `.overlay-container.overlay-transition`（42×26，z **79**）挂载 | 白底圆角 6 手柄浮现（见 §3.2） |
| `dragging` | 源块加类 `dragging`，`opacity: 0.5` | 原位半透明占位 |
| `dragging` | 新增 `div.adit-draggable-snapshot-container`（`position: absolute`，**z-index 9999**） | 跟随光标的「影子块」 |
| `dragging` | 新增裸 `div`（无 class）作为**落点指示线**（`position: absolute`，**z-index 10**） | 2px 蓝色横线 |

#### 3.4.2 影子块（snapshot）规格

| 属性 | 值 |
| --- | --- |
| 容器 | `div.adit-draggable-snapshot-container` |
| 尺寸 | = 源块宽 × 源块高（实测 **824 × 29**） |
| 定位 | `absolute` @ (578, 681)（相对文档容器） |
| z-index | **9999** |
| 内部结构 | `wrapper.block.docx-text-block.dragging` → `block.docx-text-block.drag-snapshot` → `text-block-wrapper` + `hovered-mask` |
| `hovered-mask` bg | `rgba(20, 86, 240, 0.1)` = **#1456F0 @10%** |
| 顶层拖拽层 | `body` 末尾还有一个 `position: fixed; z-index: 99999` 的裸 `div`（1512×950），**不承载可见内容**，仅作事件/定位容器 |

#### 3.4.3 落点指示线规格（B21 核心）

| 属性 | 值 |
| --- | --- |
| 元素 | **裸 `div`，无 class、无 id、无 data-\* 属性** → 只能按「2px 高 + 蓝色 + absolute」特征定位 |
| 尺寸 | **高 2px**；宽 = 内容列宽（实测 **822**，另一档 **820**） |
| 左缘 x | **605**（另一档 **607**）；右缘恒为 **1427**（右端不随落点变化）。⚠️ **这两个数是「编辑器内容列左缘 605 + 宽 822」的绝对坐标，不是魔法常量**：batch535 复测时编辑器内容列左缘为 **329**，同一浮层就落在 **`x329 + w822`**。⇒ 复刻口径 = **`left: 内容列左缘` / `width: 内容列宽`**，绝对像素值随布局变 |
| 颜色 | `background: rgb(51, 109, 244)` = **#336DF4**（与主色同源，**不是** #1456F0） |
| 圆角 / 投影 | `border-radius: 0px`、`box-shadow: none` |
| 伪元素 | `::before` / `::after` 均为 `content: none` → **左端没有圆点/小方块**（与 Notion 风格不同，复刻时不要加） |
| 定位 | `position: absolute; z-index: 10` |
| 触发范围 | **仅在光标接近块边界时出现**；光标停在块垂直中部时**指示线不渲染**（实测 y=420/500/610/700 四个采样点全部无指示线） |
| 跟随性 | 落点跟着最近的块边界跳变，**不连续滑动**（实测只在 325 与 1010 两个边界出现过） |
| 自动滚动 | 拖到底部（y ≥ 860）触发自动滚动后，指示线 y 会随滚动改变（实测 1010）→ 复刻时指示线坐标须每帧重算 |

**复刻口径（推荐实现）**

```css
.drop-indicator {
  position: absolute;   /* 相对文档容器，不用 fixed */
  z-index: 10;
  height: 2px;
  background: #336DF4;
  border-radius: 0;
  box-shadow: none;
  pointer-events: none;
}
```

```js
// 每次 dragover 重算：找最近的块边界，把指示线贴上去
const gap = nearestBlockGap(pointerY);        // 上边界 or 下边界
indicator.style.top  = gap.y + 'px';
indicator.style.left = contentLeft + 'px';    // 605
indicator.style.width = contentWidth + 'px';  // 822
```

#### 3.4.4 仍未验证（复刻可先用默认策略）

| 项 | 现状 | 暂用策略 |
| --- | --- | --- |
| 落点指示线的**缩进变体**（拖到列表项内部 → 线是否左缩进 + 变短） | ✅ **定判「不存在」（batch535 轮内对照）**：把同一源块拖到**顶层块**上边界 → 出线 4 次，**全部为 `x329 + w822`**（不同光标 x 从 425/595/775 扫过，线左缘与宽度**恒定**，不随光标横向位置变化）；把同一轮的光标移到**二级列表项**（`lx380`，4 个块 × 12 点 = 48 次探针）→ **一次都没出线**。⇒ 指示线**恒等于「落点所在顶层块的正文列」全宽**，列表缩进层级不参与计算，**没有 `indent × Npx` 的收缩档** | 实现时**不要**做线宽收缩：线左缘 = 当前落点顶层块的正文列左缘，宽度 = 正文列宽（本环境 822） |

>
> ⚠️ **复现率极低（batch533/536/537/538/539 五轮仅 batch535 一轮命中）**。已验证的触发条件：
> 1. **单次大跨度横向跳**（`mouse.move(x, y, {steps: 8})` + 等 360ms）才出线；改成「先移远再移入」的斜向进入、或每 3px/40ms 的小步慢爬（batch537/539）**全部 0 命中**。

> 3. 探针起点**不能落在顶部工具栏**（y < 110 移出编辑区后，飞书整轮不再重算落点，batch536 因此 148 点全零）。

> ⇒ 复刻时**按本表规格实现即可**，不必追求复现飞书这层不稳定行为；判定「有没有出线」不适合做自动化断言。

## 4. 选区状态机

```
光标态（collapsed）
   │  拖选 / Shift+方向 / 双击（选词）/ 三击（选段）
   ▼
文本选区态
   ├─► 出现气泡条（594×42，z 87）
   ├─► 出现字数统计气泡（27×25，z 60）
   └─► 字数 = 选区字符数
   │  Esc / 点击别处 / 输入
   ▼
回到光标态
```

| 事件 | 结果 |
| --- | --- |
| 双击单词 | 选中该词 |
| 三击段落 | 选中整段 |
| 单击图片 | **只选中块**，唤起 `block-toolbar__overlay`（310×42） |
| **双击图片** | 进入大图预览（`docx-image-viewer-shell`，z 1049） |
| **单击链接** | **新标签页打开**（batch116：当前 URL 不变、`pages` 1→2），hover 卡随之关闭 |
| **hover 链接** | ≥1.2s 后浮出**链接卡 440×42 z999**（URL + 铅笔 `edit-link` + 垃圾桶 `delete-ink` + 「标题视图」+ 更多）；**编辑必须点铅笔，不能单击** |
| **选中文字 + `Cmd+K`** | 浮出**链接编辑条 434×82 z600**（占位「粘贴或输入链接」，回车或点「确认」落链接）；**粘贴 URL + 空格不会自动转链接** |
| 拖选跨块 | 多块选中；气泡条仍显示（作用于文本部分） |

> ⚠️ 复刻踩坑：触发气泡条要用**真实鼠标拖选**（`mouse.move → down → move(steps) → up`），比 `Shift+方向键` 可靠。

## 5. 浮层栈状态机

```
无浮层
  │ 触发（点击 / 快捷键 / 输入 @ / 输入 / ）
  ▼
浮层栈 [A]
  │ 触发子菜单
  ▼
浮层栈 [A, B]        ← B 的 z-index 更高（子菜单 600 > 命令条 87）
  │ Esc / 点外部
  ▼
浮层栈 [A]           ← 逐层退出，不是一次全关
  │ Esc / 点外部
  ▼
无浮层
```

| 规则 | 说明 |
| --- | --- |

>
> **结论**：飞书代码块**没有任何按键能退出** —— `Enter` / `⌘+Enter` 一律加行，`Shift+Enter` 无效。**与 Notion 的「空行 Enter 退出」完全不同，别照 Notion 实现**。

### 10.1 图片上传失败态【实测 batch291 / batch295 / batch296】

> **一句话**：飞书**不给占位块、不给重试按钮、不插任何 `image` 块**，失败完全靠一条 **3.3 秒的顶部 error toast** 提示；用户要么重新选图，要么什么都不发生。

#### ① 两条失败分支（文案不同，触发点不同）

| 分支 | toast 文案 | 是否发网络请求 | 实测载荷 | 判定（推导） |
| --- | --- | --- | --- | --- |
| **A. 本地解析不出宽高** | **「识别图片宽高失败」** | **否**（`net = []`） | 35 B 文本冒充 `.png`、2 MB / 25 MB 全 `0x41` | 文件头不是合法图片 → 前端 `new Image()` / 解码阶段就失败，**根本不上传** |
| **B. 上传/服务端校验失败** | **「上传图片失败，图片损坏或不支持该格式」** | **是** —— `POST https://internal-api-drive-stream.feishu.cn/space/api/box/stream/upload/all/?id=file&name=…&type=image%2Fpng&size=35` | batch291 的同类载荷 | 文件头能解析、数据体损坏 → 已发起上传，服务端拒绝 |

> ⚠️ 两分支的**精确分界未逐字节隔离**（同样的 35 B 文本冒充 PNG，batch291 走 B、batch295 走 A）。**V1 不必复刻这个分界** —— 统一一条「图片无法识别，请重新选择」即可；此处记录是为了说明「飞书本身也不是单一文案」。

#### ⑤ V1 实现口径（照抄飞书 + 一条我方兜底）

1. 选图后**先在本地解码取宽高**（`createImageBitmap` / `new Image()`）；解不出 → 一条 error toast「图片无法识别，请重新选择」，**不建块、不上传**。
2. 解码成功 → **立刻插入 `image` 块并显示本地预览**（不要等上传完才建块，飞书也没有「占位块」这个中间态 —— 它是「块 + 本地 blob 预览」一步到位）。
3. 上传失败 → error toast，**保留块与本地预览**，并在图片悬浮工具条里给一个「重新上传」入口（**这是我方增强，飞书没有**；飞书失败=什么都不留，用户只能重来）。
4. toast 用同一个 `Toast` 组件：`position: fixed; top: 32px; z-index: 9999;`，`bg #FEF0F0`、`radius 6`、`padding 15px 3px 15px 19px`、`14px / #1F2329`、16px 红色感叹号、**3000 ms 自动消失**。

## 13. 撤销 / 重做与历史栈【闭环补齐 · 2026-10-25】

> **为什么单开一节**：全库此前只有两行快捷键（`⌘+Z` / `⌘+Shift+Z`），而撤销栈是**所有块操作的隐性依赖** —— 块 API 每写一次都要问「这一步能不能撤」。**本节不写清，[15 §3.1](./15-闭环审计与端到端流程.md) 标的 S1 风险就无法关闭。**

### 13.1 ① 功能定义

**历史栈 = 文档状态的线性 undo/redo 队列**，单位是 **transaction**（一次 `dispatch`），不是「一次按键」。

| 概念 | 定义 |
| --- | --- |
| **step** | 一个 ProseMirror `Step`（如「插入 1 个字符」「删掉 1 个节点」） |
| **event** | 一组 step 被合并后的**一个撤销单元**（用户感知的「一步」） |
| **group** | 相邻 event 满足合并条件时自动归并（见 13.3） |
| **stack** | `undoStack`（可回退）+ `redoStack`（可重放），**redo 在新编辑发生时全量清空** |

**核心口径：撤销的是「文档状态」，不是「UI 状态」。** 折叠/展开、滚动位置、浮层开合、面板宽度、评论已读**都不进栈** —— 这是全库最容易做错的一条。

### 13.2 ② CRUD 闭环

| 操作 | 路径 | 结果 |
| --- | --- | --- |
| **增（记录）** | 任意 `dispatch(tr)` | 若 `tr.docChanged` 且不在 `addToHistory: false` 白名单 → 入 `undoStack` |
| **删（回退）** | `⌘+Z` / 顶栏撤销按钮 / 菜单「撤销」 | 弹出栈顶 event，反向 apply 全部 step → 推入 `redoStack` |
| **改（重做）** | `⌘+Shift+Z` / `⌘+Y` / 顶栏重做按钮 | 弹出 `redoStack` 栈顶，正向 apply → 推回 `undoStack` |
| **查（可用性）** | 顶栏按钮 `disabled` 态 + `canUndo()` | 栈空 = 灰禁；非空 = 可点 |
| **清空** | 文档切换 / 重载 / 版本恢复 / 只读切换 | **两栈同时清空** |
| **隔离** | 协同远端改动 | `addToHistory: false`，**不进本地栈**（但会改变 `doc`） |

### 13.3 ③ 交互与状态机

**栈模型**

```
        ┌──────────── 新编辑 ────────────┐
        ▼                                │
  [undoStack]  ──⌘Z──▶  [redoStack]      │
   e1 e2 e3              e4' e3'          │
        ◀──⌘⇧Z──┘                        │
                                         ▼
                              新编辑 → redoStack 全清
```

**合并粒度（`newGroupDelay`）**

> ✅ **实测【batch167 K2 · 2026-10-25】—— 合并窗口存在且小于 700ms**
>
> | 探针 | 操作 | 一次 `⌘+Z` 的结果 | 结论 |
> | --- | --- | --- | --- |
> | **快打** | `page.keyboard.type('ZZFAST10CH')`（Playwright 默认零延迟，10 字符连续） | 整行**全部消失**（`readLineByPrefix` 返回 `null`） | 10 次输入变更 **合并成 1 步** ✅ |
> | **慢打** | 逐字符 `MNSLOW`，每字间隔 **700ms** | 只剩 `MNSLO`（**只撤 1 个字符**） | 700ms 间隔 **不再合并** ✅ |
>
> 📐 **由此夹逼出真实窗口：`0 < newGroupDelay ≤ 700ms`**。与 ProseMirror 默认 **500ms** 一致，本轮**未做 400/500/600ms 边界扫描**（列为待补，见 §15）。
> 🔴 **推论**：一个 10 字符的连续输入 = 1 步撤销，用户体感是"一下全没了"；**中文输入法组字（composition）必须整段算一步**，不能在 composition 中途 `closeHistory`，否则打一个字撤一个字。

| 动作序列 | 是否合并为一步 | 依据 |
| --- | --- | --- |
| 连续打字（间隔 < **500ms**，**实测确认会更小或等于 700ms**） | ✅ 合并 | `newGroupDelay: 500` + batch167 K2 实测 |
| 打字停顿 > **700ms** 再打（**实测确认**） | ❌ 分成多步 | 同上 |
| 连续 `Backspace` 删字（< 500ms） | ✅ 合并 | 同上 |
| 删到**块边界**（删掉整块） | ❌ 单独一步 | 结构性 step 强制 `closeHistory` |
| **回车换行** | ❌ 换行前后各自成步 | 结构性 step |
| **应用 mark**（加粗一段） | ❌ 单独一步 | mark step 前 `closeHistory` |
| **拖拽移动块** | ❌ 单独一步 | 移动 = 删+插，需 `closeHistory` 包住整个 move |
| **粘贴多块** | ❌ 整个粘贴 = 一步 | 一次 `dispatch` |
| **切换块类型**（`/h2`） | ❌ 单独一步 | `setBlockType` 前 `closeHistory` |
| **折叠 / 展开** | **不进栈** | 纯 UI，不 `docChanged` |
| **评论增删 / 已解决** | **不进栈** | 非文档 step |
| **修订接受 / 拒绝** | ✅ 进栈（可撤回一次 accept） | 是 `docChanged` |
| **目录开关 / 工具栏折叠** | **不进栈** | 纯 UI |

**光标与选区复原（最容易漏的一条）**

| 撤销后 | 光标应落在 |
| --- | --- |
| 撤销「插入文字」 | **被删文字的原起点** |
| 撤销「删除文字」 | **被恢复文字的末尾**（不是起点） |
| 撤销「块类型转换」 | 该块内**原来 offset 位置**，clamp 到新块长度 |
| 撤销「块移动」 | 块**回到原位**，光标落该块首 |
| 撤销「整体删除多块」 | 选区**恢复为原多块选区**（不是折叠光标） |

> ⚠️ 上表是飞书行为口径（ProseMirror `history` 默认实现即如此，`Selection` 随 `Mapping` 走）。**lark-doc 若自写历史栈，必须自己维护 `selection` 的 mapping**，否则撤销后光标乱跳。

**🔴 blockId 复原策略（决定评论锚点会不会丢 —— 全节最高风险）**

| 方案 | undo 后 blockId | 评论锚点 | 评价 |
| --- | --- | --- | --- |
| **A. blockId 存 `node.attrs`**（推荐） | **自动恢复原值**（`Step` 含 attrs） | ✅ 不丢 | ProseMirror `history` 天然支持；`setNodeMarkup` 会被一并回滚 |
| B. blockId 存外部 `Map<pos, id>` | **失配**（pos 变了、Map 不跟着回滚） | ❌ 丢 | **禁止** |
| C. 每次 dispatch 后重生成全部 blockId | 全部变化 | ❌ 全丢 | **禁止** |

**结论（写进开发约束）**：`blockId` **必须**是 `node.attrs.blockId`，由 `Step` 携带；`duplicate()` / `paste()` 生成的副本**显式改 attrs 为新 id**（否则 undo 会把副本恢复成和原块同 id → 主键冲突）。

**与持久化的关系**

| 时机 | 行为 |
| --- | --- |
| 每次 `docChanged` | 触发 `onChange`，**debounce 落库**（不受撤销影响，落的是当前 doc） |
| 撤销 | **同样触发 `onChange`**，落库回旧状态 |
| 撤销到初始态 | 落库 = 初始 JSON，**不是空** |
| 落库失败 | **不回滚文档**，只提示；历史栈保持原样 |

**与修订模式的交叉**

| 组合 | 行为 |
| --- | --- |
| 修订模式下撤销 | 撤销的是**修订建议本身**（整条 suggestion 消失），不是正文 |
| 接受建议后撤销 | 正文回退 + 建议**回到待处理态**（不进已处理列表） |
| 拒绝建议后撤销 | 同 `setContent` 回退，建议回到待处理 |
| 修订模式下 redo | 重放建议创建/编辑动作 |

**单栈深度与内存**

| 项 | 建议值 | 说明 |
| --- | --- | --- |
| `depth` | **100** | ProseMirror 默认即 100；超大文档可降到 50 |
| 单 event 最大 step 数 | 1000 | 超出的批量操作（如「全选删除」）仍记 1 步 |
| 内存上限 | 约 20–40 MB（100 步 × 中等文档） | 超限时**从栈底丢弃**（FIFO），不报错 |

### 13.5 ⑤ 边界与异常

| 场景 | 行为 |
| --- | --- |
| **只读态按 `⌘+Z`** | **无反应**（两栈被清空 + 拦截命令） |
| **无权限编辑** | 同上 |
| **撤销到文档初始态再按 `⌘+Z`** | 无反应（栈底），按钮变灰 |
| **redo 后做新编辑** | `redoStack` **全清**（标准行为，不要试图保留） |
| **协同场景：本地撤销** | 只撤**本地 origin** 的 event；跳过 `remote` origin（ProseMirror `history` 支持 origin 过滤） |
| **协同场景：撤销跨越他人改动** | step 的 `Mapping` 自动 rebase；若无法 apply（内容已被删）→ **静默跳过该 step** |
| **超长文档（5 万字+）** | 栈深度自动降到 50，避免内存爆 |
| **撤销时正有浮层打开** | 浮层**不关闭**，但内部状态刷新（如块菜单的「继续编号」读取新 state） |
| **撤销时正在输入法组词** | **先 commit 组词再撤销**，不能撤到半个拼音 |
| **撤销导致当前选区所在块被删** | 光标迁到**最近的存活块**；若无 → 文档末尾 |
| **撤销时块处于折叠态** | 折叠状态**不受影响**（不进栈），但折叠键失效的块自动展开 |

### 13.6 ⑥ 字段与接口

```ts
interface HistoryOptions {
  /** 栈深度，默认 100 */
  depth?: number;
  /** 合并窗口 ms，默认 500 */
  newGroupDelay?: number;
}

interface HistoryAPI {
  undo(): boolean;                 // 返回是否真的撤了
  redo(): boolean;
  canUndo(): boolean;
  canRedo(): boolean;
  /** 手动切分「一步」，批量操作前后调用 */
  closeHistory(): void;
  /** 清空两栈（切文档/恢复版本/进出只读） */
  clear(): void;
  /** 只读查询，用于调试面板 */
  snapshot(): { undo: number; redo: number; depth: number };
}
```

| 字段 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `depth` | `number` | `100` | 栈深；≤0 视为禁用历史 |
| `newGroupDelay` | `number` | `500` | 同组时间窗（ms） |
| `addToHistory` | `boolean`（tr meta） | `true` | 单次事务级别开关；`false` = 不进栈 |
| `origin` | `string`（tr meta） | `'local'` | `'remote'` 时 undo 会跳过 |
| `closeHistory` | `boolean`（tr meta） | `false` | `true` = 本事务开启新组 |

> **工程红线**：`addToHistory: false` 只允许出现在三类事务 —— ① 协同远端 ② 纯装饰性 `setNodeMarkup`（如加 `data-hover`） ③ 初始化 `setContent`。**其他任何地方加这个 flag 都是 bug**。

## 14. 块级剪贴板与多块多选【闭环补齐 · 2026-10-25】

> 此前全库只有一句「拖选跨块」（§4）。**复制/剪切/粘贴是块操作的第二只手**，缺它则 [15 §3.2](./15-闭环审计与端到端流程.md) 的 S1 无法关闭。

### 14.1 ① 功能定义

**一次复制可承载三种载荷（同时写入系统剪贴板，按优先级消费）**

| 优先级 | MIME | 内容 | 用途 |
| --- | --- | --- | --- |
| **最高** | `text/x-larkdoc+json`（私有） | **块子树 JSON**（含 attrs、嵌套、blockId） | 文档内 / 跨飞书文档粘贴，**无损** |
| 中 | `text/html` | 渲染后 HTML（带 `data-block-type`） | 粘到 Word / 网页编辑器，**保结构** |
| 最低 | `text/plain` | 纯文本（列表带 `-`，表格用 Tab 分隔） | 粘到记事本 / 终端，**只保文字** |

> **读取顺序**：先看私有格式 → 有则走「内部粘贴」分支（**保留 blockId 语义但要重生成 id**）；否则走 HTML 清洗分支；再否则纯文本。
>
> **为什么私有格式必须存在**：HTML 无法表达 `callout` 的 `bgColor` / `details` 的 `open` / `table` 的 `colWidths` / `code_block` 的 `language` 等 attr，走 HTML 会**静默丢一半属性**。

### 14.2 ② CRUD 闭环

| 操作 | 入口 | 行为 |
| --- | --- | --- |
| **增（复制）** | ① 选中文本 `⌘+C` ② 块左侧 `⋮⋮` 手柄菜单「复制」 ③ **多块选中** `⌘+C` | 写三种载荷 |
| **增（剪切）** | `⌘+X` / 手柄菜单「剪切」 | 复制 + 删除；**删除是一次 `dispatch`（一步可撤）** |
| **增（副本）** | 手柄菜单「创建副本」/ `⌘+D` | **不经过剪贴板**：直接在当前块下方插同结构副本，`blockId` 全重生成 |
| **增（粘贴）** | `⌘+V` / `⌘+Shift+V`（纯文本） | 插到光标处；有选区则替换选区 |
| **删** | 剪切 / 粘贴替换选区 | — |
| **改** | 无「改剪贴板」概念 | — |
| **查** | 无 UI 展示剪贴板内容 | ✅ **已定案：飞书没有「粘贴预览」浮层**（batch288 + batch290，见下方 🔴） |

> 🔴 **「粘贴预览」定案（batch288 / batch290 实测，2026-10-25）**
>
> **测法**：写剪贴板（3000 / 12000 / 30000 字）→ 点进 `bid5` 行首 + `End` → `⌘+V` → 每 200ms 轮询 3.2s，用 `/粘贴为|保留格式|仅保留文本|匹配目标样式|粘贴预览|纯文本|Paste as|Keep format/` 匹配所有可见元素。
>
> | 粘贴字数 | `bid5` 文本长度 | `.ace-line` 数 | 粘贴浮层 |
> | --- | --- | --- | --- |
> | 3000 | 22 → **3023**（+3001，一字不差） | **1（不变）** | **NONE** |
> | 12000 | 22 → **12023**（+12001） | **1（不变）** | **NONE** |
> | 30000 | 22 → **30023**（+30001） | **1（不变）** | **NONE** |
>
> **结论三条**：
> 1. **没有粘贴预览浮层** —— 三种长度全 `NONE`，飞书粘贴是**即插即落**，无中间态、无「粘贴为…」选择器。
> 2. **粘贴不分块** —— 30000 字仍落在**同一个文本块**里，`.ace-line` 恒 1。**不是**「按段落拆成多块」。
> 3. **没有「超大粘贴」降级** —— 到 30000 字仍未触发任何提示卡 / 附件化 / 分片。
>
> ⚠️ **batch289 的 `isv` 块是误判**：那段粘贴后扫到 `bid82 / data-record-id=SmlKdtbAeop1rNx99eXcsIinnde` 的 `isv` 块，三次粘贴 id 与 record-id **完全相同** → 是文档里**本来就有的**「内嵌网页」块（规格见 [02 §18](./02-块类型规格总表.md) ISV 行，534×222 加载中 → 335 加载完），与粘贴无关。
>
> **V1 实现口径**：**不做**粘贴预览浮层；纯文本粘贴**不自动分块**（单块插入，`\n` 转 `hardBreak` 或按 `paragraph` 拆分**二选一需定**——建议按 `\n\n` 拆段落块、单个 `\n` 转 `hardBreak`，因为飞书 Web 的 `ace-line` 单行模型不等价于 Tiptap 的 `paragraph`）；**不做**字数阈值降级。

#### 14.4.1 块选中的进入方式（实测 batch277/278）

| 手势 | 结果 | 说明 |
| --- | --- | --- |
| **`Esc`（光标在块内）** | ✅ 该块进 `selected`，出现 **1 个** `selected-mask` | **单块选中的唯一可靠入口** |
| **`Esc` → `Shift + ArrowDown` ×N** | ✅✅ **块级多选成立**：N=2 时 `selected` 集合 = `[5,6,7]`，`selected-mask` 数 = **3**，三块 mask 分别 @y **251 / 285 / 319**（步进 **34** = 块高 26 + 块间距 8） | **这是飞书唯一的块多选手势**，必须实现 |
| 正文内跨块拖拽 | ⚠️ 是**文本选区**（`getSelection()` 有内容），**不是块选中** —— 只有拖拽终点所在块带 `selected`，中间块**不带** | 文本跨块 ≠ 块多选 |
| `Shift` + 点击另一块（块选中态下） | ❌ **无扩选效果**（选中集合不变） | 飞书**不支持 Shift+Click 扩块**，只支持 Shift+方向键 |
| 左侧 gutter 拖拽（`x = 块左缘 − 10 ~ −34`） | ❌ 不改变选中集（`elementFromPoint` 命中的是 `svg` = 块手柄图标）；拖拽过程中 `.selected-mask` 数会瞬时变成 6，其中 **3 个 rect 全 0**（是 ghost 占位，不是真选中） | 手柄区拖拽 = **移动块**，不是多选 |

> **`selected-mask` 与块 rect 的关系**：mask 的 `rect` **精确等于** 所属块根元素的 `getBoundingClientRect()`（bid5 = `601,251,538,26` → mask = `601,251,538,26`，逐值相同）。**mask 是块的兄弟层，不是块的伪元素/背景**，实现时要单独渲染一层 `pointer-events:none` 的 div。
>
> 🔴 **实现口径**：V1 必须做 **`Esc` 单块 + `Shift+ArrowUp/Down` 连续扩选**（对齐飞书实测能力）；**不做** `Shift+Click` 扩块（飞书没有）。

### 14.5 ⑤ 边界与异常

| 场景 | 要求 |
| --- | --- |
| **🔴 `blockId` 重生成** | 粘贴/创建副本产生的**每个块**都必须**新 id**；同名 id 会导致评论锚点串号、折叠态错乱。**这是本节第一红线** |
| **粘贴到自身副本位置** | 允许，产生两份；不检测重复 |
| **跨文档粘贴（飞书 → 飞书）** | 私有格式生效，**结构无损**；但引用块/同步块等**跨文档非法块**降级为普通引用/普通文本 |
| **从飞书粘到外部** | 走 HTML（保结构）或纯文本 |
| **从外部粘到飞书** | **HTML 白名单清洗**：保留 `b/i/u/s/a/code/pre/table/ul/ol/li/h1-h6/img`；**剥离** `style`（除 `font-weight/font-style/text-decoration/color`）、`script`、`iframe`、`on*` 事件、`class` |
| **粘贴 URL 文本** | 飞书**不自动识别**为链接（batch114 实测）→ 保持纯文本 |
| **粘贴图片** | 走上传流程：先插占位块（loading）→ 上传成功换 src → 失败转降级卡 |
| ~~粘贴超大内容~~（> 1 万字 / > 200 块） | ✅ **已定案：飞书无阈值、无降级、无进度提示**（batch290）。3000 / 12000 / **30000** 字三档实测：文本**一字不差**全落进同一个 `bid5`（22→3023 / 12023 / 30023），`.ace-line` **恒 1**，**无任何浮层/提示卡/附件化**。→ **V1 不做阈值降级，直接一次 `insertContent`**（若担心卡顿，用 `requestIdleCallback` 分片插入是**我方优化**，不是飞书行为） |
| **粘贴非法嵌套**（`table` 粘进段落） | 降级：拆成「段落 + 表格」 |
| **只读态复制** | ✅ 允许（能复制不能粘） |
| ~~无复制权限~~（`contextmenu-without-copyperm`） | ✅ **已定案：整条作废** —— ① 飞书**没有自定义右键菜单**（batch287：三种块 `defaultPrevented` 恒 `false`，见 [03 §3.1 ⑥ 定判](./03-工具栏与菜单.md)），因此 **`contextmenu-without-copyperm` 这个类名在飞书里不存在**，是旧记臆造；② 「正文能否复制」由 `canCopy` capability 单独管，与右键无关 → 见 [05 §5.3.1](./05-接口文档.md) 的 `canCopy` 行。**V1 不做右键、不做 `contextmenu-without-copyperm`** |
| **剪贴板被浏览器拒绝** | 走 `document.execCommand` 降级；再失败则静默（不弹错） |
| **移动端** | 长按唤出系统菜单，私有格式可能丢失 → **退化为纯文本** |

### 14.6 ⑥ 字段与接口

**私有剪贴板块载荷**

```json
{
  "v": 1,
  "source": "larkdoc",
  "docId": "doxcnXXXXXXXX",
  "blocks": [
    {
      "type": "callout",
      "attrs": { "emoji": "bulb", "bgColor": "#E0E9FF" },
      "content": [
        { "type": "paragraph", "content": [{ "type": "text", "text": "提示" }] }
      ]
    }
  ],
  "selection": { "fromBlock": "b_1", "toBlock": "b_3" }
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `v` | `number` | ✅ | 载荷版本，当前 `1`；读到不认识的版本 → **降级走 HTML** |
| `source` | `string` | ✅ | 固定 `'larkdoc'`，用于识别「是不是自己人」 |
| `docId` | `string` | ❌ | 来源文档；跨文档粘贴时用于判断「引用块是否合法」 |
| `blocks` | `BlockNode[]` | ✅ | **块子树数组**；顶层是数组以支持多块复制 |
| `blocks[].attrs.blockId` | `string` | ❌ | **写入剪贴板时保留、粘贴时丢弃并重生成** |
| `selection` | `object` | ❌ | 仅多块复制时带，用于还原粘贴后的多块选中态 |

**接口**

```ts
interface ClipboardAPI {
  /** 复制指定块（不传则复制当前选区） */
  copy(blockIds?: string[]): Promise<void>;
  /** 剪切：复制 + 删除（一次 dispatch） */
  cut(blockIds?: string[]): Promise<void>;
  /** 粘贴到指定位置 */
  paste(at?: { blockId: string; position: 'before' | 'after' | 'inside' }): Promise<string[]>;
  /** 创建副本，返回新 blockId[] */
  duplicate(blockIds: string[]): string[];
  /** 读取剪贴板（需用户手势；可能被浏览器拒绝） */
  read(): Promise<ClipboardPayload | null>;
}
```

| 方法 | 返回 | 幂等 | 备注 |
| --- | --- | --- | --- |
| `copy()` | `void` | ✅ | 失败静默 |
| `cut()` | `void` | ❌ | 一次 dispatch，可整体撤销 |
| `paste()` | **新 blockId 数组** | ❌ | 调用方需拿返回值更新自己的锚点 |
| `duplicate()` | **新 blockId 数组** | ❌ | 不经过剪贴板，纯同步，可一次撤销 |
| `read()` | `payload \| null` | ✅ | 需 `navigator.clipboard.read` 权限 |

## 14.7 顶栏辅助入口状态机【E2 · 2026-10-25】

| 状态/入口 | 初态 | 用户动作 | 成功态 | 取消/失败态 |
| --- | --- | --- | --- | --- |
| 查找替换 | `query=''`, `matchCount=0`，操作按钮 disabled | 输入 query → 更新 `matchCount/currentMatch`；输入 replacement → 替换或全部替换 | 命中高亮；替换产生新 revision | Esc/关闭回到正文；无命中保持 disabled |
| 协作者邀请 | `subjectId=null`，发送 disabled | 搜索并选中对象，设 scope/通知/备注 | 创建 `CollaboratorEntry` | 取消不写；服务端拒权保留表单错误 |
| 提及通知 | `unnotified[]` | 单个通知或全部通知 | 对象状态 `notified`，列表移动 Tab | 单对象失败不影响其他对象 |
| 段落前作者 | `showAuthor=false` | 点击开关 | 正文段前渲染作者名 + 蓝色竖线 | 再次点击移除展示，不改正文内容 |
| 引用列表 | `visible=true` | 点击显示入口 → 确认「隐藏」 | `visible=false`；可通过同一入口恢复 | 「取消」/Esc 不改变；「不再提示」只写偏好 |
| 离线可使用 | 由宿主离线能力决定 | 点击设置开关 | 本地缓存策略接管，状态见 `04 §9` | 不支持时置灰并保留解释 |
| 举报 | 未打开 | 选择理由并提交到独立 report endpoint | 记录 `reportId/requestId`，不改变文档 | 关闭/取消不提交；不能复用评论接口 |

这些命令的共同约束是：显示偏好只写宿主偏好存储；正文查询不产生文档 revision；写入型动作（替换、邀请、通知、隐私设置、组件安装、举报）必须服务端判权并在回读后才更新 UI。
