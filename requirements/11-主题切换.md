## 0. 结论先行

| 项 | 结论 |
| --- | --- |
| 主题模型 | **三态**：`light` / `dark` / `system`（飞书网页端就是三态，现代码只有两态） |
| 核心差异化 | **UI 主题 与 正文主题 双轨解耦**——飞书深色模式下可勾选「用浅色模式查看文档内容」，即 UI 深色 + 纸张浅色。这是本 SDK 相对通用编辑器的最大价值点，必须做 |
| 主题色（苍穹/天际/晴空/湖光/曜石） | **本期不做**。它是客户端壳的皮肤，`lark-doc` 只需把 `--brand` 暴露为可覆盖变量即可 |
| 实现载体 | CSS 自定义属性。现代码**只有 5 个变量**（`--lark-doc-green/ink/muted/line/soft`，引用 72 次），但仍有 **221 处硬编码 hex（121 个唯一值）+ 26 处 `background: white`** |
| 最大工作量 | 不是写深色样式，是**把 247 处字面色收编进 token**（否则深色永远漏色） |
| 附带发现 | 现代码品牌色**绿蓝混用**：`--lark-doc-green: #00b887` 与飞书实测蓝 `#1456F0` 并存（`#1456f0`×6、`#2869f5`×9、`#2f6cf6`×3）。主题化时顺带统一，见方案 §6 R4 |
| 最大风险 | mermaid 已渲染 SVG 不会自动变色，必须**重渲染**；代码高亮需第二套配色 |
| 色值 | 本文 §4.5 给的是**推导基线**，全部标注 `【推导·待实测】`。按项目惯例，必须去真飞书深色模式采集覆盖，**不得凭手感定稿** |
| **宿主对齐** | 实测宿主 `pcvue-1023`（见 [13](./13-宿主主题-pcvue-1023.md)）：已有 `html[data-skin]` 多主题体系且 `dark` 已定义，但 lark-doc 现写死 `theme:'light'` **完全不跟随**。主题模型需从三态扩为**四态**（加 `host`），深色色板需增补「宿主对齐档」（墨绿系 `#1d3d39`） |

## 1. 飞书口径（官方帮助中心 · 实测文档）

来源：飞书帮助中心《更换主题模式和主题色》(784578188399)、《修改云文档偏好设置》(849872303611)。

### 1.1 客户端（V7.4 及以上）

| 能力 | 入口 | 取值 |
| --- | --- | --- |
| 主题模式 | 头像 > 设置 > 通用 > **主题模式** | 浅色 / 深色 |
| 跟随系统 | 同上，复选框 | 勾选后随设备外观自动切换 |
| **正文保持浅色** | 深色模式下的复选框「**用浅色模式查看文档、邮件内容**」 | 勾选后文档/邮件/表格/思维笔记正文仍为浅色 |
| 主题色 | 头像 > 设置 > 通用 > **主题色**（仅桌面端） | 5 种：苍穹（默认）、天际、晴空、湖光、曜石 |

> 平台差异：**Linux 客户端不支持跟随系统**，需手动切换。

### 1.2 网页端（云文档）

| 能力 | 入口 | 取值 |
| --- | --- | --- |
| 外观 | 云文档页面右上角头像 > **外观** | **深色 / 浅色 / 跟随系统**（三态） |
| 主题色 | —— | 网页端不支持 |

> 注意：帮助中心 FAQ 措辞是「为云文档更换主题色」，但实际选项就是「浅色 / 深色 / 跟随系统」三个 —— **网页端同样只有明暗，没有彩色主题**。

### 1.3 提炼出的三条产品语义

1. **默认跟随**：首次进入应尊重系统偏好，而不是硬给浅色。
2. **三态而非两态**：`跟随系统` 是"清除覆盖"的语义，不是第三种外观。
3. **UI 与内容可分离**：深色 UI 下正文仍可浅色。映射到 SDK 就是两个正交维度：
   - `theme`：chrome（工具栏 / 菜单 / 气泡条 / 侧栏 / 弹窗）的明暗
   - `contentTheme`：纸张（正文区）的明暗

## 2. 业界基线（2025–2026 Baseline）

来源：W3Tweaks / StackPractices / Framer 深色模式指南（2025 迭代版）。

| 主题 | Baseline | 采纳决策 |
| --- | --- | --- |
| `prefers-color-scheme` | 2019 ✅ | **采纳**，三态的 `system` 分支依赖它 |
| `color-scheme: light dark` | ✅ | **采纳，必须放 `:root`**——它同时启用 `light-dark()` 并让原生滚动条/表单控件跟随 |
| CSS 自定义属性 | ✅ | **采纳**，唯一载体 |
| `light-dark()` | 2024（Chrome 123+ / Safari 17.5+ / FF 120+） | 不采纳为主力。原因见 §5 决策 D3——双轨模型下它表达不了"UI 深 + 正文浅" |
| OKLCH + `color-mix()` | 2023 ✅ | **部分采纳**：`color-mix()` 用于派生 hover/边框；OKLCH 暂不引入（现有 06 全是 hex/rgb，混两套色彩空间会失控） |
| View Transitions API | 2025（Chrome 111+ / FF 138+ / Safari 18+） | **降级采纳**：支持的浏览器走圆形 bloom，不支持的直接切换（不 polyfill） |
| `forced-colors` | ✅ | **采纳**：Windows 高对比度模式用系统色 `Canvas / CanvasText / LinkText` |
| `prefers-reduced-motion` | ✅ | **采纳**：门控所有主题过渡动画 |
| 多标签页同步 `storage` 事件 | ✅ | **采纳** |
| `<meta name="theme-color">` | ✅ | **采纳**：仅 WC 独立页面场景，由 JS 同步更新（该 meta 只听媒体查询，不听 `data-theme`） |

### 2.1 六条必须遵守的工程纪律

1. **不吃纯黑**：纯黑底 + 纯白字可读性差。底色用深灰，正文用略灰白。
2. **深色下阴影要减弱**：黑底上阴影几乎不可见，硬加会显脏；Material 3 的做法是**抬升层级时表面变亮**而非变暗。
3. **品牌色要重调**：`#1456F0` 这类浅色底调好的蓝，在深底上会发闷，需提亮一档。
4. **不反色**：深色不是把浅色取反，是重新设计的一层 semantic token。
5. **两套色板都要过对比度**：正文 4.5:1，大字/UI 组件 3:1（WCAG 2.2）。
6. **过渡只在切换瞬间生效**：全局常驻 `transition: all` 会让首屏"渐显"，必须在首帧后再挂。

## 3. 需求规格

### 3.1 三态模型

| 值 | 语义 | 解析结果 |
| --- | --- | --- |
| `'light'` | 强制浅色 | 浅 |
| `'dark'` | 强制深色 | 深 |
| `'system'` | **跟随系统，无覆盖** | 由 `prefers-color-scheme` 实时决定；系统切换时**立即响应** |

- `'system'` 是**默认值的候选**（见 §3.6 决策）。
- 存储里只记 `light` / `dark` / `system` 三个字面值；**不把解析后的结果落库**，否则系统切换后无法再跟随。
- **第四态 `host`（跟随宿主）**：嵌入式 SDK 的宿主往往已有自己的主题体系，且**宿主 CSS 未必有变量**（实测 `pcvue-1023` 零 CSS 变量，靠 `html[data-skin]` 编译期展开）。此时 lark-doc 无法读变量继承，只能读属性。规格见 §3.9。

| 值 | 语义 | 解析来源 |
| --- | --- | --- |
| `light` / `dark` | 强制 | 自身 |
| `system` | 跟随系统 | `prefers-color-scheme` |
| **`host`** | **跟随宿主** | 监听宿主属性（默认 `documentElement[data-skin]`）+ 映射表 |

### 3.2 双轨：UI 主题 × 正文主题（核心）

| 维度 | 选项 | 默认 | 作用域 |
| --- | --- | --- | --- |
| `theme` | `light \| dark \| system` | `'light'` | chrome：工具栏、块菜单、气泡条、侧栏、弹窗、浮层、滚动条 |
| `contentTheme` | `'auto' \| 'light' \| 'dark'` | `'auto'` | 纸张：正文区背景、正文文字、块内元素、代码/表格/高亮块 |

- `contentTheme: 'auto'` = 跟随 `theme` 的解析结果 → 等价于传统单轨，零额外成本。
- `contentTheme` **不接受 `system`**——它已经是 `theme` 解析后的下游，再接系统会造成二次解析语义混乱。
- 组合矩阵（4 种有效态）：

| theme 解析 | contentTheme | 效果 | 对应飞书 |
| --- | --- | --- | --- |
| light | auto | 全浅 | 浅色模式 |
| dark | auto | 全深 | 深色模式 |
| dark | light | **UI 深 + 纸张浅** | ✅ 深色模式 + 勾选「用浅色模式查看文档内容」 |
| light | dark | UI 浅 + 纸张深 | 飞书无此组合，但宿主自定义需要，放开 |

### 3.3 DOM 契约（修订现行实现）

现状 `LarkDoc.js:194-198` 只写 `data-theme` + `.lark-doc-dark`。**CSS 里零条规则响应它** —— 类写了但没皮肤。修订为：

| 属性/类 | 宿主 | 取值 | 承载 |
| --- | --- | --- | --- |
| `data-theme` | 根容器 | `light` \| `dark` | **已解析**的 UI 主题（不含 `system`） |
| `data-content-theme` | 根容器 | `light` \| `dark` | **已解析**的正文主题 |
| `data-theme-source` | 根容器 | `explicit` \| `system` | 当前是否处于跟随态（调试与断言用） |
| `.lark-doc-dark` | 根容器 | 存在/不存在 | **保留**，历史宿主可能在用，语义 = `data-theme="dark"` |

> **向后兼容**：`data-theme` 从"两态字面值"变成"已解析值"。`'system'` 不会出现在该属性上 —— 原有读 `data-theme` 的宿主代码不会读到陌生值。

### 3.4 Token 体系（两层）

```
L1 基础层  --ld-gray-50 … --ld-gray-900  原始色值，不直接使用
L2 语义层  --ld-text / --ld-bg-surface / --ld-border …  组件唯一可引用层
```

**硬性规则**（写进 lint，见开发方案 §5）：

1. 组件 CSS **只允许引用 L2**，禁止出现 L1，更禁止出现字面 hex。
2. 宿主只能覆盖 **L1 或 L2 均可**，但 L2 覆盖优先级最高（见 §3.5）。
3. 语义层按"角色"命名而非"颜色"命名：用 `--ld-text-secondary` 不用 `--ld-gray-600`。

### 3.5 覆盖优先级（从低到高）

```
① 内建浅色默认值        :root
② 内建深色值            [data-theme="dark"] / [data-content-theme="dark"]
③ 宿主注入的 token      宿主在任意祖先或 :root 上写 --ld-*
④ 运行时 setTheme() 写入的内联变量（最高）
```

- ② 必须能压过 ①：靠**选择器特异性**（`[data-theme="dark"]` > `:root`），不靠 `!important`。
- ③ 能压过 ② 是关键：宿主想微调深色，直接写 `--ld-brand: #xxx` 即可，不需要改库。

### 3.9 第四态 `host`：跟随宿主主题

> 完整实测见 **[13-宿主主题-pcvue-1023.md](./13-宿主主题-pcvue-1023.md)**。本节是规格摘要。

**为什么需要**：嵌入式编辑器的宿主通常已有主题体系。实测 `pcvue-1023` 的三条硬约束：

| 约束 | 事实 |
| --- | --- |
| 宿主有主题 | ✅ `$themes` map（`default` / `dark`），`dark` 已完整定义 |
| 切换载体 | `html[data-skin]`，由 `store/modules/themes.js` 写入 |
| **宿主 CSS 变量** | ❌ **0 个** —— 全编译期 SCSS 展开，运行时读不到任何变量 |

→ 因为第 3 条，`var()` 继承路线**走不通**，只能**读属性 + 映射**。

**规格**：

```js
new LarkDoc({
  theme: 'host',
  hostSkin: {
    attr: 'data-skin',                                   // 默认
    target: () => document.documentElement,              // 默认
    map: { default: 'light', dark: 'dark', newYear: 'light' },
    fallback: 'light',
  },
})
```

| 规则 | 内容 |
| --- | --- |
| R1 | 仅 `theme === 'host'` 时挂 `MutationObserver`（`attributeFilter: [attr]`），避免常驻开销 |
| R2 | 未命中 `map` 或未设属性 → `fallback` |
| R3 | `data-theme-source` 写 `"host"`，与 `system` 区分 |
| R4 | 宿主皮肤名与 lark-doc 主题名**解耦**：lark-doc 不写死任何宿主私有属性 |
| R5 | `contentTheme` 仍独立生效（`'auto'` = 跟随 `theme` 解析结果，此时即跟随宿主） |
| R6 | 同时提供 `setTheme()` 显式通道作为兜底（宿主可在自己的 `changeTheme` 里调） |

**深色色板需增补「宿主对齐档」**：宿主深色底是**墨绿系 `#1d3d39`**，与 §4 的中性灰推导档并排会割裂。交付为一个可选 preset（如 `theme-preset-pcvue.css`），**不推翻默认档**。对照表见 [13 §4.3](./13-宿主主题-pcvue-1023.md)。

### 4.6 选区与光标色【实测 · batch84 · M8】

用 `getComputedStyle(el, '::selection')` 读真实渲染值（CSSOM 里**搜不到** `::selection` 规则 → 说明是**内联/JS 注入**或 UA 默认层，别指望从样式表抄）：

| 探测元素 | **浅色 `::selection` bg** | **深色 `::selection` bg** |
| --- | --- | --- |
| `.ace-line`（正文行内层） | **`rgba(20, 86, 240, 0.18)`** ← #1456F0 | **`rgba(51, 112, 235, 0.26)`** ← #3370EB |
| `.docx-page-block` | **`rgba(20, 86, 240, 0.18)`** | **`rgba(51, 112, 235, 0.26)`** |
| `body`（行外空白区） | **`rgba(20, 86, 240, 0.34)`** | **`rgba(51, 112, 235, 0.34)`** |
| `::selection color` | `rgb(31,35,41)`（= 原文字色） | `rgb(240,240,240)`（= 原文字色） |

> 📌 **四条关键结论**：
> 1. **选区蓝是两套，不是一套**：浅色 **#1456F0**，深色 **#3370EB**（更亮更蓝，深底上才看得见）。别用单一变量 + α 混色糊过去。
> 2. **α 也分两层**：行内 **0.18（浅）/ 0.26（深）**，`body` 层恒 **0.34**。原因是 body 上另有一条 `::selection` 规则给更高不透明度；选区拖到行尾空白/跨块时呈现更深的蓝（这是"选区高亮延伸到行尾"的视觉来源）。
> 3. **深色下 α 反而更高**（0.18 → 0.26）：深底上需要更强的叠加才可见；但基色也更亮，两者叠加后视觉强度相当。
> 4. **文字不反色**：`::selection color` 恒等于当前正文色（浅 #1F2329 / 深 #F0F0F0），飞书**不做反白**。
> 5. CSSOM 里**搜不到任何 `::selection` 规则**（`rules: []`）→ 值是**运行时 JS 注入**或写在 scoped/哈希类里，复刻时只能硬写这两个 rgba，抄不到源码。

### 4.7 滚动条【实测 · batch84 · M9】

**文档主滚动区（`.docx-page-block` / `.bear-web-x-container` / `body` / `html`）**：`::-webkit-scrollbar` 三件套**全部读不到有效值**（`width: auto`、bg `rgba(0,0,0,0)`）——飞书主区**不自定义滚动条**，用系统原生（`color-scheme` 控制明暗）。

**组件内滚动区（`.ud__scrollArea` = ud 组件库）**：有完整自定义规格：

| 伪元素 | 实测值 |
| --- | --- |
| `::-webkit-scrollbar` | **width / height = 11px**，bg `transparent` |
| `::-webkit-scrollbar-thumb` | **radius `9999px`（胶囊）**、border **`2px solid transparent`**、**`background-clip: padding-box`** |
| thumb 背景 | **`rgba(var(--N900-raw), 30%)`** |
| thumb `:hover` | **`rgba(var(--N900-raw), 60%) !important`** |
| thumb transition | **`background 0.2s cubic-bezier(0.34, 0.69, 0.1, 1)`** |
| `::-webkit-scrollbar-track` | bg `transparent` |
| `::-webkit-scrollbar-button` | **`display: none`** |
| `::-webkit-scrollbar-corner` | bg `transparent`、`overflow: hidden`、`border-bottom-right-radius: 4px` |

> 📌 **要点**：
> 1. **`--N900-raw` 是 raw 通道变量**：`rgba(var(--N900-raw), 30%)` 的写法要求变量存的是 `r, g, b`（逗号分隔裸值），不是完整颜色。复刻时必须同样拆成 raw 通道，否则 `rgba()` 拼不出来。
> 2. **`background-clip: padding-box` + `2px solid transparent` border** 是"thumb 比轨道窄 4px、两边留空隙"的标准做法——比直接写 `width` 更抗缩放。
> 3. **hover 才加深**（30% → 60%），静置时几乎看不见；这是飞书滚动条"不打扰"的关键。
> 4. **主文档区不自定义**，所以深色下主滚动条靠 `color-scheme: dark` 让浏览器自己变暗即可，**不要**给 `.docx-page-block` 硬套 11px 自定义条（会和飞书不一致）。
> 5. 另一条独立规则 `.fOLMAw::-webkit-scrollbar { width: 10px; }` 是**哈希类名**（CSS Module），属于某个具体组件，非全局基线。

> **不是只换基色**——基色从"浅色次要色 #646A73"换成"深色次要色 #A6A6A6"，**同时 α 从 0.05 提到 0.08**（深底上 5% 太弱看不出来）。复刻时这个 hover/底色 Token 必须存**两对值**，不能只存一个 α。
> 🔑 **未勾选复选框的边框不是主色**：浅 #1F2329（= 正文主色）、深 #757575——**未选中态用中性色，只有勾选后才变主色**。

#### 4.9.4 引用块 `slash quote`

DOM 链（6 层，两主题完全一致）：

```
block.docx-quote_container-block                    822×26
└ .quote-container-block                            820×26   padding 0 2px 0 12px   bg 透明
   ├ ::before  ← 竖线本体  2×26  position:absolute  left:-2px  top:0  content:""
   └ .quote-container-block-children                806×26
      └ .render-unit-wrapper.quote-container-render-unit   806×26
         └ .block.docx-text-block                   810×26
```

| 元素 | 浅色 | **深色** | 变/不变 |
| --- | --- | --- | --- |
| `.docx-quote_container-block` | **822**×26（比正文栏宽 2px） | 822×26 | ❌ |
| `.quote-container-block` | 820×26，padding **`0 2px 0 12px`**，bg 透明 | 同 | ❌ |
| **`::before`（竖线）** | **2×26**，bg **`rgb(187,191,196)` #BBBFC4**，`absolute` `left:-2px` `top:0` | bg **`rgb(95,95,95)` #5F5F5F** | ✅ 变 |
| `.quote-container-block-children` | 806×26 | 806×26 | ❌ |
| **引用正文色**（`.ace-line` 层） | **`rgb(100,106,115)` #646A73**（次要色） | **`rgb(166,166,166)` #A6A6A6** | ✅ 变 |

> 🔑 **竖线深色 #5F5F5F 与代码块 border 深色值完全相同**（见 §4.8）——飞书深色下「中性描边」统一收敛到 **#5F5F5F / #434343 两档**（#5F5F5F 用于块描边与竖线，#434343 用于表格网格线）。
> 📌 引用**正文用次要色**（不是主色 #1F2329），这是飞书"引用内容降级"的视觉表达；容器 padding-left **12px** 是竖线留给文字的间距。

#### 4.9.5 分割线 `slash divider`

block.docx-divider-block                            824×25
└ block-comment.divider-block-comment               820×25
  └ .block-content-container                        820×25
    └ .divider-block.editable                       820×25

| --- | --- | --- | --- |
| `.docx-divider-block` | **824**×25（块高 25，非 1） | 824×25 | ❌ |
| `.divider-block__container` | 820×25，padding **`12px 0`** | 同 | ❌ |

## 5. 关键子系统规格

### 5.1 mermaid 图表（最大风险项）

- 已渲染的 SVG **不会**随 CSS 变量变化——`mermaid.initialize({ theme })` 只对**后续**渲染生效。
- 规格：`theme` 解析值变化时，必须对每个已渲染图表**重跑渲染**（`diagram.js` 已有版本号丢弃机制，可复用）。
- 主题映射：`light → 'default'`、`dark → 'dark'`，并用 `themeVariables` 覆盖成 §4 的推导色，避免 mermaid 自带深色与整体不一致。
- **性能闸门**：图表数 > N（默认 20）时降级为「仅新渲染生效，存量不变 + 提示刷新」，避免整篇重排卡死。

### 5.2 代码高亮

- 06 §6.5.1 有浅色一组实测，需补深色一组（M6）。
- 实现：两套 token class 配色，由 `[data-content-theme]` 切换，**不能**靠 `filter: invert()`（会把品牌色也反掉）。

### 5.3 语义色板（高亮块 8 色 × 3）

- 06 §1.5 的三组（字体/边框/填充浅档·深档）在深色下需**整组重定**（M5）。
- 原则：填充色在深色下应转为**低饱和深色底**，而非维持浅底（浅底在深纸张上会"发光"）。

### 5.4 图片与媒体

- 亮图在深色下刺眼：提供 `--ld-media-dim` 开关，深色下对 `img` 施加 `filter: brightness(.85)`。
- **默认关闭**（避免过度处理）；且用户主动 hover 时恢复 `filter: none`。

### 5.5 滚动条与原生控件

- `:root` 加 `color-scheme: light dark`，并在 `[data-theme]` 上写具体值（`light` / `dark`）以精确控制。
- 自定义滚动条 thumb 走 `--ld-scrollbar-thumb`。

### 5.6 第三方嵌入（iframe）

- 09 §bridge 已预留 `host → iframe : theme` 消息位，payload 定义为：
  ```js
  { ns: 'lark-embed', v: 1, type: 'theme', payload: { theme: 'dark', contentTheme: 'dark' } }
  ```
- 嵌入页必须响应此消息，否则深色 UI 里嵌一个白底卡片。

### 5.7 Web Component 属性

| 属性 | 取值 | live |
| --- | --- | --- |
| `theme` | `light \| dark \| system` | ✅（现状已是 live） |
| `content-theme` | `auto \| light \| dark` | ✅ |

### 5.8 事件与 API

| 项 | 签名 | 说明 |
| --- | --- | --- |
| 方法 | `setTheme(theme, contentTheme?)` | 运行时切换 |
| 方法 | `getTheme()` → `{ theme, contentTheme, resolved, source }` | `resolved` 是已解析值 |
| 事件 | `onThemeChange` / `on('themeChange', fn)` | payload 同 `getTheme()` |
| 选项 | `themeStorage` | `'local'` 才写 localStorage（复用 05 §5.10 `storage` 的闸门语义）；否则不落盘，由宿主通过 `onThemeChange` 自行持久化 |

## 6. 持久化与首屏

| 场景 | 方案 |
| --- | --- |
| 防闪烁 | 宿主在 `<head>` 内联阻塞脚本，`lark-doc` **提供该片段**（读取 localStorage → 在根容器写 `data-theme`）。SDK 自身无法早于宿主首帧 |
| 存储键 | `lark-doc:theme`（值：`light`/`dark`/`system`），`lark-doc:content-theme` |
| 多标签同步 | 监听 `storage` 事件，同键变化时同步生效 |
| 系统切换 | `matchMedia('(prefers-color-scheme: dark)').addEventListener('change')`；仅当 `theme === 'system'` 时响应 |
| SSR/SSR hydration | 宿主需自行用 cookie 输出属性；SDK 侧保证"属性已存在则不覆盖" |

| 项 | 规格 |
| --- | --- |
| 过渡 | 仅 `--ld-*` 中颜色类 token 过渡，`200ms ease`；**首帧不挂**（切完加 `.ld-theme-transition`，300ms 后摘掉） |
