# 05 · 接口文档与字段含义

> 定位：本文件是「复刻飞书文档网页」所需的**接口契约**。分两层：
> - **A 层（已有）**：`lark-doc` 包内已实现的 Provider 契约，方法名/字段为源码实测，可直接对接。
> - **B 层（预期）**：要达成 1:1 飞书还需要但当前未实现的接口，按飞书实机行为反推设计，标注【预期】。
>
> 约定：`?` 表示可选；`Promise<T>` 表示允许同步返回（内部 `await` 兼容同步值）。所有时间戳为 **毫秒 epoch**。所有 ID 为 **字符串**。

| `authorization` | `getCapabilities` | 同左 | 已有 |

| `mention` | `search` `resolve` | 【预期】见 5.7 | 待建 |

> ⚠️ `document` 与上面 8 个不同级：它**不参与 `PROVIDER_FACTORIES` 校验**（文档集合操作发生在「打开文档之前」，那时 `DocumentSession` 还没建）。宿主可在打开文档前只接 `document` 不接其余。详见 **5.13**。

## 5.2 persistence Provider（草稿 + 本地快照）

### 方法签名

| 方法 | 入参 | 返回 | 语义 |
| --- | --- | --- | --- |
| `load()` | 无 | `DocumentRecord \| null` | 读草稿；无草稿返回 `null` |
| `save(record)` | `SaveInput` | `StoredRecord` | 写草稿（覆盖） |
| `snapshots()` | 无 | `StoredRecord[]` | 列快照，**最新的在前** |
| `snapshot(record)` | `SaveInput` | `StoredRecord` | 建快照并写回列表 |
| `restore(id)` | `string` | `StoredRecord` | 按 id 取快照（**不覆盖原文**，由调用方写回） |

### 字段含义

**`SaveInput`**

| 字段 | 类型 | 必填 | 含义 |
| --- | --- | --- | --- |
| `title` | `string` | ✅ | 文档标题。校验用 `typeof === 'string'`，空串合法 |
| `json` | `ProseMirrorJSON` | ✅ | 正文。必须 `{type:'doc', content:[...]}` |
| `html`? | `string` | ❌ | HTML 派生副本，仅 `saveHtml` 开启时注入 |
| `updatedAt`? | `number` | ❌ | 不传则由 `record()` 内部 `Date.now()` 覆盖 |

**`StoredRecord`（= `DocumentRecord` + `id`）**

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `title` | `string` | 标题 |
| `json` | `object` | 正文 JSON |
| `updatedAt` | `number` | 落库时间（ms） |
| `html`? | `string` | HTML 副本 |
| `id`? | `string` | **仅快照有**，格式 `${Date.now()}-${sequence}`，`sequence` 为进程内自增 |

### 合法性校验（`validRecord`）

必须同时满足，否则抛「文档结构无效，未保存」：
1. `typeof record.title === 'string'`
2. `record.json.type === 'doc'`
3. `Array.isArray(record.json.content)`
4. `Number.isFinite(record.updatedAt)`

### 行为约束（实测源码）

- **快照上限** `maxSnapshots` 默认 **20**；`options.maxSnapshots` 可覆盖，负数被 `Math.max(0, …)` 夹到 0。
- **写入顺序**：`snapshot()` 用 `[entry, ...snapshots()]` 头插，再 `slice(0, max)` 截断——超限时**丢弃最旧的**。
- **存储键前缀**：`tiptap-vue2:lark-doc:` + `draft` / `snapshots`。
- **错误文案**（应原样透出给用户）：
  - 读失败 → `无法读取本地存储，请导出当前文档`
  - JSON 解析失败 → `本地文档数据损坏，请导出当前文档后重新保存`
  - 写失败 → `本地保存失败，可能已禁用存储或空间不足；请导出当前文档`
  - 快照列表损坏 → `本地快照数据损坏，未覆盖现有文档`
  - `restore(id)` 未命中 → `该快照不存在`
- **不迁移旧 Yjs 草稿**：注释明确「不读取、迁移或清理原 Yjs 草稿」。

## 5.3 authorization Provider（能力集合）

### 方法签名

| 方法 | 入参 | 返回 |
| --- | --- | --- |
| `getCapabilities(ctx)` | `{ documentId, user }` | `Promise<Capabilities> \| Capabilities` |

### `Capabilities` 字段（8 项，默认全 true，仅 `canManagePermission` 默认 false）

| 字段 | 默认 | 控制什么（UI 表现） |
| --- | --- | --- |
| `canView` | `true` | 能否看到正文（false → 整篇只读遮罩） |
| `canEdit` | `true` | 编辑器 `editable`；false → 无光标、工具栏置灰 |
| `canComment` | `true` | 划词气泡条「评论」按钮、右键「评论」项 |
| `canResolveComment` | `true` | 批注卡片「解决」按钮 |
| `canCreateVersion` | `true` | 「创建版本」入口（版本面板按钮） |
| `canRestoreVersion` | `true` | 版本条目「恢复」按钮 |
| `canExport` | `true` | 导出菜单（Word/PDF/Markdown） |
| `canManagePermission` | `false` | 分享/权限设置入口 |

### 行为约束

- `normalizeCapabilities` 做 `{...DEFAULT, ...value}` 浅合并，**未知键原样保留**（可扩自定义能力）。
- Session 的 `can(k)` 判定：`capabilities[k] !== false` —— **缺省即允许**，只有显式 `false` 才禁用。
- **异步失败不炸**：构造时 `refreshCapabilities().catch(...)` 只 `emit('error')` 并保留上次能力，避免 unhandled rejection。（源码 `DocumentSession.js:43-46`）
- 飞书实机对应：**无权限项不是隐藏，而是静默禁用**（实测目录右键、块菜单部分项为此表现）。

### 5.3.1 capability → UI 映射表【唯一真源 · B24】

> 这张表是**唯一真源**。① `onAuthenticate` 返回的必须就是同一套 8 个字段（不要另定义一套权限名）；② 任何 UI 组件只能通过 `session.can(key)` 读取，**禁止直接读角色名 / 自己判断 owner**；③ 下表「置灰」的统一视觉是：图标与文字 `#BBBFC4`、`cursor: not-allowed`、`pointer-events` 保留（可 hover 出 tooltip 解释原因）、点击无任何副作用。

| capability | false 时的 UI 表现 | 影响范围（穷举） | 是否置灰 |
| --- | --- | --- | --- |
| `canView` | 整个编辑器容器替换为**只读遮罩**（居中图标 + 「你没有查看权限」+ 「申请权限」按钮） | 全页 | ❌ 不是置灰，是**整页替换** |
| `canEdit` | `editor.setEditable(false)`：无光标、不可键入、不可删 | 气泡条**全部格式项**、`/` 斜杠菜单、顶部工具栏全项、块手柄拖拽与点击删除、Tab/Enter/Backspace 等编辑键、`⌘+B/I/U` 等快捷键、图片/表格/嵌入的尺寸拖拽 | ✅ 置灰 |
| `canComment` | 发不了新评论 | ① 气泡条「评论」按钮 ② 块工具条「评论」 ③ `⌘+⌥+M` ④ 侧栏评论面板的「新建」入口 ⑤ 正文右键「评论」项。**已有评论仍可正常查看与定位**（这是刻意的，不可一并藏掉） | ✅ 置灰 |
| `canResolveComment` | 改不了评论状态 | ① 面板头 `resolve-btn`（解决/重新打开）② 已解决卡片上的「重新打开」。**发评论与回复不受影响**（与 `canComment` 正交） | ✅ 置灰 |
| `canCreateVersion` | 建不了版本 | 版本面板的「创建版本」按钮 + 「命名版本」入口 | ✅ 置灰 |
| `canRestoreVersion` | 恢复不了版本 | 版本条目的「恢复」按钮；provider 抛错文案**原样透出**（不二次包装） | ✅ 置灰 |
| `canExport` | 导不出 | 「更多」菜单的导出三项（Word / PDF / Markdown）+ 图片右键「下载图片」 | ✅ 置灰 |
| `canManagePermission` | **降级而非置灰（唯一特例）** | 顶栏「分享」按钮 → 变成「分享只读链接」（只复制链接，不弹权限面板） | ❌ 降级 |

**三条交叉约束（必须同时成立）**

1. **同源**：`onAuthenticate` 的返回结构 = `getCapabilities` 的返回结构 = 上表 8 个字段。两处若给的值冲突，**取交集（更严的一侧胜出）**，不允许「登录说能编辑、能力说不能」这种中间态。
2. **服务端同样拒写**：`canEdit:false` 时前端只是不呈现入口，**Provider 的所有写方法必须自己再判一次并抛错**（参考 §5.4 的权限闸门写法）。前端置灰不是安全边界。
3. **只有 `canView` 可以不挂载**：`canView:false` 时允许不创建 Tiptap 实例（省一次大 JSON 解析）；其余 7 项**一律「挂载 + 置灰」**——因为隐藏会让人误以为功能不存在，而飞书口径是让人看见但知道没权限。

### 5.3.2 官方权限交叉核对（O1 · 2026-10-25）

飞书帮助中心的权限面比编辑器内部的 8 个 capability 更宽；复刻时保留两层：8 个字段控制编辑器 UI，下面的文档/宿主 ACL 控制顶栏命令是否出现。

| 官方权限维度 | 本地字段建议 | UI 影响 |
| --- | --- | --- |
| 是否允许分享到组织外 | `canShareOutsideOrg` | 分享面板中的外部分享/链接范围；上级密级或管理员策略更严格时只能收紧 |
| 谁可以查看、邀请、移除协作者 | `canViewCollaborators` / `canManageCollaborators` | 分享面板成员列表与协作者增删 |
| 谁可以复制内容 | `canCopy` | 正文复制、快捷键复制、图片复制；没有复制权时不能只隐藏导出按钮 |
| 谁可以创建副本 | `canDuplicate` | 顶栏「创建副本」显示/禁用 |
| 谁可以打印 | `canPrint` | 顶栏「打印」显示/禁用；网页/桌面端可用，移动端不提供 |
| 谁可以下载/导出 | `canDownload` / `canExport` | 「下载为」及导出任务；Word/PDF/图片等受同一安全策略约束 |
| 谁可以评论 | `canComment` + `commentMinRole: viewer|editor|manager` | 新建评论入口；已有评论仍可查看 |
| 访问者/点赞者头像可见性 | `canViewVisitorAvatars` | 访问者与点赞头像是否显示 |

**官方边界**：权限设置受父文件夹、知识库、密级和管理员默认值限制；子文档不能放宽父级限制。前端置灰不是安全边界，所有 provider 写操作必须再次服务端判权。

官方旁证：
- [设置云文档分享、复制、下载、评论等权限](https://www.feishu.cn/hc/zh-CN/articles/360049067527-%E8%AE%BE%E7%BD%AE%E4%BA%91%E6%96%87%E6%A1%A3%E5%88%86%E4%BA%AB-%E5%A4%8D%E5%88%B6-%E4%B8%8B%E8%BD%BD-%E8%AF%84%E8%AE%BA%E7%AD%89%E6%9D%83%E9%99%90)
- [Overview of Feishu Docs permissions](https://www.feishu.cn/hc/en-US/articles/360025093793-overview-of-feishu-docs-permissions)

**不在这 8 项内、需要单独处理的 3 处**

| 场景 | 为什么不在 8 项内 | 归属 |
| --- | --- | --- |
| 复制权限（目录右键不出现「复制」） | 是**条目级 ACL**，不是文档能力 | 目录树的条目 `acl.copyable` |
| 修订模式（建议模式）能否切换 | 依赖 `canEdit` **且**依赖当前角色是否 reviewer | `canEdit === true` 且 `role ∈ {owner, editor, reviewer}` |
| 评论「私有 / 仅自己可见」开关 | 是**线程级**属性，不是能力 | `Thread.private` 字段（见 §5.5） |

## 5.4 versioning Provider（不可变版本）

| 方法 | 入参 | 返回 | 语义 |
| --- | --- | --- | --- |
| `list(ctx?)` | `{ documentId }` | `Promise<Version[]>` | 列版本，新→旧 |
| `createSnapshot(record)` | `DocumentRecord & meta` | `Promise<Version>` | 建不可变快照 |
| `get(versionId, ctx?)` | `string` | `Promise<Version>` | 取单个版本全文 |
| `restore(versionId, ctx)` | `string, { documentId }` | `Promise<Version>` | **恢复 = 新建版本**，不覆盖原版本 |

### `Version` 字段【预期，按已有 `createVersion` 反推】

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `id` | `string` | 版本 ID（服务端生成，不可变） |
| `documentId` | `string` | 所属文档 |
| `revisionId`? | `string` | 基线修订号 |
| `title` | `string` | 该版本的标题快照 |
| `json` | `object` | 该版本的正文快照 |
| `createdAt` | `number` | 创建时间（ms） |
| `createdBy`? | `Actor` | 创建者 |
| `label`? | `string` | 用户自定义版本名（飞书「命名版本」） |
| `meta`? | `object` | 透传扩展 |

### 官方版本管理约束（O1）

- 保存命名版本：桌面端或网页版；查看/管理版本：桌面端、移动端、网页版均可。
- 已保存版本不可编辑、不可添加评论、不可单独收藏或移动到知识库。
- 删除版本进入「版本回收站」，只支持恢复 30 天内删除的版本；版本链接沿用源文档标题、缩略图和权限。
- 官方不提供命名版本之间的直接 diff；需要追溯细节使用「历史记录」时间线。

官方旁证：[在文档中使用版本管理功能](https://www.feishu.cn/hc/zh-CN/articles/263283633266)。

### 权限闸门（源码实测）

```
createVersion()  → 先 can('canCreateVersion')，否则 throw '当前用户没有创建版本的权限'
restoreVersion() → 先 can('canRestoreVersion')，否则 throw '当前用户没有恢复版本的权限'
两者在无 versioning Provider 时 throw '未配置 versioning Provider'
```

### 5.5.1 评论 CRUD 实机证据（2026-10-25）

- 桌面端唯一探针完成：创建线程 → 回复列表回读 → 在回复行 `reply-controls__more-btn` 打开 **152×134** 菜单（编辑 / 翻译为简体中文 / 删除 / 举报）。
- 点击「编辑」进入同一回复编辑器，按钮为「取消 / 确认」；确认后服务端 `POST /space/api/comment/reply/update/` 返回 200，刷新后正文为新值。
- 再次打开同菜单点击「删除」，无二次确认；服务端 `POST /space/api/comment/reply/delete/` 返回 200，刷新后该回复从开放线程列表消失。头部「解决」仍是独立线程状态操作，不能与行菜单删除混同。
- `comment/add` 创建响应中的稳定字段：`comment_id`、`reply_id`、`comment_uuid`、`obj_type`、`parent_token`、`extra.content_anchor_id`、`quote`、`create_timestamp`、`modify`、`delete_flag`；更新/删除请求沿用 `comment_id` + `reply_id`，实现必须保留幂等失败态。

### 5.5.1 顶栏辅助面板 Provider（E2 前台字段）

```ts
interface Page<T> { items: T[]; nextCursor?: string; hasMore?: boolean }

interface DocumentInfoOverview {
```

## 5.6 collaboration Provider（协同）

| 方法 | 入参 | 返回 |
| --- | --- | --- |
| `connect(options)` | `{ documentId, user, session }` | `Promise<ConnectionResult>` |
| `disconnect(options)` | `{ documentId, session }` | `Promise<void>` |

### 行为约束（源码实测）

- `mode !== 'collaborative'` 时 `connect()` **直接返回 `{ status: 'local' }`**，不调用 Provider。
- `disconnect()` 在**本地模式也是安全的空操作**（`if (!provider) return`）。
- 返回值作为 `connection` 事件广播：`this.emit('connection', result || { status: 'connected' })`。
- 断开后固定广播：`{ status: 'disconnected' }`。
- **`mode:'collaborative'` 且无 Provider → 构造函数直接 throw** `'collaborative 模式必须提供 collaboration Provider'`。

### `ConnectionResult` 字段【预期 · 口径已按飞书实测订正】

> 订正依据 `15 §9.11`（batch551~561）。飞书**不是 Yjs / hocuspocus**，正文同步是 **easysync（cs3）changeset over HTTP POST**，服务端做**单块 OT 合并**（不是 CAS）；因此原来的「协议标识 = yjs/hocuspocus」口径作废。

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `status` | `'connected' \| 'local' \| 'disconnected' \| 'error'` | 连接态 |
| `protocol`? | `'easysync-http' \| 'yjs' \| string` | 传输协议标识。飞书实测 = **`easysync-http`**（`POST /space/api/docx/blocks/user_change`，单块 cs3 变更集 OT）；`yjs` 仅作自研备选 |
| `granularity`? | `'block' \| 'text'` | **新增**。变更集作用域。飞书 = `'block'`（`change_map` 一 key 一块，块内字符级 OT） |
| `version`? | `number` | **新增**。提交时携带的**基准 rev**（不是 CAS 锁）；服务端可对落后 rev 做 rebase，**超前 rev 直接 `4000028`**；成功后由服务端下发 `version+1`，**客户端不得自增** |
| `reconnect`? | `{ maxRetries: number, backoffMs: number[] }` | **新增**。飞书实测策略：`maxRetries:4`，退避 `[12800, 13000, 13400, 14200]`，**冲突对用户静默** |
| `peers`? | `Actor[]` | 当前在线协作者（驱动飞书右上角头像堆叠 20×20 圆 + 12px `#646A73` 名字） |
| `error`? | `string` | 失败原因（**不弹窗、不 toast**，飞书无冲突 UI） |
| `lastCode`? | `number` | **新增**。服务端业务码。**业务失败也是 HTTP 200**，必须判 `code`：`0` 成功 / `4000002` 参数或块不存在 / `4000028` OT 或 rev 冲突（重试）/ `1` page 无权（降级只读）/ `403` CSRF（刷 token） |
| `lastDetail`? | `string` | **新增**。服务端 `data.detail` 原文，含 4 段管线 `transaction failed → cs3 process failed → failed to process before save → failed to do collaborate calculation`，排错直接透出 |

> **配套两条硬约束（实测踩过坑）**：① 鉴权头名是 **`X-CSRFToken`（大小写敏感）**，值取 cookie `_csrf_token`；小写变体一律 403 `csrf token error`。② `change_map` 的 key 必须用 DOM 的 **`data-record-id`**（`doxcn…` 长 ID），**不是 `data-block-id`**（那是短序号 `"3"`/`"6"`，填进去必报 `blockid` 校验失败）。

## 5.7 预期新增接口【预期 · 当前未实现】

> 以下为 1:1 飞书所必需、现有 Provider 未覆盖的接口。设计对齐飞书实机行为。

### `uploader.upload(file, ctx)`

```ts
upload(file: File, ctx: { documentId, onProgress?, signal?, taskId?, chunk? }): Promise<{ url, width?, height?, size, mime, name? }>
```

**为何需要 `width/height`**：飞书图片块在插入瞬间就以**真实宽高比**撑开占位（避免加载完成后跳动）。实测飞书图片块带 `data-width` / `data-height`。

**宿主三种传法（门面归一，0.12 起）**：

| 传法 | 形态 | 说明 |
| --- | --- | --- |
| 推荐 | `uploader: { upload, limits?, retry?, chunked?, chunkSize? }` | 四条失败路径按需打开 |
| 兼容 | `uploader: fn` / `uploadImage: fn` | 裸函数，等价于只有 `url` 返回 |

**四条失败路径（P2-02 已实现，`src/core/media/upload.js`）**：

| 路径 | 行为 | 宿主配合 |
| --- | --- | --- |
| 超限 | `limits.mime` / `limits.maxSize` 在**上传前**拦掉，错误码 `UPLOAD_MIME` / `UPLOAD_SIZE`；`limits` 默认 `null`（交给图片块自己的 `imageMaxSize`，避免两处口径打架） | 想统一口径才传 `limits` |
| 重试 | 只重试**安全失败**：`error.retryable === true` / `429` / `5xx` / 网络层错误（`TypeError`、`NetworkError`、`TimeoutError`）；业务 `4xx` 立即抛。默认 `{ attempts: 3, delay: 300, factor: 3 }` | 业务错误想重试就标 `retryable: true`；不想重试标 `retryable: false` |
| 取消 | 每个任务一个 `AbortSignal`（`ctx.signal` 原样透传，转给 `fetch`/`xhr` 即可），另有 `provider.cancel(taskId)` / `cancelAll()`；统一以 `UPLOAD_ABORTED` 结束 | 监听 `ctx.signal` 并 reject |
| 断点 | 声明 `chunked: true` 后按 `chunkSize`（默认 4 MB，下限 64 KB）切片，**逐片重试**：中途失败从失败那片续；同一文件（`name:size:lastModified`）在内存记账，手动重试也接着走，成功后清账 | 读 `ctx.chunk = { index, total, offset, size, uploadId }` 做分片落库 |

错误统一带 `code`（`UPLOAD_MIME` / `UPLOAD_SIZE` / `UPLOAD_ABORTED` / `UPLOAD_FAILED` / `UPLOAD_RESULT`），UI 按码出文案，不比对英文 message。返回缺 `url` 直接判 `UPLOAD_RESULT` 失败 —— **不留半截节点**。

## 5.12 块操作 API（BlockAPI）【预期 · 最高优先级缺口】

> **背景**：本文件 5.1–5.11 全是**文档级**（`getDocumentRecord`）或 **Provider 级**（`upload/version/comments`）接口，**没有任何一个方法按 `blockId` 操作单个块**。
>
> 后果：折叠、评论锚点、目录跳转、拖拽移动、块菜单的「上移/下移/复制/删除/转为」全部要靠宿主自己写 `editor.chain().findPos...`，**每个功能各写一遍 `posAtId`**，是 [15 §3.3](./15-闭环审计与端到端流程.md) 标的 S1 返工源头。
>
> **预计收益**：写 1 页接口 → 省 P1 的 18 处零散实现。

### 5.12.1 设计原则（三条硬约束）

| # | 约束 | 原因 |
| --- | --- | --- |
| 1 | **一切方法按 `blockId`，不按 `pos`** | `pos` 会在任何一次远端协同后失效；`blockId` 稳定 |
| 2 | **每个方法自己 `dispatch` 一次**，内部自动 `closeHistory()` | 保证「一次调用 = 一步撤销」（见 [07 §13.3](./07-交互与状态机.md)） |
| 3 | **写操作返回受影响的 `blockId`**，读操作返回**快照副本** | 调用方需要更新自己的锚点；快照不可被外部改 |

### 5.12.2 接口签名

```ts
/** 位置描述：三种锚点方式，按优先级 resolve */
type BlockAnchor =
  | { blockId: string; position: 'before' | 'after' | 'inside' }
  | { blockId: string; offset: number }            // 块内字符偏移处拆分
  | { index: number; parentId?: string };          // 父容器第 index 个子块

/** 块快照：只读副本，不含 Editor 内部引用 */
interface BlockSnapshot {
  blockId: string;
  type: string;                                    // 'paragraph' | 'heading' | ...
  attrs: Record<string, unknown>;                  // 含 level / language / bgColor / checked ...
  text: string;                                    // 纯文本（拼接所有叶子）
  depth: number;                                   // 相对文档根
  parentId: string | null;
  children: string[];                              // 直接子块 blockId
  index: number;                                   // 在父容器中的序号
  isEmpty: boolean;                                // 无文本且无子块
  docPos: { from: number; to: number };            // 当前 pos，**仅供调试**，不保证稳定
}

interface BlockAPI {
  // ── 读 ──────────────────────────────────────────
  get(blockId: string): BlockSnapshot | null;
  children(blockId: string): string[];              // 直接子块；叶子返回 []
  parent(blockId: string): string | null;
  index(blockId: string): number;                   // 父容器内序号；找不到返回 -1
  siblings(blockId: string): string[];
  /** 按条件查块（调试/批量操作） */
  query(pred: (s: BlockSnapshot) => boolean): BlockSnapshot[];
  /** 选区内全部块 id，按文档顺序 */
  selected(): string[];
  isContainer(blockId: string): boolean;            // callout/details/columns/listItem/table…

  // ── 写 ──────────────────────────────────────────
  /** 插入；payload 可为 JSON 节点、块快照或纯文本。返回新块 id 数组 */
  insert(payload: unknown, at: BlockAnchor): string[];
  /** 部分更新 attrs（不算 transform） */
  update(blockId: string, patch: Record<string, unknown>): void;
  /** 删除；keepChildren=true 时子块上提（容器专用） */
  remove(blockId: string, opts?: { keepChildren?: boolean }): void;
  /** 移动到新位置；跨容器自动处理层级 */
  move(blockId: string, to: BlockAnchor): void;
  /** 复制一份插到 after，返回新 id（原块下方） */
  duplicate(blockId: string, opts?: { deep?: boolean }): string;
  /** 类型转换；attrs 可选覆盖 */
  transform(blockId: string, toType: string, attrs?: Record<string, unknown>): void;

  // ── 批量 ────────────────────────────────────────
  insertMany(payloads: unknown[], at: BlockAnchor): string[];
  removeMany(blockIds: string[]): void;
  /** 一次 dispatch 包住 fn 内所有调用 → 整体一步可撤 */
  batch(fn: () => void): void;
}
```

### 5.12.3 方法契约明细

| 方法 | 返回值 | 幂等 | 一次 dispatch | 撤销粒度 | 关键语义 |
| --- | --- | --- | --- | --- | --- |
| `get` | `BlockSnapshot \| null` | ✅ | ❌（只读） | — | 找不到返 `null`，**不抛异常** |
| `children` | `string[]` | ✅ | ❌ | — | 叶子返 **`[]`**（不是 `null`） |
| `parent` | `string \| null` | ✅ | ❌ | — | 顶层块返 `null` |
| `index` | `number` | ✅ | ❌ | — | 找不到返 **`-1`** |
| `selected` | `string[]` | ✅ | ❌ | — | 折叠光标 → 返回光标所在块**1 个** |
| `insert` | `string[]` | ❌ | ✅ | **整次插入 = 一步** | 空 payload → 返 `[]`，不做事 |
| `update` | `void` | ✅ | ✅ | 一步 | 只改 attrs，**不动内容** |
| `remove` | `void` | ✅（已删则 no-op） | ✅ | **整棵子树 = 一步** | `keepChildren` 只对容器有意义 |
| `move` | `void` | ❌ | ✅ | **整次移动 = 一步** | 同位置移动 → no-op |
| `duplicate` | `string` | ❌ | ✅ | 一步 | **必重生成 blockId 及所有子孙 id** |
| `transform` | `void` | ✅ | ✅ | 一步 | 同 type 同 attrs → no-op |
| `batch` | `void` | ❌ | ✅ | **整个 batch = 一步** | `fn` 抛错则**整体回滚**（不部分提交） |

### 5.12.4 各方法的边界行为

**`insert`**

| 场景 | 行为 |
| --- | --- |
| `at.position = 'inside'` 但目标是叶子块 | **自动降级**为 `'after'` |
| `at = { index }` 越界 | `index < 0` → 插首位；`index > len` → 插末尾（不报错） |
| 插入多块到**标题**后 | 允许（不强制拆标题） |
| 插入 `listItem` 到非列表容器 | **自动包一层 `bulletList`** |
| 插入 `column` 到非 `columns` | **自动包一层 `columns`** |
| 插入到 `code_block` 内 | **拒绝**，返 `[]`（代码块是纯文本容器） |

**`remove` + `keepChildren`**

| 目标 | `keepChildren: false`（默认） | `keepChildren: true` |
| --- | --- | --- |
| `callout` | 整个高亮块（含子块）消失 | 子块**上提到 callout 原位置**，callout 壳消失 |
| `listItem` | 该条目及嵌套子树消失 | 嵌套子列表上提为同级列表 |
| `table` | 整表消失 | **非法** → 等同 `false`（表格无「上提单元格」语义） |
| 叶子块 | 删除 | 同 `false` |

**`move`**

| 场景 | 行为 |
| --- | --- |
| 移进自己的子孙 | **拒绝**（防环） |
| 移进 `code_block` / 叶子块 | 拒绝 |
| 跨文档 | 不支持（用 `duplicate` + 宿主自己搬） |
| 移入 `listItem` 内 | 自动成为该 item 的子块 |
| 移动后 blockId | **不变**（评论锚点保留）—— 与 `duplicate` 的关键区别 |

**`transform`**

| 从 → 到 | 处理 |
| --- | --- |
| `paragraph` → `heading` | 需 `attrs.level`，缺省 `1` |
| `paragraph` ↔ `bulletList` | 自动包 `listItem` |
| `listItem` → `paragraph` | **先出列表**（`lift`），再转段落 |
| `paragraph` → `code_block` | 文本保留，mark **全部丢弃** |
| 任意 → `table` | **不允许**（表格必须走 `insert`） |
| `heading` → `paragraph` | 保留文本，丢 `level` |

### 5.12.5 `posAtId` 的实现要求（内部）

```ts
/** 唯一允许的「id → pos」实现；全库只此一份 */
function posAtId(state: EditorState, blockId: string): number | null {
  let found: number | null = null;
  state.doc.descendants((node, pos) => {
    if (found !== null) return false;          // 已找到，停止遍历
    if (node.attrs?.blockId === blockId) { found = pos; return false; }
    return true;
  });
  return found;
}
```

| 约束 | 说明 |
| --- | --- |
| **禁止 `nodeAtSafe` 反查 id** | 方向反了；`posAtId` 必须从 root 遍历 |
| **禁止缓存 `blockId → pos`** | 任何一次远端 step 都会让缓存失效；性能问题用 `WeakMap<state, Map>` 按 **state 实例**缓存 |
| 复杂度 | O(n)，5000 块文档约 2–4ms；**批量操作要先取一次 map 再循环**（`batch` 内部做这件事） |

### 5.12.6 与既有 API 的关系

| 已有 | 与 BlockAPI 的关系 |
| --- | --- |
| `DocumentSession.dispatch(tr, meta)` | BlockAPI **内部走它**，保证事务元信息完整 |
| `getDocumentRecord()` | 文档级快照，**不替代** `BlockSnapshot` |
| `editor.chain()` | BlockAPI 是它的 **blockId 语义封装**；`editor` 仍可直接用（逃生舱） |
| `commands.focus()` 等 | 不受影响 |

> **落地顺序建议**（配合 [15 §7](./15-闭环审计与端到端流程.md) P0）：`get/children/parent/index`（纯读，半天） → `insert/remove`（一天） → `move/duplicate/transform`（一天） → `batch` + 把折叠/拖拽/块菜单 3 处旧实现迁过来（一天）。

## 5.13 文档操作 API（DocumentAPI）【契约定案 · 部分行为待实测】

> 来源：[15 §9.4](./15-闭环审计与端到端流程.md) 签下的契约。`BlockAPI` 管「块」，本篇管「文档本身」—— **`DocumentAPI` 是「增删改查」里那个「删」的唯一出口**，也是 `15 §9.3` 把 D1 定为 P0 的原因：在此之前文档级 CRUD 完全没闭环。

### 5.13.1 为什么必须独立于 BlockAPI

| 维度 | `BlockAPI` | `DocumentAPI` |
| --- | --- | --- |
| 作用域 | 单文档内的 block 树 | 文档列表 / 回收站 |
| 是否进撤销栈 | **进**（`docChanged` step） | **不进**（见 5.13.4 规则 4） |
| blockId | 保持 / 局部重生成 | `duplicate` 时**全量重生成** |
| 失败语义 | 命令被拒（no-op） | Promise reject（有明确错误码） |
| 权限 | `Capabilities`（8 项） | 文档级 ACL（owner / editor / viewer） |

### 5.13.2 接口签名

```ts
/** 文档元信息。列表页 / 面包屑 / 回收站共用同一个结构 */
interface DocMeta {
  docId: string;              // 文档唯一 id（≠ 任何 blockId）
  title: string;              // 空标题时 UI 显示「无标题」，但存储为 ""
  parentId: string | null;    // null = 根目录
  ownerId: string;
  createdAt: number;          // ms epoch
  updatedAt: number;          // ms epoch
  deletedAt: number | null;   // 非 null = 在回收站
  rev: number;                // 单调递增，用于 if-not-match 并发保护
  blockCount: number;         // 列表页「N 个块」展示用，允许延迟
  icon?: string;              // emoji 或 "icon:xxx"；默认无
}

interface DocumentAPI {
  create(opts?: { templateId?: string; title?: string; parentId?: string | null }): Promise<DocMeta>;
  rename(docId: string, title: string): Promise<void>;
  duplicate(docId: string, opts?: { title?: string; parentId?: string | null }): Promise<DocMeta>;
  remove(docId: string): Promise<void>;            // → 回收站，非物理删除
  restore(docId: string): Promise<DocMeta>;        // 回原父节点；父已删则回根目录

  /* 回收站只读查询（配合 remove / restore 才闭环） */
  listDeleted(opts?: { cursor?: string; limit?: number }): Promise<{ items: DocMeta[]; nextCursor?: string }>;
  purge(docId: string): Promise<void>;             // 物理删除，需二次确认，不可恢复
}
```

> **`purge` 是单独方法而非 `remove({ hard: true })`**：物理删除需要独立的二次确认弹窗与独立权限（仅 owner），合并成布尔参数会让误调变成不可逆。

### 5.13.3 `DocMeta` 字段含义

| 字段 | 类型 | 必填 | 含义与坑 |
| --- | --- | --- | --- |
| `docId` | `string` | ✅ | 文档 id。⚠️ **不要与 `blockId` 混用**；根块 `blockId` 实测是字符串 `"1"`（`02 §0.3.1`），与 `docId` 无关系 |
| `title` | `string` | ✅ | 空标题存 `""`，**不存「无标题」**；占位文案是渲染层的事 |
| `parentId` | `string \| null` | ✅ | `null` = 根目录。`restore` 时若该父已删 → 落根目录并 toast |
| `ownerId` | `string` | ✅ | 决定 `purge` / 分享 / 转移所有权权限 |
| `createdAt` / `updatedAt` | `number` | ✅ | ms epoch。`updatedAt` **只被内容变更刷新**，`rename` 也算一次变更 |
| `deletedAt` | `number \| null` | ✅ | `null` = 正常；非 null = 回收站。**回收站保留 30 天**（5.13.4 规则 2） |
| `rev` | `number` | ✅ | 乐观并发。`rename` / `duplicate` 可带 `ifRev` 校验，不匹配抛 `REV_CONFLICT` |
| `blockCount` | `number` | ✅ | 列表页展示用，**允许滞后**（服务端异步统计），不要拿它做业务判断 |
| `icon` | `string?` | ❌ | emoji 字符或 `icon:xxx`；无则不带该字段（不是 `null`） |

### 5.13.4 四条硬规则（不可退让）

| # | 规则 | 原因 / 不这么做会怎样 |
| --- | --- | --- |
| **1** | `duplicate` 必须给**每个块重新生成 blockId** | 否则副本与原文共享锚点 —— 评论、分享锚点、`?block=xxx` 深链**全部串号**。与 `07 §14.5` 第一红线同源。`blockId` 生成器要**新开一段随机前缀**，不能靠「原 id + 后缀」 |
| **2** | `remove` 是**软删除**，返回后仍可 `restore`，**保留 30 天** | 飞书口径。物理删除是 `purge`，独立权限 + 二次确认 |
| **3** | `restore` 的目标父节点已删 → **落到根目录**并提示「原位置已不存在」 | 否则恢复会变成**静默失败**（文档进了列表但父节点不存在，前端树渲染不出来） |
| **4** | 删除 / 恢复 / 彻底删除**三者都不进撤销栈** | 文档级操作不是 `docChanged` step。`07 §13.3` 已把「非文档 step 不进栈」定死；若进栈会导致 `Cmd+Z` 在回收站场景里语义混乱 |

### 5.13.5 `duplicate` 的完整副作用表

`duplicate` 是五个方法里唯一「有内容语义」的，必须逐项定死：

| 内容 | 是否复制 | 说明 |
| --- | --- | --- |
| 块树（正文） | ✅ 全量 | 深拷贝，**新 blockId 全量** |
| 块 `attrs` | ✅ 全量 | 含 `indent` / `fold` / `textAlign` / `level` |
| 行内 marks | ✅ 全量 | 含 `link`（外链保持，**内链把 docId 换成新副本的**） |
| 评论 / 批注线程 | ❌ **不带** | 评论锚在 blockId 上，blockId 已变；带过去会变成孤儿线程 |
| 历史版本 | ❌ 不带 | 副本从 `rev = 1` 起 |
| 分享链接 / 权限 | ❌ 不带 | 副本默认继承**父节点**权限，不继承原文的额外授权 |
| 文档图标 / 封面 | ✅ 带 | |
| 折叠状态（`folded`） | ✅ 带 | 属 `attrs`，视觉一致 |
| `deletedAt` | 强制 `null` | 不能复制回收站里的文档（调用前置校验） |

> 🔴 **内链改写是最容易漏的一条**：正文里的 `@文档` / 内部跳转 mark 存的是 `docId`。若原样复制，副本里所有内链会**指回原文**。`duplicate` 必须在同一事务里把 `link.targetDocId === sourceDocId` 的全部改成 `newDocId`。

### 5.13.6 错误码

| code | 触发 | 前端表现 |
| --- | --- | --- |
| `NOT_FOUND` | `docId` 不存在或无权访问 | 跳「文档不存在」整页错误（`04 §8.3` D6） |
| `FORBIDDEN` | 权限不足（viewer 调 `rename` / 非 owner 调 `purge`） | toast「无权限」，**不做乐观更新** |
| `REV_CONFLICT` | 传入 `ifRev` 与服务端不一致 | 提示「文档已被他人修改」，附「刷新」按钮 |
| `PARENT_MISSING` | `create` / `duplicate` 指定的 `parentId` 不存在 | toast + 落根目录（与 `restore` 规则 3 同口径） |
| `QUOTA_EXCEEDED` | 文档数 / 存储超限 | 阻塞式弹窗，不 toast |
| `TITLE_TOO_LONG` | `title` > 800 字符 | 输入框红线 + 阻止提交（**非静默截断**） |

### 5.13.7 状态机

```
        create
          │
          ▼
     ┌─────────┐   remove    ┌────────────┐  restore   ┌─────────┐
     │  normal │ ──────────▶ │  deleted   │ ─────────▶ │  normal │
     └─────────┘             └────────────┘            └─────────┘
          │                        │
          │ purge                  │ purge
          ▼                        ▼
     ┌──────────────────────────────────┐
     │            gone（不可逆）          │
     └──────────────────────────────────┘
```

| 迁移 | 前置 | 副作用 |
| --- | --- | --- |
| `normal → deleted` | 有 `canDelete` 权限 | `deletedAt = now`；从所有列表移除；**不清正文** |
| `deleted → normal` | 未超 30 天 | `deletedAt = null`；父已删则 `parentId = null` |
| `deleted → gone` | 仅 owner，二次确认 | 正文与资源**异步**物理删除（先标记，后台清理） |
| `deleted → gone`（超期） | 系统任务 | 同上，无 user 触发 |

> **`gone` 是终态，没有 `recover`**。前端在 `purge` 的确认弹窗里必须写明「此操作不可恢复，文档将被永久删除」。

### 5.13.8 与既有 API 的关系

| 已有 | 关系 |
| --- | --- |
| `persistence Provider`（5.2） | `DocumentAPI` 的**存储后端**。草稿/快照是「单文档内」的持久化，`DocumentAPI` 是「文档集合」的操作，两者正交 |

### 5.13.9 模板库接口（`templates`）【batch414–422 实机定判 · 规格见 02 §28】

> 🔴 **实机定判（batch421）**：飞书模板库的「使用」**就是一次服务端文档复制**，不是「取模板 JSON 再逐块 insert」。

> 证据链：点「使用」→ `pages 1→2`（**新开页签**）→ `GET /wiki/{nodeId}`（`title=Docs`）→ 页内横幅文案 **「正在创建副本，请稍候」**；同期请求按序 `POST /space/api/suite/permission/document/actions/state/`（权限探测）→ **`POST /space/api/wiki/v2/tree/create_node/`**（建节点 = 复制落点）→ `POST /space/api/v1/bitable/obj_meta_list`（副本内若有电子表格块，拉其元信息）。

## 5.14 表格操作 API（TableAPI）【预期 · 契约级 + 已实测几何】

> **为什么必须独立**：表格是**唯一带二维网格语义**的块。`BlockAPI` 的 `insert/remove/move` 是**线性**的，表达不了「把 A1:B2 四格合成一格」「在第 2 列左侧插一列」「把第 3 行上移」这类操作 —— 强行用线性 API 拼，每次都要调用方自己算 `rowspan/colspan` 的连带影响，且**必然算错**（合并后行内 `td` 数 ≠ 列数）。
>
> 实测依据：`02 §10 ⑦-1~⑦-11`（表格全规格）、`03 §3.4 ④-2`（斜杠菜单）、`batch203/205/208/209` 日志。

### 5.14.1 数据模型（三层，别混）

```
TableNode (attrs)
  ├─ GridModel   ← 逻辑网格：rows × cols，每格 (row,col) 唯一，合并格占多格
  ├─ CellNode[]  ← 物理节点：ProseMirror 里真实存在的 tableCell（合并格只有 1 个）
  └─ RenderModel ← 渲染层：DOM 的 <table>/<tr>/<td>，飞书额外有 sticky 克隆表
```

| 层 | 谁说了算 | 关键不变量 |
| --- | --- | --- |
| **GridModel** | 逻辑真值，`getMatrix()` 返回 | `Σ colspan(row) === cols` **恒成立**；每个 `(r,c)` **恰好**属于 1 个 cell |
| **CellNode[]** | 落库真值 | 合并格**物理只有 1 个** `tableCell` + `colspan/rowspan` attrs；**不允许**照抄飞书的 `display:none` 占位 td |
| **RenderModel** | 派生，可随时重建 | 飞书用「隐藏占位 td」+「sticky 克隆表」两套技巧，**V1 都不照抄**（见 `02 §10 ⑦-11`、`⑦-7 ⑥`） |

```ts
/** 逻辑坐标（0-based，左上为原点） */
interface CellRef { row: number; col: number }

/** 矩形选区（含端点）；单格 = from===to */
interface CellRange { from: CellRef; to: CellRef }

/** 逻辑网格：合并格在它覆盖的每个坐标上都出现（同一 cellId） */
interface TableMatrix {
  rows: number;
  cols: number;
  /** cells[r][c] = cellId；合并格覆盖的多个坐标共享同一 id */
  cells: string[][];
  /** cellId → 物理格快照 */
  byId: Record<string, CellSnapshot>;
}

interface CellSnapshot {
  cellId: string;
  /** 锚点坐标 = 合并块左上角 */
  row: number;
  col: number;
  rowspan: number;                 // ≥ 1
  colspan: number;                 // ≥ 1
  text: string;                    // 纯文本
  /** 合并时被吞掉的格文本（仅当 unmerge 需要还原时用；默认不落库） */
  swallowed?: string[];
  attrs: CellAttrs;
}

/** 单元格 attrs —— 字段含义与取值见 5.14.2 */
interface CellAttrs {
  backgroundColor: string | null;   // null = 透明；实测色板 16 色，见 02 ⑦-8
  verticalAlign: 'top' | 'middle' | 'bottom';
  textAlign: 'left' | 'center' | 'right' | null;  // null = 继承列/默认
  borderColor?: string | null;
}
```

### 5.14.2 字段含义（逐字段，含实测值）

| 字段 | 类型 | 默认 | 取值 / 实测 | 含义与坑 |
| --- | --- | --- | --- | --- |
| `rows` / `cols` | `number` | 插入时 `3 × 3` | 实测新插表 `3 列 × col width="100"`、表宽 300 | **`cols` 是逻辑列数**，不是 `<colgroup>` 的 `<col>` 数（飞书克隆表 `nCol: 0`） |
| `colspan` | `number` | `1` | 实测可达 `3`（整行合并） | **合并格宽 = Σ 被覆盖列的宽**；`colspan` 之和会 **>** `cols`（因为隐藏占位 td 仍在 DOM） |
| `rowspan` | `number` | `1` | 竖向合并后 `= 选区行数` | 与 `colspan` 可叠加（`2×2` 合并 → `cs=2 rs=2`） |
| `colwidth` | `number[]` | `[100,100,100]` | 拖拽后如 `[100,100,237]`；均分后 `[146,146,146]` | **每列独立**，单位 px；**总宽可以不等于块宽**（均分除不尽 → 438 > 437） |
| `hasHeaderRow` | `boolean` | `false` | 实测开启后：**首行搬进独立 sticky 克隆表**，块内 `table` 数 `1→2` | 🔴 **不是只加底色**。V1 用 `tr { position: sticky; top: 26px }` 等价实现，**不复制双表** |
| `hasHeaderColumn` | `boolean` | `false` | 实测开启后：**只加底色 + `header-column` class，不克隆** | 与 `hasHeaderRow` **可叠加**（四态矩阵见 `02 §10 ⑦-7`） |
| `headerBgColor` | `string` | `#F2F3F5` | 实测 `rgb(242,243,245)` | 标题行/列底色，**两态同色** |
| `backgroundColor` | `string \| null` | `null` | 16 色色板（`02 §10 ⑦-8`） | 单元格级；`null` = `rgba(0,0,0,0)` |
| `verticalAlign` | `enum` | `'top'` | 三值 | 只影响 `td` 的 `vertical-align`，不影响行高 |
| `textAlign` | `enum \| null` | `null` | `null` = 不写 `style` | **不是 `'left'`** —— 写 `null` 才能让「清除格式」真的清干净 |
| `cellId` | `string` | 自动 | 稳定不变 | 评论锚点、协同定位都挂它；**`duplicate` 表格时必须全部重生成**（同 `05 §5.13.4` 规则 1） |

### 5.14.3 接口签名

```ts
interface TableAPI {
  // ── 读 ────────────────────────────────────────────────────────────
  /** 逻辑网格快照（合并格在每个覆盖坐标都出现）。非表格块 → null */
  getMatrix(blockId: string): TableMatrix | null;
  /** 某格快照；坐标越界 → null */
  getCell(blockId: string, at: CellRef): CellSnapshot | null;
  /** 物理格数量（≠ rows × cols，合并后更少） */
  cellCount(blockId: string): number;
  /** 当前选区是否为单元格矩形选区 */
  selection(): { blockId: string; range: CellRange } | null;

  // ── 结构：行列 ────────────────────────────────────────────────────
  insertRow(blockId: string, at: number, opts?: { count?: number; side?: 'above' | 'below' }): void;
  insertColumn(blockId: string, at: number, opts?: { count?: number; side?: 'left' | 'right' }): void;
  deleteRow(blockId: string, at: number, opts?: { count?: number }): void;
  deleteColumn(blockId: string, at: number, opts?: { count?: number }): void;
  moveRow(blockId: string, from: number, to: number): void;
  moveColumn(blockId: string, from: number, to: number): void;
  /** 表尾追加一行（等价 insertRow(rows)）；返回新行首格 cellId */
  appendRow(blockId: string): string;

  // ── 结构：合并 / 拆分 ─────────────────────────────────────────────
  /** 合并矩形选区 → 1 个 cell；内容按「行优先、单空格」拼接（实测） */
  mergeCells(blockId: string, range: CellRange): string;
  /** 拆分指定格；无合并 → no-op。返回被还原的 cellId 数组 */
  unmergeCells(blockId: string, at: CellRef): string[];
  /** 🔴 toggle 语义：已合并则拆、未合并则合并（对齐飞书 MergeCell 按钮） */
  toggleMerge(blockId: string, range: CellRange): { action: 'merged' | 'unmerged'; cells: string[] };

  // ── 外观 ──────────────────────────────────────────────────────────
  setHeaderRow(blockId: string, enabled: boolean): void;
  setHeaderColumn(blockId: string, enabled: boolean): void;
  /** 均分列宽：每列 = Math.ceil(当前表宽 / cols)；总宽不守恒（实测 437→438） */
  distributeColumns(blockId: string): number[];
  setCellBackground(blockId: string, range: CellRange, color: string | null): void;
  setCellVerticalAlign(blockId: string, range: CellRange, align: 'top' | 'middle' | 'bottom'): void;

  // ── 列宽 ──────────────────────────────────────────────────────────
  /** 设置单列宽（px）；内部按 clamp(min=40) 修正 */
  setColumnWidth(blockId: string, col: number, width: number): void;
  getColumnWidths(blockId: string): number[];

  // ── 批量 ──────────────────────────────────────────────────────────
  /** 一次 dispatch 包住所有调用 → 整体一步可撤 */
  batch(fn: () => void): void;
}
```

### 5.14.4 方法契约明细

| 方法 | 返回值 | 幂等 | 一次 dispatch | 撤销粒度 | 关键语义 |
| --- | --- | --- | --- | --- | --- |
| `getMatrix` | `TableMatrix \| null` | ✅ | ❌ | — | **深拷贝**；调用方改返回值不影响文档 |
| `getCell` | `CellSnapshot \| null` | ✅ | ❌ | — | 越界返 `null`，**不抛** |
| `selection` | `{blockId,range} \| null` | ✅ | ❌ | — | 光标单格 → `from===to`；非表格 → `null` |
| `insertRow` | `void` | ❌ | ✅ | 一步 | `at` 越界 → clamp 到 `[0, rows]` |
| `insertColumn` | `void` | ❌ | ✅ | 一步 | 新列宽 = **当前表宽 / (cols+1)** 向下取整，其余列**不重算** |
| `deleteRow` | `void` | ✅（删空则 no-op） | ✅ | 一步 | **删到 0 行 → 连表块一起删**（飞书同此行为） |
| `deleteColumn` | `void` | ✅ | ✅ | 一步 | 删到 0 列 → 连表块一起删 |
| `moveRow` / `moveColumn` | `void` | ✅（`from===to`） | ✅ | 一步 | 目标索引按**移除后**的数组计 |
| `mergeCells` | `string`（新 cellId） | ❌ | ✅ | 一步 | 内容 **`行优先 + 单空格`** 拼接；空格不重复（`"A B C D"` 非 `"A B  C D"`）；空串不产生空格（竖向 `"" + "C"` → `"C"`） |
| `unmergeCells` | `string[]` | ✅（无合并则 `[]`） | ✅ | 一步 | **内容有损**：整体留在左上格，其余格**回空**（实测）；🔴 **必须补插缺失的 `tableCell`**（`2×2` 拆出 4 格，其中 3 格空） |
| `toggleMerge` | `{action, cells}` | ❌ | ✅ | 一步 | 对齐飞书 `MergeCell`：**文案不变、行为是 toggle**（实测）。🔴 **守卫判 `range` 是否存在**，不判光标位置 —— 飞书合并格单击无浮条，`Shift+Click` 同格才有（batch221 S2） |
| `setHeaderRow` | `void` | ✅ | ✅ | 一步 | 同值 → no-op；**不改文案、不改按钮外观** |
| `setHeaderColumn` | `void` | ✅ | ✅ | 一步 | 同上 |
| `distributeColumns` | `number[]` | ✅ | ✅ | 一步 | `每列 = Math.ceil(表宽 / cols)`，**总宽不守恒** |
| `setCellBackground` | `void` | ✅ | ✅ | 一步 | `null` = 清空 |
| `setColumnWidth` | `void` | ✅ | ✅ | 一步 | 单列宽 < 40 → clamp 到 40 |

### 5.14.5 硬规则（不可退让）

| # | 规则 | 原因 |
| --- | --- | --- |
| **1** | **落库只存物理格**，`colspan/rowspan` 是 attrs，**不存隐藏占位 td** | 飞书的 `display:none` 占位是渲染技巧；存进 JSON 会导致 `Σ colspan ≠ cols`、序列化后再读就崩 |
| **2** | **每次结构变更后校验网格不变量**：`Σ colspan(row) === cols` 且每坐标唯一归属 | 违反即 `throw new TableGridError`，**不要静默修正** |
| **3** | **合并必须按「行优先」遍历选区**，空格拼接，空文本不产生多余空格 | 实测口径；否则内容顺序与飞书不一致 |
| **4** | **`unmergeCells` 声明为「有损」**，UI 必须在拆分前提示「合并的文本将留在左上角单元格」 | 实测飞书即如此；不提示会被当 bug |
| **5** | **`hasHeaderRow` 不复制双表**，用 `tr { position: sticky }` + `border-collapse: separate` | 双表会让 `colgroup` 丢失、`querySelector('table')` 拿到错表（我们自己就踩过两次，见 `02 §10 ⑦-7 ⑦`） |
| **6** | **`distributeColumns` 的总宽增量是允许的**，不要为「守恒」而改某列 | 实测 `437 → 146×3 = 438`；强行守恒会和飞书差 1px |

### 5.14.6 错误码

| code | 触发 | 前端处理 |
| --- | --- | --- |

## 5.15 导出任务 API（ExportAPI）【契约级 · 飞书真实报文已实测 · batch465–467】

> **一句话**：导出**不是**一次同步下载，而是「**提交任务 → 轮询状态 → 完成取文件**」三段式。飞书的真实报文已全量抓到，本节的字段名与语义**直接对齐飞书**，复刻时不要再自创命名。

### 5.15.1 为什么必须独立成组

| 维度 | 说明 |
| --- | --- |
| 产物不在编辑态 | 导出物是**文件流**，不是文档模型；`DocumentAPI`（5.13）拿不到它 |
| 耗时不可控 | 实测同一文档 428KB PDF 需 10~60s，服务端 `job_timeout` 给 **600s** |
| 可能是压缩包 | Markdown「所有内容」产物是 **`.zip`**（含图片附件），不是 `.md` |
| 有独立状态机 | `queue → running → done / failed`，与文档保存状态机无关 |

### 5.15.2 接口签名

```ts
export interface ExportAPI {
  /** 提交导出任务，立即返回 ticket（不阻塞） */
  submit(opts: ExportOptions): Promise<{ ticket: string; jobTimeout: number }>;

  /** 查询任务状态（轮询用，幂等、无副作用） */
  poll(ticket: string): Promise<ExportResult>;

  /** 完成后取文件流（由宿主决定落盘还是给 URL） */
  fetch(ticket: string): Promise<{ stream: ReadableStream; filename: string; size: number; mime: string }>;

  /** 取消进行中的任务【预期 · 飞书侧未见入口】 */
  cancel?(ticket: string): Promise<void>;
}

export interface ExportOptions {
  format: 'pdf' | 'docx' | 'md';
  /** 是否带评论。飞书字段名即为 needComment（对应 need_comment） */
  needComment?: boolean;     // 默认 false
  /** 是否把图片/附件一起打包（仅 md 有效，产物变 zip） */
  includeFile?: boolean;     // 默认 false
}

export interface ExportResult {
  status: 'running' | 'done' | 'failed';
  errorMsg: string;
  fileToken: string;
  format: string;            // 实际产物扩展名：pdf / docx / md / zip
  fileName: string;
  fileSize: number;
  /** 仅 docx 档返回 */
  extra?: { charCount?: number; isComplete?: boolean };
}
```

### 5.15.3 字段含义（逐字段，含飞书实测值）

**提交请求 `POST /space/api/export/create/`**

| 字段 | 飞书实测值 | 我方字段 | 含义 |
| --- | --- | --- | --- |
| `token` | `KI9edbwYPoeTcBxsIlDckbCbnIf` | — （宿主上下文） | 源文档 token |
| `type` | `"docx"` | — | **源**文档类型，三档**恒为 `docx`**，不随导出格式变 |
| `file_extension` | `pdf` / `docx` / `md` | `format` | **目标**产物格式 |
| `event_source` | `"6"` | — | 埋点：入口 = 顶栏「更多」 |
| `need_comment` | `true` / `false` | `needComment` | 带不带评论。**PDF/Word 默认 `false`**（弹窗默认选中「仅正文」） |
| `passback` | `"{\"include_file\":true}"` | `includeFile` | **字符串化 JSON**，仅 Markdown「所有内容」出现 ⇒ 产物由 `.md` 变 `.zip` |

**提交响应**

`{"code":0,"msg":"success","data":{"ticket":"7700276367179893751","job_timeout":600}}`

| 字段 | 含义 |
| --- | --- |
| `ticket` | 任务 ID（19 位雪花），**后续轮询与取文件的唯一凭据** |
| `job_timeout` | 任务超时秒数，实测 **600** |

**轮询 `GET /space/api/export/result/{ticket}`（无请求体）**

| `job_status` | 语义 | 同批其它字段 |
| --- | --- | --- |
| **2** | **处理中** | `file_token:""`、`type:""`、`file_extension:""`、`file_name:""`、`file_size:0`、`job_error_msg:""` |
| **0** | **完成** | `job_error_msg:"success"`、`type:"docx"`、`file_extension:"pdf"`、`file_name:"/code"`、`file_size:428145`、`file_token:"GOcIbnD9dodomZxhe8xcHjNKn7e"`、`extra._pod_name` |
| 其它 | 失败【推断】 | 未采（需构造超限文档） |

> 🔴 **`job_status` 是个坑**：`0` 是**成功**、`2` 是**处理中** —— 不是常见的 `0`=未开始 / `1`=进行中 / `2`=完成。别按直觉写。

### 5.15.4 状态机

```
submit()                       poll 返回 2             poll 返回 0
   │                              │                       │
   ├── ticket ──→ [running] ──────┴──────────────────────→ [done] ──→ fetch() 落盘
   │                  │
   │                  └── poll 返回其它 / errorMsg 非空 ──→ [failed]
   │                                                          │
   └── code≠0 ──→ 立即 [failed]，不产生 ticket                 └── 可重试（重新 submit）
```

- 轮询节奏：飞书客户端最早一次在**提交后约 3.5s**，之后间隔未精确测；建议 **3s 起、指数退避到 15s 上限**，总时长不超过 `job_timeout - 5`。
- 完成后**必须**自动落盘（飞书就是直接触发浏览器下载），不能只提示「已完成」。

### 5.15.5 产物命名规则【实测】

`file_name` 取自**文档标题**，本例标题为 `/code`；下载时把 `/` 换成 `_` ⇒ 实测落盘名 `_code.pdf` / `_code.md` / `_code.docx` / `_code.zip`。

> 复刻建议：`fileName` 清洗规则 `[/\\:*?"<>|]` → `_`，空标题回退「未命名文档」。

### 5.15.6 错误码【预期 · 飞书侧未采到失败态】

| code | 场景 | UI |
| --- | --- | --- |
| `0` | 提交成功 / 查询成功 | — |
| `40301` | 无导出权限 | 「更多」菜单三项**置灰**（见 `05 §5.3.1` `canExport`） |
| `40302` | 文档被锁定 / 无阅读权限 | toast「无权限导出该文档」 |
| `40400` | ticket 过期或不存在 | 静默重试一次，再失败提示「导出任务已失效」 |
| `42900` | 并发导出超限 | toast「导出任务过多，请稍后再试」 |
| `50000` | 服务端失败 | toast「导出失败」+ 重试按钮 |

### 5.15.7 与既有 API 的关系

| 已有 | 关系 |
| --- | --- |
| `authorization`（5.3） | `Capabilities.canExport === false` 时三个入口**全部置灰**，不发请求 |
| `DocumentAPI`（5.13） | 导出**只读**，不改文档；导出期间的编辑**不一定**进产物（飞书未承诺快照一致性，`job_status` 完成才定稿） |

## 5.16 全量功能模块契约索引（官方 API × 实机模块 × 本地 CRUD）

### 5.16.1 接入规则

1. 新模块先注册 `moduleId`、`kind`、`tier`、`sourceRefs`、`localRefs`，再实现 API；没有注册项的 UI 入口不允许进入开发。

5. 未知块、`isv`、`iframe` 保存时必须透传 `blockType`、`recordId`、原始 `attrs` 和 `ssrData`，删除前不做降级转换。

### 5.18.3 权限 bit 与 UI capability 的转换

REA 静态代码给出网页权限 bit 的确定映射：`readable=1`、`commentable=2`、`editable=4`、`shareable=8`、`perceivable=4096`。其中 `viewable = bit & 1`，`perceivable = bit & 4096`，不能把 `editable` 当成包含评论或分享的复合角色。

```ts
interface FeishuPermissionBits {
  readable: 1;
  commentable: 2;
  editable: 4;
  shareable: 8;
  perceivable: 4096;
}
function decodePermissionBits(bits: number) {
  return {
    canView: Boolean(bits & 1),
    canComment: Boolean(bits & 2),
    canEdit: Boolean(bits & 4),
    canManagePermission: Boolean(bits & 8),
    canPerceive: Boolean(bits & 4096),
  };
}
```

`canPerceive` 用于头像/协作者存在性等感知信息，不能自动放宽正文阅读；转换到本地 `Capabilities` 时缺少的能力仍由 `PermissionState`（`canCopy`、`canDuplicate`、`canPrint`、`canDownload` 等）提供。服务端写接口必须再次按 bit 和父级策略判权。

### 5.18.4 资源复制与模板/按钮副本动作

前端的 `DocumentResourceCopyAPI.copyOut` 使用 `POST /api/docx/resources/copy_out`，请求体为 `{ tokens: string[] }`。静态实现把 token 分成**每批最多 50 个**，并发上限为 **2**；单批错误被客户端捕获，不能据此推断整批成功。

```ts
interface DocumentResourceCopyAPI {
  copyOut(input: { documentId: string; tokens: string[]; requestId?: string }):
    Promise<{ copied: Array<{ sourceToken: string; targetToken: string }>; failed: Array<{ sourceToken: string; code: string; message: string }> }>;
}
```

服务端必须返回逐 token 结果、`requestId` 和可重试错误。模板的“使用”和按钮块“创建副本”仍走 `DocumentAPI.duplicate` 的文档复制语义：复制正文/密级，默认不复制评论、历史、分享和权限；目标位置权限不足时整个副本事务失败，不产生半个文档。资源 copy-out 是副本内部的资源迁移步骤，不是块遍历替代品。

## 5.32 独立产品 Provider 适配层契约（架构定案 · 2026-10-26）

Jira、OKR、多维表格、问卷和 AI 是独立产品。文档编辑器只负责嵌入块、引用、状态展示、权限申请入口和同步回读；产品原生页面、资源生命周期、产品角色和产品数据由对应 Provider 负责。Provider 不得把第三方页面实现复制进 `lark-doc` 主包，也不得把 HTTP 200 或 iframe 加载成功当作业务成功。

### 5.32.1 公共类型和注册表

```ts
type ProviderName = 'jira' | 'okr' | 'bitable' | 'survey' | 'ai'
type ResourceKind = 'project' | 'issue' | 'objective' | 'key_result' | 'base' | 'table' | 'view' | 'record' | 'survey' | 'ai_task'
type SyncState = 'idle' | 'syncing' | 'synced' | 'stale' | 'conflict' | 'failed'
type PermissionState = 'unknown' | 'granted' | 'pending' | 'denied' | 'expired' | 'revoked'

interface ProviderContext {
  tenantId: string
  actorId: string
  documentId?: string
  blockId?: string
  locale?: string
  requestId: string
  identityMode?: 'user' | 'app' | 'anonymous'

}

  provider: ProviderName

  tenantEnabled: boolean

  actions: string[]

  canSubscribe: boolean
  canWebhook: boolean

}

  provider: ProviderName
  code: string | number
  message: string
  retryable: boolean
  status?: number

}

  syncState: SyncState

  error?: ProviderError
}

  get(ctx: ProviderContext, input: { resourceKind: ResourceKind; resourceId: string }): Promise<EmbeddedResource>
  create(ctx: ProviderContext, input: Record<string, unknown>): Promise<EmbeddedResource>
  update(ctx: ProviderContext, input: Record<string, unknown>): Promise<EmbeddedResource>
  delete(ctx: ProviderContext, input: { resourceKind: ResourceKind; resourceId: string }): Promise<{ deleted: boolean }>

  resourceKind: ResourceKind
  resourceId: string
```

### 5.32.8 统一错误、重试和审计

| 错误类别 | 统一状态 | 客户端行为 | 是否自动重试 |
| --- | --- | --- | --- |
| 未授权/过期 | `denied` / `expired` | 显示重新授权或申请权限 | 否 |
| 租户未开通/额度不足 | `tenantDisabled` / `quotaExceeded` | 显示产品开通或升级入口 | 否 |
| 资源不存在/已删除 | `notFound` | 保留块与资源 ID，允许解绑或重新绑定 | 否 |
| 网络、429、5xx | `failed` | 保留 requestId，指数退避重试 | 是，最多 3 次 |
| 版本冲突 | `conflict` | 重新拉取、展示差异、禁止覆盖写回 | 否，需用户决策 |
| 部分成功 | `partial` | 按资源/任务逐项展示，允许只重试失败项 | 仅失败项 |
| 第三方业务错误 | `providerError` | 展示 provider 文案与错误码 | 按 `retryable` |

每次 provider 命令都写入 `requestId/idempotencyKey/actorId/tenantId/provider/resourceId/action/resultCode/permissionState/providerVersion`；文档审计只记录嵌入块和宿主动作，第三方资源的完整审计由第三方产品保留。
