# lark-doc 统一接入改造计划

> 目标：完成 7 个阶段结算时约定的统一接入方案，让 Vue2、Vue3 等构建型项目在业务层使用同一套 `LarkDoc` 命令式 API，仅在构建产物层区分环境。
>
> 当前状态：统一接入改造已完成代码实现、构建产物补齐和定向验收；本 worktree 仍未提交、未推送、未发布。

## 1.1 插入弹窗交互统一约定

加号入口、空段落左侧「＋」入口、斜杠 `/` 入口和工具栏图表入口统一复用现有原生命令菜单与浮层关闭机制，不在各入口另造一套弹窗交互：

- 工具栏「插入」和空段落「＋」都打开同一份 `createCommandMenu()`，保留搜索、键盘导航、子菜单和模板/表格/分栏选择器。
- 斜杠菜单继续由编辑器状态驱动；选择命令后删除 `/query`，Esc 使用 dismissed 语义，避免关闭后立即重开。
- 加号/图表菜单采用飞书式 hover + click：移入触发器打开，移入弹层取消延迟关闭，移出后约 150ms 关闭；点击可切换，键盘仍支持 Enter/Escape。
- 图表类型下拉继续复用 `diagramTypes` 和 `insertDiagramType(typeId)`，不复制 Mermaid 插入事务；菜单会根据真实高度在上下方向间自动翻转并限制在视口内。
- 弹层关闭继续走 `overlayDismissMixin` 的外部点击、Esc 和互斥关闭链；所有入口保留 `aria-haspopup` / `aria-expanded` 语义。

后续新增插入类型时，应优先加入命令表或 `diagramTypes`，再复用现有 renderer 和 handler，不要在 Vue demo 或宿主层单独实现弹窗。

## 1. 最终目标

Vue2、Vue3、Vite、webpack4、webpack5、React 等环境统一使用：

```js
import { LarkDoc } from 'lark-doc'

const doc = new LarkDoc({
  element: host,
  title: '测试文档',
  content: '<p>正文内容</p>',
  contentFormat: 'html',
  readonly: false,
  storage: 'none',
  onReady(payload) {},
  onChange(payload) {},
  onError(error) {},
})
```

统一以下内容：

- 包名和安装方式
- `LarkDoc` 引入方式
- `new LarkDoc(options)` 初始化方式
- 配置项和事件
- 实例方法
- 模式切换行为
- 销毁方式
- 内网 npm/tgz 交付方式

只在构建层区分：

| 环境 | 主要消费产物 | 业务层 API |
|---|---|---|
| Vue2 + webpack4 | CJS | `import { LarkDoc } from 'lark-doc'` |
| Vue2 + webpack5 | ESM/CJS | `import { LarkDoc } from 'lark-doc'` |
| Vue3 + Vite | ESM | `import { LarkDoc } from 'lark-doc'` |
| React/Vite | ESM | `import { LarkDoc } from 'lark-doc'` |
| Node/测试环境 | CJS | `require('lark-doc')` |
| 原生 HTML/CDN | UMD/Web Component | `lark-doc/element` 或 UMD |

`lark-doc/element` 保留为原生 HTML、CDN、静态页面和不方便直接挂载命令式实例的兼容入口；不再作为 Vue3 的默认接入方式。

## 3. 分阶段执行计划

### 阶段一：冻结统一 API 契约

确认并固定公共门面支持的配置、事件和方法。

初始化配置至少包括：

```js
{
  element,
  title,
  content,
  contentFormat,
  readonly,
  theme,
  storage,
  toolbarKeys,
  features,
  uploader,
  persistence,
  onReady,
  onChange,
  onSave,
  onError,
}
```

公共实例方法至少确认：

```js
getEditor()
getHTML()
getJSON()
getText()
getTitle()
setTitle()
setContent()
setReadonly()
isReadonly()
setMode()
focus()
save()
undo()
redo()
destroy()
```

检查方法名、参数、返回值和事件 payload 是否在 Vue2、Vue3 中一致；发现不一致时优先修公共门面，不在 Vue3 demo 中写特殊适配逻辑。

### 阶段二：核对 `LarkDoc` 是否真正框架无关

重点检查：

```text
src/index.js
src/LarkDoc.js（如存在）
src/mount/
src/mount/domRenderer.js
src/ui/workspaceShell.js
src/legacy-vue/
src/adapters/vue3/
src/web-component/
```

验收要求：

1. `new LarkDoc()` 不依赖 Vue2 运行时。
2. Vue3 使用命令式入口时不加载 Vue2 SFC。
3. Vue2、Vue3 共用原生 DOM Renderer。
4. `destroy()` 能清理 DOM、事件、编辑器和定时器。
5. `setMode()` 在各环境行为一致。
6. 模式切换 Message 由公共 DOM/Renderer 逻辑负责，而不是只在某个 Vue 适配器中实现。

### 阶段三：补齐正式分发产物和 `exports`

核对 `package.json` 的 `main`、`module`、`exports` 与 `dist/` 实际文件是否一一对应。至少确认以下类型按项目现有命名规则生成并存在：

```text
dist/lark-doc.common.js
dist/lark-doc.esm.js
dist/lark-doc.css
dist/lark-doc-legacy.*
dist/lark-doc-vue3.*
dist/lark-doc-element.umd.min.js
dist/plugin.*
```

要求：

- `exports` 不能指向不存在的文件。
- webpack4 能够通过 CJS 入口加载。
- Vite/Vue3 能够通过 ESM 入口加载。
- CSS 产物真实存在且可显式引入。
- Element 入口及其异步 chunk、字体等静态资源可在内网同目录加载。
- 不要凭猜测新增未被现有构建系统支持的产物名称；先以 `package.json`、构建脚本和现有清单为准。

### 阶段四：将 Vue3 demo 改回统一命令式入口

把当前临时的：

```js
import 'lark-doc/element'
```

以及：

```vue
<lark-doc />
```

改为：

```vue
<template>
  <div ref="host" class="editor-host"></div>
</template>

<script setup>
import { ref, onMounted, onBeforeUnmount } from 'vue'
import { LarkDoc } from 'lark-doc'

const host = ref(null)
let doc = null

onMounted(() => {
  doc = new LarkDoc({
    element: host.value,
    title: 'Vue3 统一接入测试',
    content: '<h1>统一接入测试</h1><p>Vue3 文档内容。</p>',
    contentFormat: 'html',
    storage: 'none',
  })
})

onBeforeUnmount(() => {
  doc?.destroy()
  doc = null
})
</script>
```

Vue3 只负责创建宿主节点、初始化实例、保存实例引用和销毁实例；不再负责 Web Component 属性转换或 CustomEvent 转换。

### 阶段五：统一 Vue2 与 Vue3 demo 配置

两套 demo 使用同一份测试配置和相同的公共 API，仅生命周期写法不同：

```text
Vue2：mounted / beforeDestroy
Vue3：onMounted / onBeforeUnmount
```

建议验证内容：

| 验证项 | Vue2 | Vue3 |
|---|---:|---:|
| 初始化 | 通过 | 通过 |
| ready | 通过 | 通过 |
| 获取 HTML/JSON | 通过 | 通过 |
| setContent | 通过 | 通过 |
| setReadonly | 通过 | 通过 |
| 编辑/阅读/修订切换 | 通过 | 通过 |
| Message 提示 | 通过 | 通过 |
| destroy | 通过 | 通过 |

### 阶段六：重新定位 Web Component

保留 `lark-doc/element`，但文档明确区分：

```text
推荐：Vue2 / Vue3 / Vite / webpack 项目
      import { LarkDoc } from 'lark-doc'
      new LarkDoc({ element, ...options })

兼容：原生 HTML / CDN / 静态页面
      import 'lark-doc/element'
      <lark-doc></lark-doc>
```

不得为了统一 Vue2/Vue3 API 而删除已有 Web Component 能力。

### 阶段七：整理内网交付

构建项目推荐 npm/tgz：

```bash
npm install lark-doc@新版本
# 或
npm install ./lark-doc-新版本.tgz
```

业务代码统一：

```js
import { LarkDoc } from 'lark-doc'
```

静态页面交付完整 `dist/` 资源目录，主文件、异步 chunk、字体必须一起复制，不允许只复制主 UMD 文件。

文档至少包含：安装、webpack4 alias、Vue2 初始化、Vue3 初始化、配置、实例方法、销毁、内网资源复制、常见问题。

本轮执行结果：主入口、legacy、adapter、plugin、collab、lite、features 产物均已生成；`exports` 与实际文件已通过契约检查；Vue3 demo 已改为 `new LarkDoc({ element, ...options })`，构建和定向测试通过；React / Vue3 环境文档已将主入口命令式接入列为默认方式，`lark-doc/element` 仅保留为 Web Component 兼容入口。当前不执行提交、推送和发布。
