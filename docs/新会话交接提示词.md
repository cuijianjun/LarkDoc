## 总目标

恢复并完成 7 个阶段结算时约定的统一接入方案：

```js
import { LarkDoc } from 'lark-doc'

const doc = new LarkDoc({
  element: host,
  ...options,
})
```

Vue2、Vue3、Vite、webpack4、webpack5、React 等构建型项目，业务层都使用同一套 `LarkDoc` 命令式 API。不同环境只在构建产物层区分。

Vue2 和 Vue3 不应分别采用：

```js
// 不作为 Vue3 默认方案
import 'lark-doc/element'
```

配合：

```vue
<lark-doc />
```

`lark-doc/element` 继续保留，但定位为原生 HTML、CDN、静态页面和兼容入口。

## 计划执行顺序

### 1. 冻结并核对统一 API

确认 `new LarkDoc(options)` 的配置、事件、实例方法在 Vue2/Vue3 一致，至少核对：

```text
配置：element、title、content、contentFormat、readonly、theme、storage、toolbarKeys、features、uploader、persistence、onReady、onChange、onSave、onError

方法：getEditor、getHTML、getJSON、getText、getTitle、setTitle、setContent、setReadonly、isReadonly、setMode、focus、save、undo、redo、destroy
```

如果有不一致，优先修公共门面和 DOM Renderer，不在 Vue3 demo 里写特殊逻辑。

### 2. 确认门面框架无关

确保：

- `new LarkDoc()` 不依赖 Vue2 运行时。
- Vue3 命令式接入不加载 Vue2 SFC。
- Vue2/Vue3 共用原生 DOM Renderer。
- `destroy()` 清理 DOM、事件、编辑器和定时器。
- `setMode()` 和 Message 行为在两个环境一致。

### 3. 补齐正式构建产物

根据现有构建系统生成并核对实际需要的 CJS、ESM、CSS、legacy/Vue3 adapter、Element 等产物。重点是：

- `exports` 不能指向不存在的文件。
- webpack4 可以加载 CJS。
- Vite/Vue3 可以加载 ESM。
- CSS 可以正常引入。
- Element 异步 chunk 和字体在内网同目录可加载。

不要未经核对就新增虚构的文件名或入口。

### 4. 改造 Vue3 demo

把 Vue3 demo 改为：

```vue
<template>
  <div ref="host" class="editor-host"></div>
</template>

<script setup>
import { ref, onMounted, onBeforeUnmount } from 'vue'
import { LarkDoc } from 'lark-doc'

const host = ref(null)
let doc = null

onMounted(() => {
  doc = new LarkDoc({
    element: host.value,
    title: 'Vue3 统一接入测试',
    content: '<h1>统一接入测试</h1><p>Vue3 文档内容。</p>',
    contentFormat: 'html',
    storage: 'none',
  })
})

onBeforeUnmount(() => {
  doc?.destroy()
  doc = null
})
</script>
```

保留模式切换 Message 验证，但不要继续使用 `<lark-doc>` 作为 Vue3 默认接入。
